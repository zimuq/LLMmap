## D — The question

> **Can the two I2-violating defects in `PromptConfFactory` be fixed
> cleanly (a trivial forwarding bug, and a genuinely missing train/test
> split for sampling hyperparameters), and — to the extent determinable —
> does the shipped `default_dataset.jsonl` that D001/D004 depend on carry
> either defect?**

### What was found (context, not re-discovered here — see the source note)

1. **`PromptConfFactory.sample()` never forwards `pool`.**
   `LLMmap/prompt_configuration.py:234-240` accepts `pool` as an argument
   but calls `self.sample_one()` without it, so both `dataset_maker.py`'s
   `sample(..., pool=TRAIN)` and `sample(..., pool=TEST)` calls silently
   draw from the same (TRAIN) pool. `train_test_split.json` itself is
   genuinely disjoint (systems 51/33, cot 4/2, rag 6/3, zero index
   overlap) and `_cond_choice` honours `pool` correctly — the defect is
   the one missing argument.
2. **Sampling hyperparameters have no split structure at all.**
   `sample_one` draws `do_sample`/`temperature`/etc. via
   `sample_from_multi_universe(self.sampling_universe)`, and
   `confs/prompt_configurations/general.json`'s `sampling_universe` is a
   single flat set — no train/test partition. The paper (§7.1) describes
   splitting `H` into `Htrain`/`Htest`; the released code never
   implemented it.

Both run without error and produce plausible-looking output — exactly
invariant I2's stated failure mode ("selection-on-test happens silently").

### Why this needs a D of its own rather than a drive-by fix

Per `CLAUDE.md`'s code-change rule, anything invariant-touching or
method-affecting goes through a reviewed plan, not a silent commit — even
though item 1 is a one-line change. Item 2 additionally requires an actual
design decision (how to partition `sampling_universe`), which is a
methodological call, not just a bugfix.

## Required steps

**M1 — Fix item 1.** Restore `pool` forwarding
(`self.sample_one(pool)` or equivalent). Verify with a direct test: sample
100 configs from each pool and assert zero index overlap between the two
resulting sets — the same style of check `train_test_split.json`'s own
disjointness already satisfies, made executable rather than asserted by
inspection.

**M2 — Design and implement a train/test split for `sampling_universe`.**
Propose a partition scheme in P (e.g. splitting the `temperature`/
`do_sample` value sets the way `train_test_split.json` already splits
system/CoT/RAG indices) for design-side review before implementing — this
is genuinely a new design decision, not a bug fix, so P should present it
as a choice with a stated rationale, not bury it inside the code diff.

**M3 — Make I2 an assertion, not a convention.** Per `TODO.md` T1.3's
existing requirement ("automated assertion... make it a test, not a
comment") — add a check that fails loudly if any future config change
reintroduces cross-split leakage, covering both prompts and sampling
hyperparameters.

**M4 — Best-effort determination of the shipped dataset's exposure.**
Check what can actually be recovered about how `default_dataset.jsonl` was
generated (git history of the data file, any accompanying release notes,
whether its structure is consistent with pool-aware or pool-blind
generation). Report DETERMINED (with evidence) or UNDETERMINABLE — do not
infer a answer from absence of evidence either way.

## Constraints

**Applicable invariant:** I2, directly.

**Code-change rule applies in full.** M1's fix is low-risk but still goes
through this D's REVIEW gate before being committed, per `CLAUDE.md` — no
exception for "it's only one line."

**Out of scope:** do not regenerate `default_dataset.jsonl` or any other
corpus. Do not re-run D001 or D004 with the fix applied — if M4 concludes
the shipped dataset is affected and design side decides a clean re-run is
warranted, that is a separate D, not part of this one.

**Backward compatibility is not a goal.** `PromptConfFactory`'s only
current caller is `dataset_maker.py`; there is no released corpus built on
the *current* (buggy) code path to preserve compatibility with (the
shipped dataset predates it, per M4). Fix correctly rather than
preserving the current broken behavior for any caller.
