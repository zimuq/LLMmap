## 0. Objects and conventions (fixed here)

**Units.**
- A **target** is one (model t, slot s) `test_tgt` unit: 250 MET samples
  or 200 ZP outputs under t's S_test config s.
  - v2 has 85 × 25 = 2,125 targets; v1 has 37 × 25 = 925, the same slots
    as the comparators' `cnt_model` columns.
- A **native target** is t's `native_tgt` unit (one per model).
- A **reference library** holds one reference per candidate model m:
  - **Gen** = m's `gen_ref`;
  - **All** = m's `all_ref` samples pooled into one sample set. For MET:
    250 samples, 10 per prompt. For ZP: 10 prompts × 20 repeats; each
    (base query, repeat) carries its own S_build config, shared across the
    base query's 5 variants (Call 3, P1).

**Native scores, oriented so that higher = more similar.**

| method · variant | score(target, reference_m) |
|---|---|
| MET-Hamming (primary) | −MMD²_u, the official `mmd_hamming`: prompt-aware, unit-diagonal-normalised Hamming kernel on Unicode code points, padded with −1 / truncated to L = 1000, diagonal excluded |
| MET-e5 (variant) | −MMD²_u with the same prompt mask and diagonal exclusion. Kernel k(x, y) = exp(−‖e(x) − e(y)‖² / (2σ²)), e = frozen I5 e5 embedding with D028's settings (raw text, max_length 512, mean-pool, no normalisation). σ = median Euclidean distance over all pairs of the 21,250 Gen-reference completions (85 × 250), computed and frozen in S2 before any target is scored (Call 4) |
| ZP-512 (primary) | (Pearson + 1) / 2 of the official fingerprints (mpnet → per-base-query ridge Jacobian α = 0.001 → mean), official `compute_similarity` |
| ZP-200 (variant) | the same, on outputs truncated to their first 200 tokens of the generating model's tokenizer (Call 5) |
| LLMMAP-OS (descriptive) | −distance between released open-set encoder outputs. Primary: cosine (the D, as ZeroPrint/BReF report it). Euclidean (the released default) alongside (Call 6) |

**Identification and ties** (the D's pre-registration, made operational):
- **top-1 credit** of target (t, s) = 1/|T| if t ∈ T, where T is the set
  of candidates whose score equals the maximum exactly. Otherwise 0.
- **Pairwise** for a pair {a, b}, on a target of model a: 1 if
  score(·, ref_a) > score(·, ref_b), **0.5 if equal**, 0 otherwise. A pair's
  two-logit accuracy pools both directions × slots, so 50 targets per pair.
  - This is independent of the candidate set, so the v1 666-pair values are
    the same numbers as in v2, restricted to v1 models.
- **v1 view:** targets and candidates restricted to the 37 v1 models;
  top-1 is argmax over those 37 only.
- **Tie rate** per method × variant × row × view = the fraction of targets
  with |T| > 1, reported.
- **Rank of the true model** (for Top-3 / MRR, descriptive) = 1 + #{m :
  score > s_t} + ½ #{m ≠ t : score = s_t} (average rank). Top-3 = 1[rank ≤ 3];
  MRR = mean 1/rank (Call 7).

**Counts written in D029's format** (one `.npz` per method × variant ×
library × view, committed):
- `cnt_total` (25), `cnt_model` (n × 25), `cnt_pair` (H × 25), `dirH`
  (H × 2 × 25, float, ties at 0.5);
- v1 also `cnt_pair666` (666 × 25);
- plus `tie` (n × 25), `rank` (n × 25) and `native` (n: top-1 credit, rank).
- H = D028's H_all (57 pairs) on v2. On v1, `cnt_pair` = D016's 65
  structural pairs. Same orders as `results/D029/counts_JG.npz` /
  `results/D023/run_counts.npz`.
- **Score matrices** `S[t, s, m]` (n × 25 × n, float64) and the native
  `S[t, m]` go to `results/D030/scores/` (gitignored, about 25 MB). Their
  sha256 is recorded.

## 1. S2 — score (no S_test summary is printed or written in S2)

**S2.0 Freeze before scoring** (`results/D030/s2_freeze.json`, committed
before S2.2):
- σ for MET-e5 (Call 4);
- the LLMMAP-OS SINGLE configs per model and corpus (D024 rule, Call 6);
- the ZP-200 truncation counts;
- the sha256 of every `final.json` read.

**S2.1 Derived representations** (no scoring):
- **ZP-200 texts** (Call 5). Per model, in its generation env
  (tokenizer-only): ids = tok(text, `add_special_tokens = False`); if
  len(ids) > 200, text₂₀₀ = tok.decode(ids[:200], `skip_special_tokens =
  True`); otherwise the stored text is kept as is.
  - Written to `data/baseline_ext_v1/derived/zp200/{slug}.jsonl`, with the
    fraction truncated per model.
- **e5 embeddings of every MET completion** (595,000, plus nothing else).
  `d006_s6_embed`'s settings in `llmmap-gpu`, fp16, stored as
  `data/baseline_ext_v1/derived/met_e5/{slug}.npy` + row index.
- **mpnet output embeddings** for every ZP unit (ZP-512 and ZP-200): the
  official `_compute_output_embeddings` in `d030-zp` (GPU). Per-unit 10 ×
  768 means are stored, which is all the fingerprint needs.
- **LLMMAP-OS encoder outputs.** The released `load_LLMmap(
  './data/pretrained_models/default')` → `InferenceModel_open`, called
  unchanged on PAPER8 answers (pool ids 0–7; their texts are byte-identical
  to the encoder's `conf.queries`, checked in S0 recon). Answers are cut
  to 650 characters by the released code itself.
  - v2 view: corpus-v2 rows of all 85 models; v1 view: corpus-v1 rows of
    the 37 models.
  - Every S_build config (for All = the released `compute_template`, mean
    over the 75), the SINGLE config, and every S_test slot.
  - 384-d outputs stored.

**S2.2 Score matrices** (GPU torch, fp64 accumulation):
- **MET (both variants):** for each prompt, an exact block computation of
  the kernel sums, giving S for {test, native} targets × {Gen, All}
  libraries. About 3.8 × 10⁵ MMDs per variant.
- **ZP (both variants):** the 170 reference fingerprints (85 Gen + 85 All)
  are held in memory. The 2,210 target fingerprints are streamed through the
  Woodbury closed form (S0.5(b): matches the official form,
  similarity = 1.0 to 1e-6). Pearson is computed with the official formula.
- **LLMMAP-OS:** cosine and Euclidean distances, Gen and All, both views.
- **Code-path asserts**, which stop S2 if they fail:
  - MET: the fast block form = the official `mmd_hamming` on 20 random
    (target, reference) pairs, |Δ| ≤ 1e-9. For MET-e5, the same against a
    direct O(n²) implementation.
  - ZP: Woodbury = official `_estimate_gradients` + `_aggregate_gradients`
    on 5 random units (rel. ≤ 1e-4, similarity ≥ 1 − 1e-6).
  - LLMMAP-OS: our batched call equals the released `__call__` on 5 traces
    exactly.
  - These asserts read S_test units only through code paths, never their
    scores.
- **Counts** (§0) → `results/D030/counts_{method}_{variant}_{Gen|All}_{v2|v1}.npz`.
- **Double-BOS control reads** (Review stop A; native rows only):
  - (i) Pearson(F_dblbos, F_gen_ref) vs Pearson(F_gen_ref, F_native_tgt),
    per model;
  - (ii) the rank of the true model when `native_tgt` is scored against the
    85-model ZP Gen library with that model's reference replaced by
    `gen_ref_dblbos`;
  - both for ZP-512 and ZP-200 → `results/D030/dblbos_control.json`.

## 2. S3 — analysis (the single S_test read)

**Comparators (I6: reused verbatim; nothing of ours is re-selected or
retrained).**

| view | ours, attention (primary) | ours, linear (sign check) | PAPER8 (reference row) | bootstrap |
|---|---|---|---|---|
| v2 85-way | `results/D029/counts_JG.npz` `att\|8\|r\|*`, r = 0–4 | `lin\|8\|*` | `counts_PAPER8.npz` `att\|8\|r\|*`, `lin\|8\|*` | D029's draws: `M = boot_draws(25, 2000, seed=20261005)`, seeds `S = default_rng(20261005).integers(0, 5, (2000, 24, 5))`, slot k − 1 = 7 |
| v1 37-way | E_all: `results/D010/run_counts.npz` `joint_energy\|8\|r\|cnt_model`; E_hard: `results/D023/run_counts.npz` `JointGreedy\|8\|r\|cnt_pair666` | E_all: `results/D020/linear_counts.npz` `JointGreedy\|concat\|8\|cnt_model`; E_hard: Call 1 | E_all: `results/D009/run_counts.npz` `paper8\|8\|r\|cnt_model`; E_hard: `results/D023/run_counts.npz` `paper8\|8\|r\|cnt_pair666` | D023's draws: `M = boot_draws(25, 2000, seed=20260928)`, `S = default_rng(20260928).integers(0, 5, (2000, 8, 5))`, slot 7 |

- The baselines use the **same M** as the comparator in each view. They
  have no seed dimension, so only their configs are resampled.
- Every Δ is paired draw by draw.

**Endpoints** (per method × variant × library × view):
- **E_all** = mean top-1 credit over targets. Draws: (M @ cnt_model.ᵀ) /
  25, averaged over models.
- **E_hard:**
  - v2 = mean two-logit accuracy over H_all (57). Draws: (dirH summed over
    directions) @ M / (2 · 25), averaged over the 57 pairs.
  - v1 = CVaR₀.₁ of two-logit accuracy over the 666 pairs. Per draw: the
    666 per-pair accuracies from `cnt_pair666` @ M / (2 · 25), then
    `LLMmap.joint_statistic.cvar(·, 0.1)` (m = 66), as in D023 S-b.

**Order of S3, as the D requires:**
1. **WORSE scan first.** For each method (MET, ZP) × view, every variant ×
   library cell: Δ = OURS(att) − cell on E_all and E_hard. Any cell with
   hi(Δ) < 0 is listed in R-final's first lines, before any label. This is
   not limited to B*.
2. **Strongest-baseline rule.** B* per method × view = the cell with the
   highest E_all point estimate among {Gen, All} × {primary, variant}. The
   native row is excluded.
3. **Labels** (per method × view, against B*):

| label | rule |
|---|---|
| BETTER | lo(Δ_all) > 0 **and** lo(Δ_hard) > 0, **and** OURS(linear) − B* > 0 in point estimate on both |
| PARITY | both intervals ⊂ [−0.02, +0.02] |
| WORSE *(headline)* | hi(Δ_all) < 0 **or** hi(Δ_hard) < 0 |
| INCONCLUSIVE | otherwise |

   Precedence if two rules match: WORSE > BETTER > PARITY. The linear check
   is a sign check on point estimates, as D029 read it (Call 2).
4. **Opposite-failure hypothesis** (descriptive, stated in the D):
   - for each method × variant: native − Gen and native − All on top-1
     (native = one target per model, point only);
   - E_hard and per-pair accuracy on H_all, H_N, H_X and N′ (161 pairs,
     `results/D027/n_prime.json`) on v2; on the 65 structural pairs and the
     666 on v1;
   - E_hard / E_all ratio relative to ours.
5. **Secondary (descriptive):**
   - (a) paired MET-Hamming − MET-e5 and ZP-512 − ZP-200 on E_all and
     E_hard, with intervals;
   - (b) E_all by block (v2 new 48 vs v1 37, D029 blocks);
   - (c) E_all by the slot's config type (none / sys / RAG / CoT, frozen
     typing), with the share of slots per type;
   - (d) LLMMAP-OS Gen and All rows, both views, split by encoder-training
     overlap (A4: v1 37 in-sample, v2 new 48 out-of-sample), cosine and
     Euclidean;
   - (e) the mandatory hard-tail plot: two-logit accuracy over all pairs
     (v2 3,570, v1 666), sorted, for ours (attention, k = 8), PAPER8 and
     each method's B* → `results/D030/tail_{v2,v1}.png`;
   - Top-3 and MRR for every cell;
   - tie rates;
   - the double-BOS control (S2.2).
6. **McNemar** (BReF style). Exact two-sided McNemar on per-trace top-1:
   ours (linear; one trace per (model, slot), `cnt_model` ∈ {0, 1}) vs each
   method × variant × library cell, per view.
   - Baseline traces with a top-1 tie are excluded from that test; the
     number is reported (Call 7).
   - Holm correction over all tests in the table.

## Calls

1. **v1 linear E_hard is not in any stored count (needs design-side).**
   D020 stored the linear readout's `cnt_model` and the 65-pair
   `cnt_pair`, not `cnt_pair666`. The BETTER rule's linear sign check on v1
   E_hard therefore has no input.
   - **TACC proposes** re-deriving D020's `JointGreedy|concat|8` linear
     test logits on D020's exact code path (`d020_paired_linear.fit`:
     lbfgs, C = 1.0, `max_iter` = 20000, tol = 1e-6, no scaler). It must
     reproduce D020's stored `cnt_model` and `cnt_pair` exactly (assert),
     before `cnt_pair666` is read off.
   - This is D020's own precedent: D020 refit D017's fits and required
     exact reproduction before trusting their counts. It is a reproduction
     under an equality assert, not a retrain whose outcome is used.
   - **If the assert fails,** fall back to the sign of linear Δ on the 65
     structural pairs' mean (the stored `cnt_pair`), labelled as a proxy.
   - **Alternative:** drop the linear check on v1 E_hard (E_all only).
2. **Linear sign check = point estimates**, as D029 read "linear Δ agrees
   in sign" (D029 Call 4 disclosure). Precedence WORSE > BETTER > PARITY.
   Disclosure.
3. **Baseline E_hard ties = 0.5** in `dirH` / `cnt_pair666`, so those
   arrays are float rather than int16. Disclosure.
4. **MET-e5 σ** = the exact median over all C(21,250, 2) Euclidean
   distances of Gen-reference completions, across prompts. It is frozen in
   `s2_freeze.json` before any target is scored. Needs design-side ack:
   the D says "median pairwise distance over the Gen reference pool"
   without saying whether pairs are within prompt.
5. **ZP-200 by re-tokenisation** of the stored text (the token ids were not
   stored). Decode with `skip_special_tokens = True`. Texts ≤ 200 tokens
   are unchanged. The per-model truncated fraction is reported. Disclosure.
6. **LLMMAP-OS details** (needs design-side ack):
   - cosine as the primary distance (the D), with Euclidean, the released
     default (`conf.json` has no `distance_fn`), alongside;
   - the Gen reference = the D024 SINGLE rule applied per corpus (tier per
     model reported; v2 new models may fall to tier 2/3);
   - All = the released `compute_template` (mean of encoder outputs over
     the 75 S_build configs).
7. **Average-rank ties for Top-3 / MRR;** tied traces excluded from
   McNemar. Pre-registered here.
8. **Native rows are point estimates** (one target per model; no config
   dimension to resample). Descriptive, as the D says.
