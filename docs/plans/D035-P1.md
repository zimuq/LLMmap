## 5. Endpoints and bootstrap (S3, `d035_analysis.py`)

**Bootstrap.** One set of draws, shared by every arm and every `k`, is D031's v2 `Boot`:

- attention seeds: slot `k − 1` of `default_rng(20261005).integers(0, 5, (2000, 24, 5))`;

Point estimates are full-data 5-seed means; intervals are the 2.5 / 97.5 percentiles.

**Primary (each of P1 = CLOUD − CENTROID\*, P2 = CENTROID\* − SINGLE).**
- **Quantity:** per replicate, Δ_k = acc_a,k − acc_b,k (85-way top-1, attention) for `k` = 1..8. The primary is
  their mean over `k` = 1..8, as in D024 Call 3.
- **Labels:**
  - BETTER if lo(mean over `k` = 1..8) > 0 **and** the linear mean-over-`k` point Δ is > 0 (the D029–D033 sign
    convention);
  - WORSE if hi(mean over `k` = 1..8) < 0;
  - PARITY if the interval of the mean over **that comparison's differing `k`** ⊂ [−0.02, +0.02];
  - INCONCLUSIVE otherwise;
  - "IDENTICAL CHAINS" if no `k` differs.
- **Sensitivity row (independent seeds):** the second arm of each comparison takes its seed indices from
  `default_rng(20261101).integers(0, 5, (2000, 24, 5))`. If its verdict differs from the joint-seed verdict, R's
  headline says so.
- **Reported without a verdict:** CLOUD − SINGLE and CLOUD − (the other CENTROID variant).
- **Per-`k` table:** each Δ_k with its interval, and the old D009 / F1 reading (interval excludes 0 **and**
  |Δ| > max 5-run range).

**Secondary, labelled (`k` = 8, D031 convention).**
- **Endpoints:**
  - E_all = 85-way top-1;
  - E_tail = CVaR₀.₁ over the 3,570 pairs of the both-direction two-logit accuracy (`cnt_pair_all`, averaged
    over resampled seeds before the CVaR).
- **D031 `label()`:**
  - WORSE if hi < 0 on either endpoint;
  - BETTER if lo > 0 on both **and** both linear points are > 0;
  - PARITY if all four bounds are within ±0.02;
  - otherwise INCONCLUSIVE.
- **Applies to P1 and P2.**
- **WORSE scan** over every trained-arm contrast at `k` = 8, in the order "richer fingerprint first":

## 7. Calls

**Call 1 — SINGLE reference for the 21 models without a tier-1 greedy config (decision needed before S1).**
- **(a) The D's rule verbatim** *(recommended)*. Take the first non-empty tier (tier 1 for all 85). Within it,
  take greedy, else the lowest temperature, then the lowest config index. Result:
  - 64 greedy references;
  - 21 sampled references (16 at T = 0.1, 2 at 0.4, 2 at 0.7, 1 at 1.0).
  - **Pro:** the D wrote this fallback in advance ("If the tier has no greedy config, take the lowest
    temperature"), and its Notes forbid substituting a reference after S0.
  - **Con:** for 21 models, CENTROID\* − SINGLE partly measures "one stochastic sample" rather than "one
    config". That is the conflation D024 Call 1 (b) avoided. Secondary (e) reports the split, so R can say
    how much of P2 comes from those models.
- **(b) Greedy-first.** Take the first tier, 1 → 3, that contains a greedy config. All 85 references are then
  greedy: 64 in tier 1, 5 in tier 2 ("You are a helpful assistant."), and 16 in tier 3, which carry persona
  system prompts.
  - **Pro:** a deterministic reference for every model.
  - **Con:** 16 references are no longer "no system prompt", and it departs from the D's written order.
- **Either way:** the reading not chosen stays a **selection-only** row (chain, trace, overlap), not trained.
- **Blindness:** both readings were computed in S0 to disclose the case. What S0 inspected is the table in §2.2
  (target-free health rows), and the recommendation rests on the D's text, not on those rows.

**Call 2 — query 253 under SINGLE-norm (relevant only if CENTROID\* = norm).**
- **The problem:** 1,831 of 3,570 pairs are exactly 0 under the D's SINGLE, so the median is 0 and the
  normalised row is undefined.
- **(a) Exclude query 253 from SINGLE-norm's candidates** *(recommended)*. Record it in `chains.json`, and assert
  it is never selected.
  - Under raw scaling its single-query CVaR is exactly 0 (51% of the pairs are at 0, far above the worst
    10%), so it is not a plausible early pick under any scaling. The exclusion removes an undefined row, not a
    competitor.
- **(b)** Normalise that query by the median of its non-zero cells.
- **(c)** Use SINGLE-raw whatever CENTROID\* is. This departs from the D's "SINGLE uses CENTROID\*'s scaling".
- **Under Call 1 (b)** no query has a zero median, so Call 2 would not arise.

**Call 3 — S_val choice mechanics (decision needed before S1b).**
- **(a)** *(recommended)* Train both CENTROID variants once in S1b (D029 protocol, with S_val used for early
  stopping), with no S_test loaded. Choose on the reloaded best checkpoints' S_val top-1. S2 then **reloads**
  those checkpoints for S_test instead of retraining.
  - The S_val that picks the checkpoint is the S_val that picks the variant. That inflates both variants'
    S_val numbers in the same way. It is the D's specified readout ("S_val attention"), and the alternative is
    an extra validation split the corpus does not have.
  - The linear S_val numbers are recorded as a diagnostic, so the Review can see whether the two readouts
    agree.
- **(b)** Choose by linear S_val (D031 / D032 practice), and keep the attention numbers as a diagnostic. This
  departs from the D's text.

**Call 4 — freezing SINGLE before its scaling is known (no change to the D's intent).**
- **The tension in the D:** it freezes `chains.json` "before any training", but chooses SINGLE's scaling after
  training the CENTROID variants.
- **Proposal:** S1a selects and freezes SINGLE in **both** scalings. After the choice, only the one in
  CENTROID\*'s scaling is trained; the other is a selection-only row. No chain is created after training starts.
