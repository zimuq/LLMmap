## Calls

### Call 1 — batch 1 run as k concurrent processes (needs design-side)

- The D allows a faster mode only if it passes the padding-sanity rule, and
  otherwise says "the model runs at batch 1, sharded by config range".
  Bucketing fails the rule (table above).
- **TACC proposes:** run the batch-1 shards **concurrently on the same GPU**
  (k processes, disjoint config ranges via `--part i --nparts n`).
  - Each process does exactly batch-1 generation; nothing is batched.
  - Verified: process 0's 12 outputs at k = 4 and 8 are **identical** to the
    solo run, for all three models.
  - It is the D's batch-1-sharded fallback with the shards co-scheduled on
    one node, not a new generation mode.
- **Plan:**
  - Falcon-H1-3B and Qwen3.5-4B: one job each, k = 8, nparts = 8, pool then
    ML (≈ 24 h and 21 h).
  - Falcon-H1-7B: two jobs × k = 4 (parts 0–3 and 4–7 of nparts = 8;
    ≈ 26 h each, within the 48 h wall).
- **Seeds** are per (model, pool, config), so the part split does not
  affect any row.
- **Alternative:** plain batch 1, sharded. About +200 node-h (total ≈ 400,
  on the Call line), with no difference in outputs.

### Call 2 — the tensor builder needs a loader wrapper (needs design-side)

- The D says "`d007_build_tensor.py` unchanged". It cannot run on 85
  models: its loader `d007_lib.load_corpus` hard-asserts 37 models and reads
  `corpus_v1`.
- `experiments/d028_build_tensor.py` supplies only an 85-model S_build cube
  loader (same cube layout). It **imports `pair_worker`** (probe AUC, energy
  raw / scale-free, split-half probes) **and `SPLIT_SEED` unchanged**.
- **Equivalence is proven by the D's own reproduction check.** For every
  pair of two reused v1 models (C(34, 2) = 561 pairs), each of the five v2
  tensors must equal D007's tok200 tensor. Max |Δ| is reported, and a Call
  is raised if it is not ~0.
- Logged as `TACC_NOTES` Issue 22.

### Call 3 — reused shards: symlinks, fields in the manifest (disclosure)

- "Reused means unchanged", so the 34 `corpus_v1` shards are **not
  rewritten** to add the four v2 fields.
  - `data/corpus_v2/{slug}.jsonl` and its embeddings are symlinks to
    `corpus_v1`, with sha256 asserted equal to D006's status file.
  - `shard_source: corpus_v1-reuse`, `gen_env` and `config_source` live in
    `results/D028/reuse.json` and `manifest.json`.
- Consumers read `shard_source` from the manifest (migration note).

### Call 4 — other disclosures

- **The multilingual rows of the 34 reused v1 models come from the D027
  environment** (32 in `llmmap-gpu-v2`; DeciLM `llmmap-gpu`; internlm
  `llmmap-internlm`), as the D says. Their pool rows come from D006.
  - D027's (f1) = 1.0 for 32 of these 34 shows the environment is neutral
    for them. (Llama-3.2-1B/3B: 0.998; internlm: own env, 0.50.)
  - The pool / ML provenance split within a model is recorded per block.
- **S_test of the 48 new models is generated here for the first time**, from
  D027's frozen draws. Nothing in this D reads it (I2).
- **Back-translation 294** is implicit (above). It is reported, not acted on.
- **Measured baseline 0.457:** padded batching vs batch 1 changes ~half of
  greedy outputs on ordinary models in this environment. Recorded for
  anyone comparing modes later.

## Steps after approval

**S1 — generate** (`experiments/d028_generate.py`).
- **Per (model, block, part):**
  - load through `d027_llm.LLMv2` at the D027 revision (shims as approved);
  - configs = D027 frozen draws (new) / `corpus_v1` rows (gemma ×3, and all
    v1 for ML);
  - `torch.manual_seed(sha256(model|pool|config_index))` per config;
  - restartable per config.
- **Mode:**
  - `d006` (`make_dataset_entries_for_new_llm`, batch 64) for 45 new +
    3 gemma;
  - batch 1 with k concurrent parts (Call 1) for the trio;
  - ML: one call of 16 per config in the same mode.
- **Jobs:**
  - ~16 `gh` jobs for the d006 block, bucketed by projection (≤ ~8 h each;
    Qwen3-30B-A3B ×2 in their own jobs);
  - 4 jobs for the trio;
  - 3 jobs for ML of the reused v1: v2 env; DeciLM `old`; internlm
    `internlm`.
  - ≤ 20 running (`MaxJobsPU`). Bucket lists committed with the launch.
- **Finalize** (`--finalize`) per (model, block):
  - merge parts in (pool, config_index) order;
  - assert every row's `prompt_conf` equals its source;
  - 125 configs × 259 (pool) or × 16 (ML);
  - empty rate reported; sha256 → `{slug}.final.json`. COMPLETE or
    INCOMPLETE; no model is dropped.
- **Reuse** (`experiments/d028_link.py`): 34 symlinks with hash asserts →
  `results/D028/reuse.json`.

**S2 — embed** (`experiments/d028_embed.py`, `llmmap-gpu`, `d006_s6_embed`
function and settings).
- I5 parity first: 50 stored responses per reused model, max |Δ| ≤ 1e-2.
- Then the 51 generated pool shards and all 85 ML shards.
- `results/D028/manifest.json`: every source, shard and embedding sha256,
  `shard_source`, `gen_env`, mode, empty rates, measured gen/s per block.

**S3 — tensor** (`experiments/d028_build_tensor.py`, a CPU `gh` job,
68 workers).
- Five tensors `S_*_tok200_v2.npy` (frozen: `S_energy_sf_tok200_v2`, the v2
  analogue of D007's `S_energy_tok200`).
- `tensor_v2.json` with sha256s and the reproduction max |Δ| (Call 2).
- **Mandatory hard-tail plot** (`d028_plots.py`, `llmmap` env): per-pair
  CVaR₀.₁ / mean of the frozen statistic across the 3,570 pairs, with H_N
  and H_X marked.

**S4 — `## R`.**
- The label; per-block completeness, sources and hashes; measured cost per
  block (the trio separately); empty rates.
- The back-translation table, the frozen hard-set summary, the reproduction
  max |Δ| and the tail plot.
- **No method comparison and no S_val / S_test accuracy of any chain**
  (D029).
- S1 → S2 → S3 are chained with Slurm dependencies, so the pipeline does not
