## 1. Families and folds (S0; before any tensor statistic is read)

**Families.** Undirected graph on the 85 v2 models, edge = an N′ pair (`n_prime.json`: same non-empty `base`
or same non-empty `lineage`, the D001 / D027 rule). Family = connected component. Checked while writing this
P (metadata only): **24 families**, sizes 10, 7, 6, 6, 5, 5, 4 × 4, 3 × 5, 2 × 6, 1 × 3, identical to the
`lineage` column's 24 groups. S0 asserts the component partition equals the `lineage` partition; if it does
not, S0 stops (the D names "base-and-lineage", and the two would then differ).

**Primary — model-level folds (`kind = model`).**
- `rng = default_rng(int(sha256("D033|folds|model").hexdigest(), 16))`.
- Order families by size descending; ties broken by `rng.permutation` over the tied families (by sorted
  name). Within each family, members in `rng.permutation` order.
- Concatenate, and deal model *i* of the concatenation to fold `i mod 5`. 85 = 5 × 17, so **every fold has
  exactly 17 models**. A family of ≤ 5 members lands in ≤ 1 model per fold; the 10-member family puts 2 per
  fold; 6- and 7-member families put ≤ 2 per fold. **Every held-out model in a family of ≥ 2 has ≥ 1
  enrolled sibling** (the 3 singletons have none). S0 asserts both properties.

**Secondary — family-level folds (`kind = family`).** Same rng construction with `"D033|folds|family"`.
Families in size-descending order (rng tie-break), each assigned to the fold with the fewest models so far
(lowest fold index on a tie). Held-out models never have an enrolled sibling.

**v1 view.** The same assignment restricted to the 37 v1 models (no separate draw). v1 fold sizes are
whatever the restriction gives; S0 records them. v1 has 4 models with no v1 sibling (aya-23-8B, DeciLM,
internlm2.5, the single v1 EuroLLM); they are reported in (d).

`chains.json` records: family label per model, both fold assignments (model → fold), per-fold model lists
per view, and the sibling-enrolled flag per (model, kind).

## 3. Readout ② — nearest point cloud (training-free)

For a target trace *t* (one model *a*, one config *c*: `k` responses, one per query) and enrolled model *m*:
- per query *q*: `A(t, m, q) = mean_j ‖x_{t,q} − Y_{m,q,j}‖` over *m*'s 75 S_build points (frozen I5
  embeddings, float64 arithmetic on the fp16 cubes), `W(m, q) = mean_{i,j} ‖Y_{m,q,i} − Y_{m,q,j}‖`
  (V-statistic, diagonal included — the frozen tensor's convention, `joint_statistic.energy_direct`);
- **raw:** `e(t, m, q) = 2A − W`; **scale-free:** `e / W`;
- score(t, m) = Σ_{q ∈ chain[:k]} e(t, m, q); prediction = argmin over the enrolled models (85 v2 / 37 v1);
  exact tie → lowest model index.

Enrolment is from S_build only for every model, held-out or not (no training exists, so a model's fold only
matters through which chain scores it).

**Code-path assert (S1, before the choice):** for 3 fixed pairs per view and 5 fixed queries, mean over *a*'s
75 S_build points of `2A(x, b, q)` − `W(a, q)` − `W(b, q)` equals the frozen raw-energy tensor cell to
≤ 1e-5 relative. This checks distances, convention and query / model indexing against I6's tensor.

**S1 choice (the D's only tuning).** O_all on **S_val** held-out targets (each model scored by its own
model-level fold's OURS^fold, `k` = 8), per view; raw vs scale-free; the higher wins; tie → raw. Chosen per
view (the D does not say joint; one file records both, and S3 uses each view's own choice). `variant_choice.json`
records both S_val numbers, `s_test_reads: 0`, and the commit it was produced at.

Per-query terms `e(t, m, q)` are stored for every target (S_val, S_test) × model × union query, so every arm,
both variants and every `k` are scored by the same arrays.

## 4. Readout ① — LLMmap open-set encoder, retrained per fold

**Code path (the D009 S8 path, `experiments/d009_openset.py`, applied per fold):**
- traces: `d009_lib.build_traces(q, split, qe, cubes)` — (N, k, 2048) = [E(query) ‖ E(response)];
- pairs: `d009_lib.TracePairDataset` (mirrors `LLMmap/dataset.py DatasetFactorySiamese`: per-index reseeding,
  50/50 same / different, label 1 = same model) — `num_pairs_per_epoch` 500,000 on S_build traces,
  `num_pairs_per_eval` 5,000 on S_val traces;
- training: `LLMmap.trainer.train_model(tmp, siamese=True, …)` → `make_siamese_network` +
  `LLMmapTrainerSiamese` (`ContrastiveLoss`, sigmoid over a BN + linear map of the Euclidean feature
  distance); early stopping on S_val loss, patience 5, max 50 epochs; best checkpoint by S_val loss;
- hyperparameters: `d009_lib.hparams_from_shipped(k, n_train)` = `confs/default.json → inference_model`
  verbatim (D009 S8 and every D009–D032 attention run), `num_classes` = n_train (unused by the siamese head);
- seeds 0, 1, 2: `pl.seed_everything(seed, workers=True)` before the loaders, as D009 S8.

**Held-out exclusion (asserted in S2, per run):** the S_build and S_val traces handed to the pair datasets are
exactly the `train` models of that fold (labels re-indexed 0 … n_train − 1); the assert compares the set of
original model indices with `chains.json`. S_val traces of held-out models are never loaded into a run.

**Templates and targets (the shipped functions, not reimplemented):**
- `templates.infer_features(feature_extractor, loader)` on the S_build traces of **all** enrolled models
  (85 / 37), then `templates.build_templates` = per-model mean over its 75 S_build features — the
  config-spanning "All" template D030 used for LLMMAP-OS (`InferenceModel.compute_template` is the same mean;
  D030 asserted ≤ 1e-5);
- `infer_features` on the S_val and S_test traces of all models;
- distances target × template, Euclidean and cosine (`scipy.spatial.distance.cdist`), argmin, tie → lowest
  index.

**Arms.** OURS^fold, PAPER8, FULL, JG^fold per (view, fold, seed). Training order = the chain's selection
order. **Identical inputs (Disclosure 6):** if two arms of the same (view, kind, fold) have the same ordered `k` = 8
chain, they share one training; if the same *set* in a different order, they are trained separately (the
encoder is order-sensitive; D031's `train_order` normalisation exists to reproduce stored runs, and there are
none here).

**Storage per run:** features (S_build, S_val, S_test; float32, 384-d) in `results/D033/feat_*.npz`, the
checkpoint in `results/D033/models/…ckpt` (D034's open-set section re-scores with them), both gitignored;
counts (§5) in `results/D033/counts_*.npz` (committed). S_test is written, never printed or summarised in S2.

**Determinism.** The pilot (§9) retrained D009 S8's v1 PAPER8 seed-0 encoder: the checkpoint is bit-identical
to D009's stored one, so this code path is the D009 S8 path and is reproducible on this stack. R cites the pilot
as ①'s code-path check. Seeds vary only the initialisation (the pair sampler is reseeded per index, as shipped,
so every seed sees the same pairs).

## 5. Endpoints (S_test, `k` = 8, per view × readout × arm)

Targets: every (model *a*, S_test config *c*). Model *a* is **held out** in fold *f(a)*, and its target is
scored with fold *f(a)*'s chain (and, for ①, fold *f(a)*'s encoder and templates) against **all** enrolled
models. Results pool the five folds; each model appears exactly once as a held-out target.

- **O_all** = mean over held-out targets of [argmin = *a*]. Counts: `cnt_model` (n × 25) and `cnt_total` (25)
  per (arm, seed) — D031's format.
- **O_tail.** For every ordered pair (*a* → *b*), *a*'s target is held out in *f(a)* with *b* enrolled, so
  every unordered pair has both directions, each from its own target's fold. Two-candidate correct = score
  to *a* < score to *b* (exact tie → the lower-index member, D031's rule). `cnt_pair_all` (P × 25, both
  directions summed) per (arm, seed); pair accuracy = `cnt_pair_all / 50`; **O_tail = CVaR₀.₁ over all P
  pairs** (v2 3,570 / v1 666) — D031's E_tail statistic. Pairs whose two members share a fold (both held out
  together) are included like any other; the D's "average the two directions" is the same statistic. (Disclosure 7)
- **Seen targets (secondary).** For each fold, the S_test targets of its `train` models, scored with that
  fold's chain / encoder against all enrolled models: `cnt_model_seen` (5 folds × n × 25). Pooled = mean over
  the 4 folds in which a model is seen. Gap = seen − held-out, per readout (cf. D030 0.72 vs 0.40).

**Bootstrap (2,000 replicates, per view).**
- Configs: D031's `M` (multinomial weights over the 25 S_test configs, `boot_draws(25, 2000, seed_view)`),
  shared by every arm, readout and fold.
- ① seeds: `S3 = default_rng(int(sha256("D033|seeds|<view>").hexdigest(), 16)).integers(0, 3, (2000, 3))`,
  shared across arms (paired) and across folds (a "run *r*" is the five fold encoders of seed *r*). D023's
  seed draws index 5 seeds and cannot be reused for 3 (Disclosure 5). ②: configs only.
- Fold assignment fixed, not resampled (the D).
- Pair accuracies are averaged over resampled seeds before the CVaR (D029 / D031).

## 6. Labels, WORSE scan, claim rule (S3, in this order)

| label | rule |
|---|---|
| WORSE *(headline)* | hi(Δ_all) < 0 **or** hi(Δ_tail) < 0 |
| BETTER | lo(Δ_all) > 0 **and** lo(Δ_tail) > 0 |

| INCONCLUSIVE | otherwise |
