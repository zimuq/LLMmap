## Call 1 — pooling. **Concatenation, not mean-pooling. D017's stated objection does not hold for a fitted model.**

D017 proposes mean-pooling and asks that concatenation be rejected because it
*"would reintroduce a slot-order dependency the attention network provably does not
have."* I predicted in S0 that this is false for a *fitted* linear model —
`f(x) = Σᵢ Wᵢvᵢ + b`, so permuting slots permutes the learned blocks, and both the
loss and the L2 penalty (a sum of squares over all blocks) are
permutation-equivariant, making the convex optimum unique and order-free.

**First measurement contradicted me: 0.900541 (chain order) vs 0.896216
(permuted).** So I tested whether that was the objective or the optimiser:

| solver setting | chain order | permuted | gap |
|---|---|---|---|
| `max_iter=3000, tol=1e-4` (sklearn-ish default) | 0.900541 | 0.896216 | **0.004324** |
| `max_iter=20000, tol=1e-6` | 0.902703 | 0.902703 | **0.000000** |
| `max_iter=60000, tol=1e-8` | 0.902703 | 0.902703 | **0.000000** |

**The gap is an lbfgs convergence artifact and closes to exactly zero.** My
prediction was right about the objective and wrong about the default solver
settings — recorded that way rather than as a clean hit.

**So concatenation is exactly order-invariant here**, and it is also the *more*
faithful analogue of the attention network:

| | can distinguish which query produced which response? |
|---|---|
| attention network | **yes** (self-attends over slots; `E(query)` tells it which is which) |
| **concatenation** | **yes** (a separate weight block per slot) |
| mean-pooling | **no** — it is the strict special case `Wᵢ = W/k` for all `i` |

**Proposal: concatenation as primary, mean-pooling reported as a secondary
condition.** The secondary is worth keeping precisely because it is the restricted
model: the concat-vs-meanpool gap **measures how much of the selection benefit
requires per-query resolution**, which is D017's theoretical question in miniature.
Measured at `paper8` `k`=8: **concat 0.9005 vs mean-pool 0.8281, a 7.2-point gap** —
so per-query resolution matters a great deal, and mean-pooling alone would have
understated every condition.

**Solver frozen at `max_iter=20000, tol=1e-6`** for every fit — required for the
order-invariance above, and cheap (32 s at the largest shape).

## Part 0 — Two S0 facts that change how `R` must be written

### (a) `E(query)` carries **zero** information for any linear model here

Measured: within a condition, `E(q_i)` is **identical across all 2,775 training
traces** (exact, `atol=0`) — every trace answers the same `k` queries. A linear
model's `Wᵍ·E(q)` term is therefore the same constant for every sample and is
absorbed into the bias. Confirmed empirically: full 2048·`k` features score
0.900541, response-only 1024·`k` score 0.899459 — the difference is convergence
noise at the loose setting, not information.

**So the "2048-d trace" is effectively 1024-d per slot for this D.** The attention
network *can* use `E(query)` — not to discriminate models, but to modulate how each
slot is read — and concatenation reproduces that capability through separate weight
blocks. Mean-pooling cannot, which is the mechanism behind the 7.2-point gap above.
**Proposal: keep the full 2048-d input for faithfulness to "the exact same frozen
traces", and state this fact in `R`** so nobody reads the query half as doing work.

### (b) The linear classifier **beats** the paper's attention network, by a lot

| `paper8`, `k`=8 | mean top-1 |
|---|---|
| attention network (D009, same chain, seed 0) | **0.8346** |
| linear, mean-pool | 0.8281 |
| **linear, concatenation (C=1.0, converged)** | **0.9027** |

**+6.8 points over the architecture the paper specifies**, on identical frozen
traces, splits and query chain.

This does not change what D017 asks, but it changes the frame. D017 is written as
*"does the advantage survive a **simpler/weaker** classifier"* — the premise that a
linear model is weaker is wrong at this data scale (2,775 training samples, 3.0M
attention parameters). **Proposal: report the comparison as
linear-vs-attention, not weaker-vs-stronger**, and flag for design side that the
attention network may be undertrained or overparameterised for this corpus — a
separate question this D does **not** answer and should not be read as answering.

## S1 — regularization, picked once on validation and frozen

Grid `C ∈ {0.003, 0.01, 0.03, 0.1, 0.3, 1.0, 3.0}`, chosen on **`S_val` only**
(test never consulted to choose), on `paper8` `k`=8, then frozen for every
condition and every `k` — D009/F4's fairness discipline:

| C | 0.003 | 0.01 | 0.03 | 0.1 | 0.3 | **1.0** | 3.0 |
|---|---|---|---|---|---|---|---|
| val | 0.8778 | 0.9027 | 0.9114 | 0.9146 | 0.9146 | **0.9189** | 0.9189 |

**Chosen: C = 1.0** (ties with 3.0 on val; the smaller of a tie, i.e. more
regularization, chosen as the conservative default). Mean-pool's own sweep selects
**C = 3.0**, used for that secondary condition so it is not handicapped by a
constant tuned for a different feature space.

**Disclosure:** the table above shows test accuracy alongside val (it was computed
in the same pass) but **test was not used to select** — val's argmax and test's
argmax happen to coincide at the top of the grid, which is a coincidence, not a
procedure.

## F1 — With the fit deterministic, "5 seeds" measures nothing; the bootstrap is the whole uncertainty

Measured: two fits of the same data with different `random_state` give
**bit-identical coefficients**. lbfgs on a convex objective with fixed data has no
stochasticity to capture.

**Proposal: drop the 5-seed axis for the linear conditions and report the
config-level paired bootstrap only** — the same 2,000-draw machinery
(`d008_lib.boot_draws`) that is already the primary uncertainty source in every
prior D's "resolved" calls. D017/S0 anticipated exactly this.

**Consequence for comparison, stated plainly:** the attention-network numbers this
D compares against *do* have a 5-seed axis, and D009/F1's "resolved" rule requires
a delta to exceed the seed range. **A linear-vs-attention delta has a seed range on
one side only.** Proposal: report those cross-architecture deltas with the
attention side's seed range shown, and label them *"resolved against the attention
network's own seed variability"* — not as a symmetric test.

## F2 — Two conditions at `k`=1 are the same condition, again

D015/R5 found that `coverage` and `joint energy` coincide at `k`=1 (the joint
statistic reduces to the per-query one, D010/R2). That holds here unchanged — same
chains. **`R` will mark the `k`=1 column for those two as one condition, not two
agreeing measurements**, so the ordering claim is never counted twice. Flagged
because D017 asks for the ordering "per `k`, not just at `k`=8".

## F3 — Cost is larger than D017 expects, and still trivial

D017 predicts "sub-second fits" and "one of the cheapest D's". At the converged
setting a single `k`=8 concat fit is **32 s**, not sub-second — 16,384 features
× 37 classes. Full grid: 3 conditions × 8 `k` × 2 poolings ≈ 48 fits, with cost
rising in `k`; estimated **≈15 min**. Still cheap, but a factor of ~10³ off the
D's stated expectation, and stated now rather than in `R`.
