### S0.5 Code-path checks (stop with a Call if any fails)
- **(a) MET statistic.** Our scorer must equal the official
  `mmd_hamming(CompletionSample, CompletionSample)` exactly (|Δ| ≤ 1e-12)
  on toy sample sets, and on pilot samples converted from stored text by
  our loader (`tokenize_unicode` → `pad_to_length(L = 1000)`). The fast
  block-diagonal version P2 will use is checked against it here as well.
- **(b) ZeroPrint fingerprint.** On one pilot model, call the official
  `ZeroPrintFingerprint.get_fingerprint` with its `_generate_model_outputs`
  replaced by a replay of our stored outputs. Our offline function on the
  same outputs must agree within 1e-6. Also assert Pearson(F, F) = 1 and
  that two runs are bit-identical.
- **(c) Prompt/decoding parity with the official generators.** On three
  models (Llama-3.1-8B-Instruct, gemma-2-9b-it, Qwen2.5-7B-Instruct):
  - token ids of our rendered native prompt = MET's `format_as_chat(plain)`
    path (their `chat` strips BOS and re-adds it at tokenisation; ours
    keeps the template's BOS with `add_special_tokens = False`);
  - the same for ZeroPrint's `InstructModel` formatting;
  - the effective `generate` kwargs equal each method's native set, and
    `top_k = 0` really disables top-k under transformers 5.18 (logits
    processor list inspected).
  - A mismatch is fixed toward the official behaviour and reported.

## 3. S1 — generate (after the stop-A Review note only)

- **One job per model** (or per model × part for the batch-1 trio). It loads
  the model once and generates MET rows, then ZP rows. Resumable per manifest
  line, like `d028_generate.py`.
- **Mode = D028's per model** (`results/D028/manifest.json`): padded batch
  64 for 82 models, batch 1 with k concurrent processes for the trio.
  - single-config rows: the expanded prompt list (prompt-major, as both
    official loops order it) in chunks of 64;
  - `all_ref`: grouped by config (sampling settings differ per config, so
    groups cannot share a `generate` call).
- **Decoding** (Call 8): native rows pass the method's full native set
  explicitly; config rows pass the config's own `sampling_hparams`
  (`do_sample`, `temperature`), with the rest from the model's
  `generation_config`, exactly as corpus v2 was generated.
  `max_new_tokens` = 50 (MET) / 512 (ZP) in every row.
- **Wrapping:** the baseline prompt takes the place of the pool query in
  `PromptConf.__call__` (CoT, then RAG, then system/template), through
  `d027_llm` with `TEMPLATE_KWARGS`, as D028's ML extension.
- **≤ 20 running jobs** (`MaxJobsPU`); bucket lists committed with the
  launch.
- **Finalize + health report (R-P1, S1 part):**
  - completeness per (method, model, row, slot);
  - `prompt_conf` equality with the source rows;
  - empty rate, length-cap rate, token statistics per method × row;
  - greedy-collapse rate (identical samples within a prompt; expected on
    the 20.8 % greedy slots);
  - sha256 per file; measured node-h per block.
- **No score of any kind is computed in S1.** Then **stop B**: P2 is
  written from R-P1.

## Calls

1. **MET prompt draw (needs design-side).** Use MET's own released draw
   `wikipedia_prompt_indices_test/25/0.json` rather than a new seeded draw
   from the 5 × 100 pool. It is the same distribution, and it is MET's own
   artifact, so it is the more native reading of "drawn once (seeded)".
   Alternative: our seeded draw. Either way it is frozen in S0.
2. **Dataset revision (disclosure).** Cohere Wikipedia data files have not
   changed since 2024-01; pinned at the current revision, with the parquet
   oids asserted. If S0 finds them changed, that becomes a Call.
3. **All-reference draw granularity (needs design-side).** MET: one
   independent S_build config per (prompt, sample) slot, as the D says.
   ZeroPrint: TACC recommends one config per (base query, repeat), shared
   across that query's 5 variants. Otherwise every perturbation Δ in the
   Jacobian also carries a config change, which no target ever has.
   Alternative: fully independent per slot (the D read literally).
4. **Config-type precedence for the T_ZP rule (needs design-side).**
   25.1 % of S_test configs (533 / 2,125, *recon*) combine wrappers
   (e.g. sys + CoT, sys + RAG + CoT), so "type" needs a rule. TACC proposes RAG > CoT > sys >
   none, with round-robin group order none → sys → RAG → CoT (the D's
   listing order). Metadata only; fixed before generation. It also fixes
   secondary (c)'s by-type breakdown.
5. **ZeroPrint input truncation not applied (needs design-side).** The
   official generator truncates inputs to 512 tokens on the right. Long RAG
   configs would then lose the end of the prompt, including the
   generation-prompt tokens. TACC renders the full prompt (as corpus v2
   does). The native rows are unaffected, since ZP prompts are ~30 tokens.
6. **Generation path and batching (disclosure).** Generation uses our
   `d027_llm` wrapper and D028's per-model mode, not the official loops
   (ZP batch 100; MET HF/vLLM). Under bf16, padded batching changes about
   half of greedy outputs relative to batch 1 (D028 S0: 0.457). Template
   kwargs (`enable_thinking = False`, frozen date) apply to every row, as in
   our arm.
7. **Tokenisation parity (disclosure).** MET's `chat` column strips BOS and
   the tokenizer re-adds it. Ours keeps the template's BOS. S0.5(c) checks
   token-level equality; any model where they differ is listed.
8. **Sampling under configs (disclosure).** Configs carry only
   `do_sample` and `temperature`. `top_p` / `top_k` / repetition penalty
   come from each model's `generation_config`, as in the corpus. Native
   rows override all of them with the method's set. On greedy configs
   (20.8 % of S_test slots), MET's 10 samples and ZP's 20 repeats collapse
   to near-identical text. That is the method's behaviour under that
   deployment and is reported, not corrected.
9. **Side environments (disclosure).** `d030-zp` follows ZeroPrint's pins
   except torch cu128 (aarch64). ZeroPrint's `prepare()` uses a thread
   pool on global `random`; it is run once and frozen.
10. **LLMMAP-OS training overlap (disclosure for P2).** The released
    open-set encoder was trained on LLMmap's own model list, which overlaps
    our universe. Where it does, its references are not out-of-sample. P2
    lists the overlap.
11. **Storage.** `data/baseline_ext_v1/` on `$WORK`, gitignored. Estimated
    ≤ 3 GB at T_ZP = 25 (ZP ≈ 476 k × ≤ 512 tokens). The manifest, prompts,
    draws and hashes are committed.
