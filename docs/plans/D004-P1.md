## 1. Statistics

### M1a — A3 default (bounded, for direct comparability with D001)

Per pair (A,B): **5-fold stratified CV AUC of an L2-regularized logistic probe**
distinguishing A's 68 trace embeddings from B's 68, on the raw 384-d vectors.
Regularization matters: 384 dims vs 136 samples is p ≫ n, so an unpenalized probe
separates *any* two classes in-sample. CV is the honest estimate; `C` is fixed a
priori (not tuned per pair, which would leak). Report mean, percentiles, CVaR₀.₁,
M6 ratio — the same shape D001 reported, so the two are directly comparable.

### M1b — Unbounded companion (the actual fix for saturation)

**Energy distance** between the two point clouds — sanctioned by `DECISIONS.md` A3
as a robustness check, non-parametric, no bandwidth to choose:

```
E(A,B) = 2·mean‖a−b‖ − mean‖a−a′‖ − mean‖b−b′‖
```

Reported both raw and **scale-free** (divided by pooled within-cloud mean pairwise
distance), the latter being a d′-like effect size.

**Why this is the centerpiece.** A CVaR/mean ratio computed on a *censored* variable
is uninterpretable — that is precisely what went wrong in D001, where 88.2% of mass
sat at an exact ceiling. Energy distance has **no upper bound**, so it preserves
ordering among pairs that AUC pins at 1.0, and its CVaR/mean ratio is meaningful.
If M1a saturates and M1b shows real spread, that is decisive evidence the D001
result was an instrument artifact.

### M2 — 52-way statistic (the task the project actually cares about)

**Leave-one-out nearest-neighbour over point clouds**, primary. For each of the 3536
test traces, find its nearest neighbour among the other 3535 (excluding itself) and
predict that neighbour's model → a 52×52 confusion matrix. Per-pair confusion rate:

```
conf(A,B) = (C[A,B] + C[B,A]) / (n_A + n_B)
```

Chosen over a multiclass probe as primary because it is non-parametric (no
regularization or fold choices to defend), genuinely 52-way, operates on point
clouds rather than centroids, and is the natural cloud-based analogue of LLMmap's
own nearest-template inference — so it is directly comparable to D001. A **52-class
multiclass logistic probe (5-fold CV)** runs as a secondary check that the verdict
is not an artifact of the NN choice; both are reported.

D001's own full-set baseline was Top-1 ≈ 88–91% over 52 classes, so unlike the
pairwise case there is real error mass here to distribute — M2 has genuine headroom
by construction.

### M3 — Resolution audit (mandatory, for every statistic)

For each of M1a / M1b / M2 report: fraction of pairs at the exact ceiling, at the
exact floor, number of distinct values, and the smallest resolvable increment.
Mirrors D001's "88.2% at AUC = 1.0" disclosure. **A ratio near 1 will not be
reported as "no tail" unless M3 shows the underlying distribution is not censored** —
that is the specific error D004 exists to avoid repeating.

### M4 — Motivating case carried forward

Percentile rank of `Meta-Llama-3-70B-Instruct` ↔ `abacusai/Smaug-Llama-3-70B-Instruct`
under M1a, M1b and M2, tabulated beside D001's 0.75 (open-set nearest-template).

## 4. Failure handling

| Failure | Response |
|---|---|
| **All three statistics saturate** | Report **STILL INCONCLUSIVE**, not "no tail". Per M3, state exactly where each ceiling sits and what a third instrument would need (most likely: measuring in a space *not* produced by a contrastively-trained separator — e.g. raw e5 embeddings before the fingerprinting head). Do not force a verdict. |
| M1a probe unstable (p ≫ n) | Fixed `C` chosen a priori and reported; if CV variance across folds is large, report per-pair fold spread rather than hiding it in a mean. |
| Cache missing/corrupt (contradicts F1) | Re-extraction from the shipped test set is cheap and allowed by D004's Constraints — but **stop and report first** if it turns out to require re-running generation, per D004's own note. |
| sklearn unavailable on aarch64 | Implement the probe with a plain regularized least-squares/LDA closed form in numpy; report the substitution. |

## 5. Limitation carried forward (not introduced by this D)

D004 reuses D001's trace embeddings, which come from the shipped
`default_dataset.jsonl`. **Whether that dataset's train/test prompt-configuration
holdout was actually applied cannot be verified from the artifact** (its entries
carry no `prompt_conf` field). A related live bug exists in the current generator —
`PromptConfFactory.sample()` accepts `pool` but never forwards it
(`LLMmap/prompt_configuration.py:239`), so both splits draw from the TRAIN pool —
and sampling hyper-parameters have no train/test split at all
(`general.json`). See the TACC note appended to D001's `## Review`.

If the shipped dataset shares that defect, test traces were produced under prompting
configurations seen during the fingerprinting model's training, which would
**inflate every separability statistic here and in D001 alike**. This does not
change D004's *comparative* conclusion — all instruments are computed on the same
traces — but it is a fourth candidate explanation for saturation beyond D001 R2's
three, and it must be stated in R rather than left implicit.
