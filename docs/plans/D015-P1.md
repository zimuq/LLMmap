## F2 — Use the per-pair config bootstrap, not a 5-seed bootstrap

D015 says CIs should be *"paired at the config-bootstrap level, per D009's
convention."* The machinery for that already exists per pair and is better than
resampling 5 seed values: every run stores `cnt_pair`, shape **(65, 25)** — for
each pair, the number of correct traces in each test config (0, 1 or 2, since a
config contributes one trace per model).

**Proposal:** reuse `d008_lib.boot_draws` to generate one set of 2,000
config-multiplicity vectors, shared across all methods and both `k` — so every
Δ is **paired on identical draws**, exactly as D009/D010/D012/D013 did for
aggregates. Per pair `p`: `acc_boot = (cnt_pair[p] @ M.T) / (2 · n_configs)`,
averaged over the 5 seeds' count arrays. No new test, no new framework — D015/S5's
requirement.

## F3 — The resolution floor: report it beside the tables or they will be over-read

This is the finding I would most want a reader of `R` to see first.

| | |
|---|---|
| the aggregate effect being decomposed (joint − coverage, `k`=8) | **+0.41 pp** |
| `hard_subset`'s total evidence base | 65 pairs × 2 models × 25 configs = **3,250 trace decisions** |
| what +0.41 pp amounts to | **≈13 trace flips in total**, i.e. **0.21 flips per pair** |
| smallest change one pair can show | 1 trace of 50 = **2.00 pp** |
| aggregate movement from one flip in one pair | 0.062 pp |

**So the quantity D015 is decomposing is roughly an order of magnitude smaller than
the granularity of a single pair.** A per-pair table cannot show "most pairs
improving a little" — no pair *can* improve by less than 2 pp. Whatever the tables
show will be a small number of pairs moving by ≥2 pp with the rest at exactly zero,
and that pattern is forced by arithmetic, not evidence about concentration.

**This does not make the D pointless — it sharpens what it can answer.** The
question *"does any pair get worse"* (redistribution the aggregate hides) is fully
answerable and is the part that matters: if 5 pairs gain 2 pp and 3 lose 2 pp for a
net +0.41 pp, that is a real and reportable finding. The question *"spread vs
concentrated"* is **not answerable at this resolution**, and `R` will say so rather
than reporting the forced pattern as a result.

**Proposal: state this arithmetic in `R` before the tables, and label the
spread-vs-concentrated branch of D015's question as unanswerable at the current
evaluation size** — 25 test configs is the same wall D008/F3, D009, D010/R9 and
D011 each hit, and it binds hardest here because the denominator is per pair.

## F4 — A value-level corroboration for S0, since metadata cannot supply one

Since three of four files store no model list (S0), **proposal: add a check the
files *can* answer.** Take the Falcon3-10B↔7B index derived from D008's model
list and report its **rank among the 65** in each of the four sources
independently. D001 (external artifact, pre-corpus) and D008 (oracle on our
tensor) both flag it as hardest or near-hardest; if the index were permuted between
files, its rank would jump between them. Agreement is corroboration, not proof —
and `R` will label it that way.
