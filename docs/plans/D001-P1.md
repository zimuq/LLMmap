## 0. Findings that shape this plan

D001 §"Notes for whoever writes P" left three things to be determined from the
repo. All three are now resolved by code inspection, and two of them change what
M1 can legitimately mean.

**F1 — A template is a single 384-dim centroid; intra-model spread is already
discarded.**

```python
# LLMmap/templates.py:58
templates[c] = feats[mask].mean(axis=0)
# LLMmap/inference.py:188
return _template.mean(0)
```

`data/pretrained_models/default/templates.json` holds 52 keys × 384 floats
(matching `conf['inference_model']['feature_size']`), unnormalized (L2 norms
52.6–64.9). Only the first moment survives — no covariance, no per-class radius,
no threshold. **D001 asked for this to be flagged explicitly if true. It is true.**

Consequence: template-to-template distance is **not** a separability measure. Two
models can have distant centroids and still overlap heavily, because the spread
that determines overlap was averaged away. M1 must therefore be measured from
traces, not from centroid geometry.

**F2 — The only comparison quantity the model natively exposes is trace→centroid
Euclidean distance.** `inference.py:178` → `cdist(emb, self.DB, metric=self.distance_fn)`,
with `distance_fn` defaulting to `'euclidean'` (`inference.py:164`) and absent from
the shipped `conf.json`. The network emits a raw `[CLS]` vector (`(1, 384)`,
`inference_model_archs.py:123-130`) with no L2 normalization. The siamese
`bn`/`fc` head that mapped distance→probability during training is **not present in
the checkpoint**, so distances are uncalibrated. `self.DB` is `(52, 384)` in
`sorted(templates_map.keys())` order.

**F3 — The shipped model is usable as-is; no trace generation is required.**
`data/datasets/default_dataset.jsonl` = 7800 entries, **4264 train / 3536 test**,
perfectly balanced at **68 test and 82 train entries per model across 52 models**,
8 traces per entry, with the identical 8 queries in every entry. The test-split
`llm` values, the `templates.json` keys, and `conf['llms_map']` keys are three
**identical** 52-element sets, so label indices align under sorted order.

**F4 — No pairwise or confusion-matrix code exists anywhere in the repo.** Nothing
computes model-vs-model comparisons, per-class accuracy, or intra-class spread.
All of it is new work.

**F5 — Platform (D001 asked for this to be flagged early).** aarch64/GH200 is
fine; every required dependency has an ARM build. Two aarch64 blockers were found
and are already fixed on `main`: `torch.load()` ignored its `device` argument and
crashed loading the MPS-saved checkpoint on non-Mac hosts, and `accelerate` was
missing from `requirements.txt` despite being required by `transformers` when
`device_map=` is used. Remaining caveat: the installed torch is `2.7.1+cpu` and
Slurm advertises no GRES on `gh`/`gh-dev`, so **this is a CPU job**. Given the cost
below that is acceptable. **This does not rise to a D002-level finding.**

## 1. Separability metric (M1)

Given F1, measure separability **empirically from test traces against the shipped
templates**.

For an unordered pair (A,B), score every trace by

```
Δ(trace) = d(trace, T_B) − d(trace, T_A)
```

and define **separability(A,B) = AUC** of Δ separating A-traces from B-traces
(equivalently the Mann-Whitney U statistic normalized by `n_A · n_B`).

- 1.0 = perfectly separable, 0.5 = indistinguishable.
- Symmetric: swapping A,B negates Δ and yields the same AUC.
- Threshold-free and bounded — important because F2 shows distances are
  uncalibrated, so any fixed-threshold metric would be arbitrary.
- Uses only the quantity the model natively exposes (F2).
- Has a standard nonparametric CI.

Secondary metrics reported alongside: **pairwise confusion rate** (nearest-of-two
balanced error, threshold-dependent but directly interpretable) and **centroid
distance** `‖T_A − T_B‖`. Reporting centroid distance against measured AUC
*evidences* F1 rather than merely asserting it.

Everything derives from one `(3536 × 52)` distance matrix, so the expensive
embedding pass runs exactly once.

## 2. Steps

### S0 — Prerequisites and reproduction baseline

```bash

```

`matplotlib` is the only new dependency. scikit-learn is deliberately **not**
added — AUC comes from `scipy.stats.mannwhitneyu`, and scipy is already pinned.

The `test_model.py` run is the reproduction baseline D001 requires, on the **full**
test set. Record it as *our* baseline; per D001's interpretation limits, do not
reconcile it against the published numbers (this is LLMmap0.2, which the README
states is not a one-to-one conversion of the paper's implementation).

### S1 — Feature extraction (the only expensive step)

Reuse existing machinery rather than writing new embedding code:

```
load_LLMmap(model_home_dir, device='cpu')
  → load_datasets(conf, siamese=False)        # LLMmap/dataset.py:169
  → infer_features(inf.model, loader_test)    # LLMmap/templates.py:10
```

`EmbeddingCache.precompute` deduplicates strings and batches at
`embedding_batch_size` (256), which is substantially faster than the per-trace path
in `InferenceModel.__call__` (which embeds 8 strings per call).

Seed `random` before loading: `read_dataset` shuffles unseeded
(`LLMmap/dataset_maker.py:8`), which makes runs non-reproducible.

Persist `f_test (3536,384)`, `y_test (3536,)`, and `D = cdist(f_test, inf.DB)` as
`.npy`, so S3–S6 are cheap re-runs off cached arrays.

> **Guard — must fail loudly.** Assert that the `cache.llms_map` index order equals
> `inf.label_map` order before using `D`. Both are sorted over sets F3 shows are
> identical, so this should hold — but a silent mismatch would invalidate every
> downstream number. Note also that `load_datasets` mutates `conf` in place
> (`dataset.py:190-195`), overwriting `llms_map`, `queries`, and `num_classes`.

### S4 — M3: structural annotation and enrichment

Build `results/D001/model_metadata.csv` covering all 52 models: organization,
family, base model, version, architecture, tokenizer, parameter count, and a
per-relationship `documented | inferred` flag (D001 requires flagging relationships
that are inferred rather than documented).

Derive pair labels: same base (one is a fine-tune of the other) · adjacent versions
· same family · same organization · same architecture · same tokenizer · unrelated.

Compute enrichment of the bottom decile (133 pairs) over the base rate across all
1326 pairs, with CI from a **model-level bootstrap** — resample the 52 models with
replacement and recompute pairs and decile. Pairs share models and are therefore
not independent; a pair-level bootstrap would understate the CI. Test D001's
FALSIFIES criterion directly with a permutation test (shuffle separability across
pairs, 10k draws). Bottom decile → `results/D001/hard_pairs.csv`.

> **Power caveat, stated up front.** Only ~8–10 documented base↔fine-tune pairs
> exist among these 52 models, so the expected count inside a 10% decile under the
> null is ~1. The decile test has power for large effects only. Mitigations: (a)
> also report a broader "structurally related" union label (~50–80 pairs); (b) also
> report a Mann-Whitney comparison of the **full** related-vs-unrelated
> separability distributions, which uses all 1326 pairs rather than thresholding at
> the decile. If CIs still span "no effect", report **INCONCLUSIVE** — D001
> explicitly permits this and forbids forcing a verdict.

## 3. Cost, scheduling, failure handling

Single Slurm job, `gh-dev` partition (72-core GH200, 2h QoS cap), `-t 02:00:00`.

Dominant cost is embedding ~62k unique strings. Measured throughput on a Vista
compute node is ~40 embeddings/s, giving **≈25–40 min wall-clock and ~0 GPU-hours**
(CPU-only torch build, per F5). S2–S7 run off cached `.npy` in seconds.

**Do not run this on a login node.** Observed login-node load average reached 48
with 148 concurrent users, and a 20-sample job failed to complete there.

| Failure | Response |
|---|---|
| Embedding pass exceeds the 2h cap | Resubmit to `gh` (no 2h cap), or install the aarch64 CUDA torch wheel (`--index-url https://download.pytorch.org/whl/cu126`) for GPU. Not expected. |
| Label-order guard trips (S1) | **Stop.** Do not patch around it; report as a blocker. |
| Templates fail to reproduce (S2) | Continue — shipped templates remain the reference — but record the deviation prominently in R, since it changes what M1 is measured against. |
| OOM during `precompute` | Lower `conf['embedding_batch_size']` from 256. |
