# P1 — Execution plan for D024 (fingerprint definition: CLOUD vs CENTROID vs SINGLE)

**Status: PROPOSED — awaiting review.** `gate: REVIEW`. S0 (inventory and
target-free setup) has run: job 1033286, 44 s on `gh`. **No CENTROID or SINGLE
chain has been selected, and nothing is trained.** S1 is deliberately left for
after the Review, so the freeze commit follows the approved rules (D023
precedent). **No existing repo file modified.**

**Headline.**
- **Neither S0 stop condition fires.** All 37 models get a SINGLE config in
  tier 1. The D024 greedy wrapper with D010's CLOUD statistic reproduces D010's
  chain `[193, 140, 237, 114, 233, 117, 0, 16]` exactly, with max |Δ objective|
  = 0.0 over the 8 steps.
- **The SINGLE rule has one ambiguity that must be fixed now (Call 1).** Every
  model's tier 1 holds the same four sampling settings. One is greedy decoding,
  whose `temperature` field reads 0.7 but is inert. "Lowest temperature" is
  either the sampled T=0.4 config (the field, literally) or the greedy config
  (effective temperature 0).
- **CENTROID is healthy. SINGLE has exact collisions:** about 1,900 of the
  172,494 cells are exactly 0, i.e. two models gave byte-identical embeddings.
  They are concentrated on Phi-3 pairs. This is real signal loss, not a code
  fault, and the objective is not degenerate (no argmax ties). Details below.

## Call 1 — SINGLE: which "lowest temperature"?

**The facts.**
- The D's rule ends in "lowest temperature, then lowest config index".
- In every model's tier 1, the candidates are sampled T ∈ {1.0, 0.7, 0.4} and
  one greedy config (`do_sample=False`, `temperature` field 0.7).
- Under `do_sample=False`, HF `generate` ignores `temperature`. The field's
  0.7 is an artefact of how the config tuple was drawn (A5's carve-out keeps
  `do_sample` as its own axis).

**Options.**
- **(a) field**, literal: sampled T=0.4. The reference fingerprint is one
  stochastic draw per (model, query).
- **(b) effective** *(recommended)*: greedy decoding, treated as temperature 0.
  "Lowest temperature" plainly means "the most deterministic setting", and
  greedy is its limit.
  - It is also the natural reading of a *reference* config: reproducible, and
    what a vendor-default / AdaptPrint-Gen-style reference would use.
  - With (a), CENTROID − SINGLE would partly measure one sample's noise rather
    than the lack of multi-config data.

**Blindness.** Both readings were computed in S0 to disclose the ambiguity.
The only thing inspected was the table above (target-free: medians, zero
counts, single-query CVaR). No chain exists and no trained number was read.
The two readings look alike on every health row, so neither is favoured by
what S0 saw.

**Proposal.**
- Primary SINGLE = (b).
- SINGLE-field = **selection-only sensitivity row**: its chain, objective trace
  and overlap with SINGLE-effective, reported in S1 and not trained.
- Design side can promote it to a trained descriptive row at ~7 GPU-min. TACC
  does not recommend it: the D forbids swapping the reference after seeing
  results, and training both invites exactly that.

## Call 2 — training order and identical-input `k`

The D says to "order shared queries as in D023's Call 3". The nested greedy
chains have their own order, and the attention readout is not order-invariant
(~0.2 pp, D023). For identical sets to be literally identical inputs across
**all** arms, including CENTROID vs SINGLE, the training order must be a
function of the set alone.

**Proposal (D023 Call 3, generalised to three arms).** At each `k`, the
training list for arm *a* is
`[q for q in JG[:8] if q in S_a,k]` (in JointGreedy's order), followed by the
remaining queries of `S_a,k` in ascending id.

- Here `S_a,k` = the set of the first `k` queries of arm *a*'s chain.
- For CLOUD this reproduces D010's lists verbatim, so no retraining is needed.
- **Identical-input `k`** for a comparison: the ordered lists are equal. Under
  this rule that means the sets are equal.
- **Exact-reproduction asserts** (stop and report on failure; do not proceed):
  - an identical-input `k` vs CLOUD must reproduce D010's per-seed attention
    counts and D020's linear counts exactly;
  - an identical-input `k` between CENTROID and SINGLE must give bit-identical
    counts in the two new arms. This is a free determinism check.
- **What changes.** A new arm's `k`-set is trained in canonical order rather
  than chain order. This only changes slot positions.
- The ordered training lists and the identical-`k` lists for P1, P2 and
  CLOUD−SINGLE are committed with the chains at S1, before training.

## Call 3 — the bootstrap, exactly (approval-before-S3, as D023 required)

D023's approved scheme (D023 Review Calls 1–2 plus amendment), extended to
three arms with **one** set of draws so P1, P2 and CLOUD−SINGLE are mutually
consistent.

- **Counts.** `c[a,k,r]` ∈ ℕ²⁵ is the per-config correct count over 37 models,
  for *a* ∈ {CLOUD, CENTROID, SINGLE}.
  - CLOUD = D010 `run_counts.npz` `joint_energy|k|r|cnt_total`.
  - The new arms come from S2.
- **Draws b = 1..2000.**
  - Config multiplicity `M_b = boot_draws(25, 2000, seed=20260928)[b]`, shared
    over all arms and `k`.
  - Seed indices `S = default_rng(20260928).integers(0, 5, (2000, 8, 5))`,
    shared over all arms, independent over `k`.
- **Accuracy.** `acc_{a,k}^(b) = (1/5) Σ_j M_b · c[a,k,S_bkj] / (37 · ΣM_b)`.
- **Point estimate:** full-data 5-seed means. **Interval:** 2.5/97.5
  percentiles.
- **Verdict per comparison** (the string implements the full rule):
  - BETTER if lo(mean over `k`=1..8) > 0;
  - WORSE if hi(mean over `k`=1..8) < 0;
  - PARITY if the interval of the mean over **that comparison's differing `k`**
    ⊂ [−0.02, +0.02] (D023 Call 2 (b));
  - else INCONCLUSIVE.
  - If every `k` is identical for a comparison (not expected), its verdict is
    "IDENTICAL CHAINS", with no bootstrap.
- **Sensitivity row (D023 amendment).**
  - Independent seed resampling on the differing `k`: the second arm of each
    comparison takes its seed indices from `default_rng(20260930)`.
  - If the verdict differs from the joint-seed verdict, R's headline says so.
  - The disclosure that 5 seeds with replacement understates seed variance by
    4/5 carries over.
- **Per-`k` disclosure:** the old D009/F1 reading (CI excludes 0 **and**
  |Δ| > max 5-run range), and D018's label lesson ("resolved" means both
  conditions).
- **Secondaries:**
  - (a) linear: the same draws with the seed layer dropped (deterministic fits,
    D020).
  - (c) `cnt_pair666`: same scheme, `k`=8 only. CLOUD's comes from D023's
    stored `JointGreedy|8|r|cnt_pair666`, which was extracted from D016's
    logits.

## Call 4 — raw-centroid trigger, pre-decided

**The D's rule.** The raw-centroid chain is trained only if it differs from
CENTROID's at `k`≥3. In that case, report it and raise a Call.

**The problem.** S0 shows raw medians spanning 10.8×, so the trigger is likely.
Raising the Call only at S1 costs a full review round-trip for a ~7 GPU-min
descriptive row.

**Proposal.** Define "differs" as: for some `k` in 3..8, the *set* of the first
`k` differs. If triggered:
- S1 records the Call in `selection.json` and in `## R`;
- the raw-centroid arm is trained in the same S2 job as a **descriptive
  sensitivity row** (no verdict, not in P1/P2), with the same order rule and
  counts.

If design side prefers the round-trip, S1 stops after the freeze and waits.

## Steps

**S1 — Selection** (CPU `gh` job, about 1 min). **Freeze, commit and push
before S2 is submitted.**
- Chains via `d024_lib.greedy_cvar` + `additive_hooks`, `k`=1..8, from
  `distances.npz`:
  - CENTROID;
  - SINGLE (Call 1 reading);
  - selection-only: SINGLE-other-reading and CENTROID-raw.
- Per-step objective traces, including `n_exact_ties_at_max`.
- Canonical training orders (Call 2) and identical-input `k` per comparison
  (P1, P2, CLOUD−SINGLE).
- The Call 4 trigger evaluation.
- Chain overlaps among CLOUD / CENTROID / SINGLE / paper8 / Greedy-ADD.
- Each chain's statistic evaluated on every other chain (a cross-objective
  table, target-free).
- → `results/D024/selection.json`, with `frozen_before_training: true`.

**S2 — Training** (one GPU `gh` job, 2–3 arms).
- **Attention.** D009 protocol via `d023_train.train_attention`, imported and
  not edited: `d009_train.run_one`, `hparams_from_shipped`, hparams hash
  asserted equal to D009's, `S_val` early stopping, `S_test` once, seeds 0–4,
  **all 5 checkpoints saved**. Each checkpoint is reloaded and its `mean_top1`
  asserted.
- **Counts:** `cnt_total`, `cnt_model`, `cnt_pair` (65) and `cnt_pair666` at
  every `k`, via D016's two-logit loop (`d023_train.pair666_counts`).
- **Linear.** `d023_train.fit_linear` (D020's `fit`, C=1.0 concat / 3.0
  mean-pool).
- **Exact-reproduction asserts** per Call 2. The reference for identical-to-
  CLOUD `k` is `joint_energy` (D010) and `JointGreedy` (D020).
  - One thing in the D023 helpers needs checking: `train_attention`'s
    `ident` argument only compares against a stored reference prefix. The
    CENTROID-vs-SINGLE bit-identity assert is done in `d024_train.py` after
    both arms finish.
- → `run_counts.npz`, `linear_counts.npz`, `runs.json`, and checkpoints under
  `results/D024/models/`.

**S3 — Analysis** (CPU).
- **Primary:** P1 and P2 per Call 3, plus CLOUD−SINGLE reported without a
  verdict.
- **Ladder row, descriptive:** SINGLE → CENTROID → CLOUD → Greedy-ADD (D023
  counts), per-`k` means with seed ranges.
- **(a)** Linear: concat and mean-pool, per `k` and mean over `k`, with
  config-bootstrap intervals.
- **(b)** Predictor footing on D016's 666-pair `k`=8 target.
  - Target = `full_pair_trained_accuracy.json`, over D016's three chains
    (paper8, coverage, joint_energy).
  - The CENTROID and SINGLE statistics are computed per pair on each chain's
    `k`=8 set.
  - Pooled ρ = mean over the three chains of per-chain Spearman, which is
    D021's `pooled`.
  - LOMO jackknife, 37 folds, `t_36`, via `d021_s0.jackknife`.
  - Paired Δρ(JOINT-E − CENTROID) and Δρ(CENTROID − SINGLE).
  - D021's `MAX`/`JOINT-E`/`ADD` values are read from `predictors.npz` and
    recomputed and asserted, not retyped.
- **(c)** Hard cases at `k`=8:
  - CVaR₀.₁ over the 666 pairs' trained two-logit accuracy, the worst pair,
    and the two named pairs (Falcon3-10B↔7B, Phi-3-medium-128k↔4k), per arm,
    with hierarchical intervals on differences;
  - D019's four hard-model sets (restricted top-1 recall, seed ranges), via
    `d019_hard_model_recall.model_sets`.
- **(d)** Chains:
  - overlaps among the arms and with paper8;
  - family composition by D022's labels;
  - union-flag count per chain from `query_flags.json`, descriptive only.
- → `analysis.json`.

**S4 — `## R`:** verdicts first, then per-`k` tables, secondaries, and the
measured cost (`sacct`).
