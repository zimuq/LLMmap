## Uncertainty method — fixed before any correlation (commit `c54e4d1`)

This section is unchanged from the draft committed and pushed before S0 ran. The
git timestamp is the audit trail.

**Leave-one-model-out (LOMO) jackknife, 37 folds.**

- Fold `m` drops every pair containing model `m` (36 pairs), leaving 630 of the
  666 pairs. Within each fold, every per-chain Spearman ρ (average ranks for
  ties) is recomputed on the 630 remaining pairs. The pooled statistic is the
  mean of the three per-chain ρ, and every Δρ is computed **within** the fold, so
  it is paired.
- `SE = sqrt((n−1)/n · Σ_m (T_(m) − T̄)²)` with `n = 37`. The 95% interval is
  `T̂ ± t_{0.975, 36} · SE`, where `t = 2.028` and `T̂` is the full-sample
  statistic. No bias correction. **Half-width = `t · SE`.**
- The same method is used for every interval in the D.

Why not a model bootstrap: resampling models with replacement creates pairs
between a model and its own copy, which have no target. Dropping them makes the
pair set vary for reasons unrelated to the question. The jackknife is also
deterministic. A known limitation, stated in advance: it can be somewhat
conservative, and that works against GO.

## Call 1 — the δ check failed. How should the gate proceed? (the D's mandated stop)

**What the numbers imply for the pre-registered rule.** Assume Δρ(`ADD` −
`JOINT-E`) has about the incumbents' paired half-width, h ≈ 0.09 (a guess: `ADD`
and `JOINT-E` may be more correlated than `JOINT-E` and `MAX`, which would narrow
it):

| outcome | rule | point Δρ needed at h ≈ 0.09 |
|---|---|---|
| GO (first leg) | lower > −0.05 | Δρ(`ADD` − `JOINT-E`) ≳ **+0.04** |
| NO-GO | upper < −0.05 | Δρ(`ADD` − `JOINT-E`) ≲ **−0.14** |
| INCONCLUSIVE | otherwise | a band about **0.18 wide** |

So the rule as written is still *decidable*, but only for large effects. NO-GO
in particular needs `ADD` to be dramatically worse than `JOINT-E`.

**Why the interval is wide, and why a fresh S_test won't narrow it.** An
i.i.d. treatment of 666 pairs would give roughly ±0.06 (Fisher-z approximation,
for this Call only; not a method). The LOMO jackknife gives about twice that.
**The width comes from there being only 37 models, and every model appears in
36 pairs.** It does not come from noise in the trained targets. The D's
INCONCLUSIVE branch suggests a fresh S_test. A fresh S_test improves the targets
but keeps the same 37 models, so **it would barely move this interval**. Worth
knowing before that D is drafted.

**Options:**

- **(a) Keep δ = 0.05 and the rule unchanged. Run it.** *(Recommended.)* The
  rule was fixed before any number existed, and the S0 finding changes how
  likely each outcome is, not whether the rule is fair. Report the reachability
  table above in `R` next to the verdict. An INCONCLUSIVE should then be read
  as "the 37-model instrument cannot resolve this", not "additivity is
  uncertain".
- **(b) Widen δ to about the observed half-width (≈0.10).** **Not recommended.**
  Widening δ makes GO easier (lower > −0.10) and NO-GO harder (upper < −0.10).
  It is one-sidedly permissive and chosen after seeing an interval.
- **(c) Move the primary to the non-ceiling subset** (paired h = 0.066). Still
  above δ, so the gain is small. And even though the choice would be based on
  incumbent-only widths, it's a footing switch made after S0. Not
  recommended.
- **(d) Add a decision criterion not based on ρ** (e.g. the S3(c) calibration, or
  the S3(d) k-curve agreement). This changes what the D is testing, so it's
  design side's call. Listed for completeness.

This is a genuine trade-off about what the gate should be able to decide, so it
may need the human (CLAUDE.md (c)).

## Call 3 (minor) — S3(d)'s k-curve: which chains, and the Monte Carlo

The D says "per chain" but cites trained sources that include D018 (the H1
chains). **Proposal:** run the k-curve on the three primary chains, plus the
two H1 chains as a separately labelled extension (5 chains × 8 `k` = 40 points),
against the attention readout (D009/D010/D018) and the linear readouts
(D017/D020).

The prediction is cross-fitted so it isn't optimistic:

- For chain `c` and `k`, simulate 2,000 draws per model from
  `N(μ_v^B, Σ_Q)`, where `Σ_Q` is block-diagonal from the per-query `Σ_q`
  (64-d each).
- Classify each draw by the nearest `μ_u^A` in Mahalanobis distance (equal
  priors).
- The predicted 37-way accuracy is the mean over models. Seed 20260928.

Report Spearman over the (chain, `k`) points and the absolute gap. Descriptive,
as the D says.

## Steps (after the Calls)

**S1 — Evidence tensor.** For every query (259), on S_build only:

1. PCA fit on all 2,775 points (SVD), keeping `d` = 64.
2. Pooled within-model residuals, then Ledoit–Wolf
   (`sklearn.covariance.ledoit_wolf`, `assume_centered=True`) → `Σ_q`.
3. Cross-fitted `M²_q(v,v') = (μ_v^A − μ_v'^A)ᵀ Σ_q⁻¹ (μ_v^B − μ_v'^B)`, exactly
   as in the D, with D007's halves.

The code path is `experiments/d021_s0.py:m2_query`, already run in S0's pilot.
Variants for S3(e): `d` ∈ {32, 128}; per-half `Σ` (Call 2); and per-pair-pooled
`Σ` (within-model covariance from the pair's two models only, 150 points,
Ledoit–Wolf). Outputs: `evidence_tok200.npy` (259 × 666, d = 64) plus one
`.npy` per variant and `evidence_tok200.meta.json` (schema
`d021-evidence-v1`, `d`, shrinkage per query, split seed, config counts,
config 49's exclusion). Negative-cell count reported.

**S2 — Predictors**, three chains × `k`=1..8:

- `MAX` and `JOINT-E` exactly as in S0.
- `ADD` = signed sum of `M²`.
- `JOINT-G`: the chain's per-query 64-d PCA scores concatenated (64·`k`-d), one
  full pooled-within Ledoit–Wolf covariance, and the same cross-fitted form.
- **Assert `J ≡ A` at `k`=1** to 1e-8. It must hold exactly: same features,
  same Ledoit–Wolf.

**S3 — Primary analysis** as the D specifies, with the Call 1 outcome.

- Verdict strings implement the **full** rule: both GO legs, NO-GO, else
  INCONCLUSIVE, plus a sign-consistency note across the three chains.
- Then secondaries (a)–(e) with Call 3's k-curve. `Φ(−√max(A,0)/2)` is used for
  calibration only.

**S4 — `## R`.** Verdict first, then the reachability table from Call 1, the
per-chain table, secondaries, and cost.

## Cost

- Loading is the bottleneck: 64 s for 21 queries → **~13 min for all 259**.
- `M²` takes 0.32 s per query → ~1.4 min at `d` = 64.
- Variants: ~3× that, with the per-pair `Σ` the largest at 259 × 666 small
  Ledoit–Wolf fits (~5–10 min).
- The k-curve Monte Carlo: 40 points × 37 × 2,000 draws, minutes.

**Total ≈ 30–40 min on one node, CPU only.** S0 itself took 2.3 min × 3 runs.
