## 1. What D036 asks (restated)

On corpus v2 (85 models, 3,570 pairs), JointGreedy-CVaR₀.₁ is held fixed while the fingerprint statistic changes:

| arm | statistic for a pair (v, v′) over the running set (concatenated queries) | source |
|---|---|---|
| **CLOUD-raw** | `2·E‖X−Y‖ − E‖X−X′‖ − E‖Y−Y′‖`, 75 S_build points per model | **new** (this D) |
| **CENTROID-raw** | `‖μ_v − μ_v′‖` | D035, chain and counts verbatim |
| **CLOUD** (scale-free) | the CLOUD-raw numerator ÷ `(E‖X−X′‖ + E‖Y−Y′‖)/2` | D029, chain and counts verbatim |
| PAPER8 | LLMmap's 8 queries | D029 counts, reference row |

- **P1 = CLOUD-raw − CENTROID-raw:** distribution vs mean, both unscaled.
- **P2 = CLOUD-raw − CLOUD:** the effect of the scale-free division with the distribution held fixed.
- **Triangle:** P1 − P2 = CLOUD − CENTROID-raw = D035's P1, replicate by replicate on the shared draws.

The open-set rows are a labelled secondary. They use v2 only, readout ② raw only, and D033's frozen protocol.

## 4. S1 — selection, frozen before any training or scoring (`d036_select.py`, CPU)

1. **Precompute.** `precompute(X, ms, pairs)` on the v2 S_build cubes (`d031_lib.cubes("v2", ("build",))`). This
   gives the XY2 / XX2 accumulators, the same ones S0 and D029 use.
2. **CLOUD-raw (full).** `cloud_chain(XY2, XX2, ia, ib, "raw")`:
   - all 85 models and 3,570 pairs (`m` = 357);
   - nested `k` = 1..8;
   - ascending-id scan with a strict `>`, so ties go to the lowest id.
   The chain and the per-step trace are stored (objective, mean / min statistic, number of exact ties at the max).
3. **Fold chains.** For the 5 model-level folds of D033 (`results/D033/chains.json → folds.model`, unchanged), with
   `tr, ho, cols = d033_lib.train_split("v2", fold, f)` (68 training models, 2,278 pairs, `m` = 227):
   - **CLOUD-raw^fold** = `fold_cloud(XY2, XX2, ia, ib, tr, cols, "raw")`;
   - **CENTROID-raw^fold** = `fold_centroid(D2, cols)`. `D2` is D035's `CENTROID|raw` array; a pair's value
     depends only on its two models, so restricting to `cols` uses training models only;
   - **CLOUD^fold** = D033's `JG^fold`, copied verbatim. S0 already showed `fold_cloud(..., "sf")` reproduces it.
   - Assert for every fold: no held-out model appears in any pair used.
4. **Stop conditions.** These are checked before anything is written; if one hits, there is no commit and the stop
   is reported in R. This is the D's S0 stop, moved to S1 (Disclosure D1):
   - the `k` = 1 argmax is not unique;
   - the objective trace is constant, for the full CLOUD-raw chain or any fold chain.
5. **Canonical training order.** `d031_lib.train_order(S, jg, p8)` for CLOUD-raw at each `k`: JG-shared queries in
   JG order, then ascending id; a set equal to a JG / PAPER8 `k`-prefix takes that order. D024 Call 2 and D031 used
   the same rule, and so did D035's CENTROID-raw. Two arms with the same set therefore get identical inputs.
6. **Identical-input `k`.** Recorded per comparison: P1 vs D035's `train_order["CENTROID|raw"]`, P2 vs D029's JG
   prefixes, and CLOUD-raw vs PAPER8. The differing `k` give each comparison's PARITY quantity.
7. **Descriptive rows (secondary (c), target-free):**
   - the CLOUD-raw trace;
   - overlaps at each `k` with CLOUD, CENTROID-raw, PAPER8 and D031's MMR|pearson|0.7;
   - per chain, the number of queries in the 233–257 id block;
   - a cross-objective table: every chain under CLOUD-raw, CLOUD (sf) and CENTROID-raw;
   - fold chains' overlap with the full-model chains, and the overlap between the fold arms;
   - **D034 union:** the set of all new chains (full and fold), and how many of its queries are not already in
     D033's union (`results/D033/chains.json → union`) or D035's chains.
8. **Commit and push** `results/D036/chains.json` (`frozen_before_training: true`) before S2 or S3 starts. S2 / S3
   assert this through `git log`.

## 5. S2 — closed-set training and scoring (`d036_train.py`, GPU node)

Only **CLOUD-raw** is trained. CENTROID-raw (D035) and CLOUD / PAPER8 (D029) are read verbatim.

- **Attention:**
  - D009 / D029 / D031 / D035 protocol: `d031_train.Ctx("v2", ("build", "val", "test"))`,
    `hparams_from_shipped`, `run_one`;
  - seeds 0–4 at every `k` = 1..8 (40 runs), S_val for early stopping only;
  - the best checkpoint is reloaded on S_test and asserted against `run_one`'s own accuracy and counts, exactly as
    D035's SINGLE path did;
  - checkpoints go to `results/D036/models/CLOUD-raw_k<k>_r<r>.ckpt` (gitignored).
- **Linear:**
  - D017 concat, 8 fits through a fork pool (`d031_train._lin_worker`, 8 workers);
  - the CUDA-initialising imports (`d009_train`, `d023_train`) come after the pool, as in D035;
  - the job command sets `OMP_NUM_THREADS=8 D031_WORKERS=8 D031_THREADS=8`. D035 lost two jobs because this was
    missing (D035 R).
- **Exact-reproduction asserts on identical-input `k`:**
  - a set equal to a JG / PAPER8 prefix goes through `d031_train.check_ident` against D029's counts (attention:
    every seed; linear);
  - a set equal to D035's CENTROID-raw set at that `k` gets an equality assert on all count arrays against D035's
    `run_counts.npz` / `linear_counts.npz`, and on the logits against `logits_att.npz` / `logits_lin.npz`;
  - a failed assert stops the job (no counts written) and goes to R as a stop.
- **Outputs:**
  - `run_counts.npz`, keys `CLOUD-raw|<k>|r<seed>|{cnt_total,cnt_model,cnt_pair,cnt_pair_all}`;
  - `linear_counts.npz`, keys `CLOUD-raw|<k>|…`;
  - `logits_att.npz`, `logits_lin.npz` (gitignored);
  - `runs.json`.
  - S_test counts are written, never printed or summarised, before S4.

If the CLOUD-raw set equals CLOUD's (or CENTROID-raw's) set at every `k`, that comparison has no differing `k`.
Call 2 covers that case.

## 6. S3 — open-set scoring, readout ② raw (`d036_openset.py`, CPU)

Protocol (D033 R §8, frozen):
- **Folds:** model-level, family-stratified (`chains.json → folds.model`).
- **Targets:** each held-out model's 25 S_test configs.
- **Enrolment:** all 85 models' 75 S_build points.
- **Score(t, m):** the sum over the chain of `2·A − W`, where `A[t, m, j]` is the mean point-to-cloud distance and
  `W[m, j]` the V-statistic within-cloud mean (`d033_lib.nc_terms` / `nc_scores(..., "raw")`); argmin, ties to the
  lower index.
- **Pooling:** each model is held out in exactly one fold and scored with that fold's chain.
- **Counts:** `d033_lib.counts` (D031 format: `cnt_model` 85 × 25, `cnt_pair_all` 3,570 × 25).

Steps:
1. Compute `nc_terms` from `d031_lib.cubes("v2", ("build", "test"))` for every query in the union of the three fold
   arms' `k` ≤ 8 chains. This includes all JG^fold queries, so the reproduction check below needs no stored terms.
   Saved as `results/D036/nc_test.npz` (gitignored, sha in `openset.json`).
2. **Reproduction asserts** (Call 3):
   - terms for queries in D033's union equal D033's `nc_test_v2.npz` (`A`, `W`) to |Δ| ≤ 1e-12;
   - re-scoring JG^fold for **all 5 folds** at `k` = 1..8 gives `cnt_model` and `cnt_pair_all` equal to D033's
     `counts_v2.npz → nc|model|JG|raw|<k>|…`.
3. Write per-arm, per-`k` pooled held-out counts for CLOUD-raw^fold and CENTROID-raw^fold to `openset_counts.npz`.
   CLOUD^fold is not rewritten: S4 reads D033's stored counts. `openset.json` holds the metadata, sha values and
   assert results, but no accuracy.

S2 and S3 run as two concurrent streams of one job (S3 is CPU-only).

## 7. S4 — analysis (`d036_analysis.py`, then `d036_plots.py`)

**Order:**
1. Write `plotdata.npz` (I1 tail curves). Draw and view `tail_k8.png` (closed-set: CLOUD-raw, CENTROID-raw, CLOUD,
   PAPER8 at `k` = 8, attention 5-seed mean) and `tail_openset.png` (held-out targets, three fold arms, `k` = 8,
   ②) **before any label is read**.
2. WORSE scan.
3. P1, P2.
4. `k` = 8 labelled secondaries.
5. Triangle.
6. Open-set O1 / O2.
7. Secondaries (a)–(e).

**Closed-set bootstrap** (same as D035):
- `d031_analysis.Boot("v2")`: configs `boot_draws(25, 2000, 20261005)`; attention seeds are slot `k` − 1 of
  `default_rng(20261005).integers(0, 5, (2000, 24, 5))`, shared by every arm;
- linear uses config draws only.
- The independent-seed row redraws the second arm's seeds from `default_rng(20261101)`, as D035 did.

**Quantity:** the mean over `k` = 1..8 of Δ (85-way top-1), attention, with the matching linear row. The PARITY
quantity is the mean over that comparison's own differing `k`.

**Verdict** (the D's table, with the symmetric linear clause, DECISIONS 2026-11-02):

```
BETTER        att mean-k lo > 0  and lin mean-k point > 0
WORSE         att mean-k hi < 0  and lin mean-k point < 0
PARITY        att mean over differing k: interval within [-0.02, +0.02]
INCONCLUSIVE  otherwise; "attention BETTER/WORSE, linear disagrees" when attention alone resolves
```

`d035_analysis.verdict` is not reused, because it has no linear clause on WORSE.

**`k` = 8 labelled secondaries** (D031 `label()` on E_all and the all-pair E_tail, attention + linear): for P1 and
P2. **WORSE scan:** every ordered contrast among {CLOUD-raw, CENTROID-raw, CLOUD, PAPER8}, on mean-`k` and on
`k` = 8 E_all / E_tail; each hit is listed.

**Triangle (secondary (d), assert):**
- the replicate vector of P1 − P2 equals the replicate vector of CLOUD − CENTROID-raw, to ≤ 1e-12;
- its point and 95 % interval equal D035's published P1 (`results/D035/analysis.json → primary.P1.mean_k1_8`:
  −0.0176 [−0.0270, −0.0086]) to rounding.
- A failure is a stop, reported in R.

**Open-set** (`d033_analysis.Boot("v2")`, `Unit`, `contrast`, `label`; D031 v2 config draws, 2,000 replicates,
folds fixed, no seeds):
- O_all / O_tail at `k` = 8 per arm;
- O1 = CLOUD-raw^fold − CENTROID-raw^fold and O2 = CLOUD-raw^fold − CLOUD^fold, with D033's label table:
  BETTER = lo(Δ_all) > 0 and lo(Δ_tail) > 0; WORSE = hi(Δ_all) < 0 or hi(Δ_tail) < 0; PARITY = both ⊂ ±0.02.
- **Level check:** CLOUD^fold's O_all / O_tail from D033's counts must equal D033 R's published `nc|model|JG` level.

**Secondaries:**

| | content |
|---|---|
| (a) | per-`k` P1 / P2 deltas with intervals, both readouts |
| (b) | at `k` = 8: H_all (57), stably-hard (26) (`d029_lib.targets`), N′ (161) (`results/D027/n_prime.json`) vs the rest, for P1 and P2; open-set H_all / N′ subsets |
| (c) | chains, overlaps, 233–257 block, cross-objective table, D034 union (from S1) |

| (e) | open-set curves at `k` = 1..8 for the three fold arms (②) |
