## Call 1 — the hierarchical bootstrap: resample seeds as **paired units across arms**, not independently

**What the D specifies.** Resample the 25 test configs paired across arms, and
"independently resample each arm's 5 seeds with replacement".

**Why that breaks here.** When the two arms' `k`-sets are identical (`k`=1, 2),
the runs are bit-identical seed for seed. Seeded training is deterministic, as
D016 and D019 showed. The true Δ is exactly 0, yet independent seed
resampling draws different seeds for the two arms and manufactures a nonzero
spread. More generally, both arms are trained with seeds 0–4. Seed *r* fixes
initialisation and data order in both, so the two arms' seed-*r* runs can be
positively correlated. Independent resampling then overstates the variance of
Δ.

**Proposal: resample seed indices jointly across arms.** For each draw, the
same seed index vector goes to both arms at a given `k`. This is valid whether
or not the arms are correlated: if they're independent it has the same
expected variance as independent resampling. It is exact when they're
identical.

**The exact scheme** (so the Review can approve it before S3, as the D asks):

- **Inputs.** `c[a,k,r]` ∈ ℕ²⁵ is the per-config correct count over 37 models,
  for arm *a* ∈ {ILP-ADD, JointGreedy}, `k`=1..8, seed *r*=0..4. JointGreedy's
  comes from D010's `run_counts.npz`, ILP-ADD's from S2.
- **Draw b = 1..2000.**
  - Config multiplicity `M_b` = `boot_draws(25, 2000, seed=20260928)[b]`,
    shared by both arms and all `k`.
  - Seed indices `s_{b,k,1..5}` = `default_rng(20260928).integers(0, 5, (2000, 8, 5))[b, k]`,
    shared by both arms, independent across `k`. Runs at different `k` are
    separate trainings.
- **Accuracy.** `acc_{a,k}^{(b)} = (1/5) Σ_j  M_b · c[a,k,s_{b,k,j}] / (37 · Σ M_b)`.
- **Primary.** `Δ^{(b)} = mean_k (acc_{ILP,k}^{(b)} − acc_{JG,k}^{(b)})`. The
  interval is the 2.5/97.5 percentile. The point estimate is the full-data
  5-seed means.
- **Disclosed property.** Resampling 5 seeds with replacement understates the
  seed variance of a 5-seed mean by a factor of 4/5.
- **The same scheme covers:** S-d (Greedy-ADD vs JointGreedy, ILP-ADD vs
  Greedy-ADD); S-b on `cnt_pair666`; S-a with the seed layer dropped (linear
  fits are deterministic, D020).

## Call 2 — identical-input `k` and what PARITY means

**The facts.**
- `k`=1 and `k`=2 are identical inputs, and possibly others: S1 will tell,
  before any training.
- Under Call 1, an identical-input `k` contributes exactly 0 to every draw.
  Averaging over all 8 `k` therefore multiplies both the point estimate and the
  interval by *n_diff*/8.

**What that does to each outcome.**
- BETTER (lower > 0) and WORSE (upper < 0) are **unchanged**; only the sign of a
  bound matters.
- **PARITY (interval ⊂ [−0.02, +0.02]) gets easier** as more `k` coincide. With 2
  of 8 identical, it effectively tests ±0.027 on the differing `k`.

**Options:**
- **(a)** keep the D's quantity exactly (mean over `k`=1..8, identical `k`
  included as exact zeros);
- **(b)** *(recommended)* keep (a) for BETTER/WORSE, but judge PARITY on the mean
  over the `k` whose ILP-ADD set differs from JointGreedy's. That set of `k` is
  fixed at S1, from selection alone, and committed with the chains before any
  training.
- **(c)** use the mean over differing `k` for everything. It has the same
  BETTER/WORSE outcome as (b), and its point estimate isn't diluted.

**Recommend (b):** it changes nothing the D decided except removing a dilution
the D didn't anticipate. `R` reports both means either way.

## Call 3 (minor) — slot order of ILP sets

ILP sets are unordered. The attention network is order-insensitive (D012), but
not bit-exactly. Concat has a 0–1-trace order residual (D020).

**Proposal:**
- Order each ILP set with JointGreedy's chain order for any shared queries
  first, then ascending query id.
- That makes identical-set `k` **literally identical inputs**. S2 then asserts
  that their retrained counts reproduce D010's per-seed counts (attention) and
  D020's (linear) **exactly**, which is a free determinism check.
- Greedy-ADD keeps its own selection order.

  re-solve to test for a tied optimum. Report status, gap and time.

- → `results/D023/selection.json`, **committed and pushed before the S2 job is
  submitted.**

**S2 — Training and evaluation (one GPU job).**
- **Attention.** For each new arm (ILP-ADD, Greedy-ADD), each `k`, and seeds
  0–4: D009's code path (`d009_train.run_one`, `hparams_from_shipped`, hparams
  hash asserted equal to D009's, `S_val` early stopping, `S_test` once).
  - **Save all 5 checkpoints.**
  - Reload each checkpoint, recompute the test logits, and assert that
    `mean_top1` matches.
  - Store `cnt_total`, `cnt_model`, `cnt_pair` (65) and `cnt_pair666` (666, via
    D016's two-logit loop) → `run_counts.npz`, keys
    `{arm}|{k}|{r}|{cnt_*}` (D009/D010 format).
- **Linear.** D020's `fit` (C=1.0 concat / 3.0 mean-pool, `tol=1e-6`,
  `max_iter=20000`), with the same counts → `linear_counts.npz`.
- **Baselines for S-b.** JointGreedy and paper8 `cnt_pair666` at `k`=8 come from
  D016's cached logits, with no retraining.
- **Identical-input `k`:** exact-reproduction asserts (Call 3).

**S3 — Analysis.**
- Primary: Calls 1–2. The verdict string implements the full rule: BETTER if
  the lower bound > 0; WORSE if the upper bound < 0; PARITY if the interval
  ⊂ [−δ, δ] on the approved quantity; else INCONCLUSIVE.
- The old D009/F1 rule, per `k`, as a disclosure.
- S-a, the linear readouts.
- S-b, the `k`=8 tail: CVaR₀.₁ over 666 trained pair accuracies, the worst
  pair, and the two named pairs, for ILP-ADD, Greedy-ADD, JointGreedy and
  paper8, with hierarchical intervals on the differences to JointGreedy.
- S-c, the Goodhart diagnostic: ρ(`ADD`, trained 666-pair accuracy) per new
  chain at `k`=8, flagged if < 0.595 − 0.15 = 0.445. Also the worst-66 overlap
  (by `ADD` vs by trained accuracy) next to JointGreedy's.
- S-d, the objective and optimiser decomposition.
- S-e, the certificate, gaps, times and overlaps.
- → `metrics_by_k.json`, `analysis.json`.
