# P1 — Execution plan for D019 (hard-model true-top1 recall for D018's two H1 chains)

**Status: PROPOSED — awaiting review.** `gate: REVIEW`. Nothing has been trained
and no D019 deliverable exists yet. The checks below are **read-only**: file
listings, and arithmetic on already-stored run records (D009 `runs.json`, D010
`metrics_by_k.json`, D015 `per_pair_k8.json`). They were run to write this P
correctly. **No existing repo file modified.**

**Headline:** S0's branch is already known. **2 of the 10 needed attention
checkpoints exist; 8 were never saved.** The D's premise that "the checkpoints for
both chains' final 5-seed evaluations were saved" is wrong. That premise came from
ambiguous wording in D018/R6, which TACC wrote. Retraining the missing 8 is ~2
minutes and bit-exact (D016's precedent). Two things in the `## D` need a
design-side call first: what "H1-linear" means here (Call 1), and a tie-break
under which the `consensus6` construction does not reproduce its own listed
models (Call 3).

## S0 — already answered: partially saved, by construction

`results/D018/models/` on `$WORK` holds exactly two files:

| file | what it is |
|---|---|
| `H1-attention_k8_r0.ckpt` | attention network, H1-attention chain, `k`=8, **seed 0** |

from that sentence. The sentence was incomplete, not false, but it cost a
premise here, so it's corrected now.

**The linear classifier fits were never saved at all.** D018's S2 fits
`sklearn.LogisticRegression` in memory and never persists it. This only matters
if Call 1 goes the other way. The fits are bit-deterministic (D017/S0), so a

## Call 1 — "H1-linear" should mean the H1-linear *chain*, read by the attention network

The D is ambiguous here. S0/S1 say "`H1-linear`'s deterministic fit" and "for the
linear chain, the single deterministic fit", which reads as the **linear
classifier**. Three other places in the same D point to the **attention
network**:

1. The comparators are the attention network's `per_model` ("the same quantity
   D009/D010 already store for `paper8`/`GreedyCover`/`JointGreedy`").
2. S1's correctness assert targets "that chain/`k`=8/**attention-readout**" in
   D018's `metrics_by_k.json`.
3. "What counts as an answer" computes the gap against "each chain's own all-37
   `mean_top1`", which for the three comparators is attention-network only.

**Proposal: both H1 chains are read by the attention network, 5 seeds each**,
exactly like the three comparators. D018 stored the targets:
`H1-attention|attention` `k`=8 = **0.860541**, `H1-linear|attention` `k`=8 =
**0.868757**. That gives one table, one readout, and five comparable rows.

**Not proposed:** a linear-readout `per_model` column. No comparator has one
(D017 stored no `per_model`, which the D itself notes), so the column would sit
next to nothing. Adding comparators would mean refitting D017's
paper8/coverage/joint rows, which is scope the D rules out. It costs seconds if
design side wants it anyway; say so and it goes in as a clearly separate table.

## Call 2 — retrain the 8 missing seeds; retrain seed 0 as well, as a determinism check

D019/S0 already authorizes "retrain just the missing ones … no design-side Call
needed unless the retrain cost is surprisingly large". It isn't: D016 measured
**9.8 s** per `k`=8 run, and D018's S2 averaged ~7 s. **Proposal:**

- Retrain **all 5 seeds for both chains** (10 fits, ≈1.5 min of training).
  Seed 0 is the extra one. The saved seed-0 checkpoint is then **reloaded and its
  `per_model` asserted bit-identical to the retrained seed 0's**. Every
  `per_model` value comes from one code path, and the two existing checkpoints
  serve as an independent determinism check rather than a mixed data source.
- **Asserts, per chain (stop on failure, do not report):** 5-seed mean
  `mean_top1` equals D018's stored value to 1e-6. The 5-seed
  `mean_top1_range` equals D018's stored range to 1e-6 (this catches a seed
  mismatch that happens to average out). `mean(per_model)` equals `mean_top1`
  (balanced test set, so it must). The `hparams` hash equals D009's.
- Reuse D018's exact code path (`d009_train.run_one`, `build_traces`,
  `hparams_from_shipped`, seeds 0–4), not a reimplementation. The only difference
  is that `per_model` is kept.
- **Save all 10 checkpoints this time** (~360 MB, gitignored), so the next
  per-seed question doesn't repeat this Call.

## Call 3 — `consensus6`: the stated tie-break does not reproduce the listed six

**What happens.** The D defines `consensus6` as the intersection of the three
methods' worst-6 pairs and lists 6 models (3 pairs: Phi-3-medium-128k/4k,
Falcon3-10B/7B, Mistral-7B-v0.2/v0.3). Under the tie-break the D states for
`worst6-paper8` (pair index), the intersection is **2 pairs / 4 models**. The
Mistral pair drops out:

| `coverage` rank | pair | acc. | index |
|---|---|---|---|
| 6 | gemma-1.1-2b / gemma-1.1-7b | 0.912 | 231 |
| 7 | Mistral-7B-v0.2 / v0.3 | 0.912 | 621 |

The two pairs tie exactly at the cutoff. Pair index keeps gemma.

**What does reproduce it.** Breaking ties by **D015's file order** (rows are
stored sorted by `paper8` ascending, so a stable sort on one method's column
breaks its ties by `paper8`) gives **3 pairs / 6 models, exactly the listed
set**. The same rule also reproduces FINDINGS' 2026-09-23 consensus table in
full: worst-6 → 3/6, worst-10 → 5/9, worst-16 → 10/12. So this is the rule the
chat analysis actually used.

**Proposal:** use the **listed six verbatim**, as the D instructs ("reuse
exactly, not re-derived"). Assert membership equals the list. Record in
`hard_model_recall.json` that the list is reproduced by the file-order
tie-break and not by pair-index. Also logged as `TACC_NOTES.md` Issue 15, since
the fix belongs in the design-owned `## D`. The D says "stop and report" on a
count mismatch, and this P is that report. **Nothing runs until design side
confirms.**

**The other three sets reproduce as stated** (checked read-only):

| set | construction check | size |
|---|---|---|
| `worst6-paper8` | `paper8`-ascending, pair-index tie-break → exactly the 10 listed names | 10 ✓ |
| `worst16-paper8` | same, first 16 pairs, procedural (as the D requires) | **21** ✓ |
| `naturalgap5` | **only** when sorted by the *min over* `paper8`/`coverage`/`joint_energy`: first 5 pairs → exactly the 7 listed names. The 7.6 pp jump after rank 5 is confirmed (0.824 → 0.900). Sorting by `paper8` alone gives 9 models. The D's "`min_over_methods`/`paper8`" wording is slightly ambiguous, so the script uses min-over and asserts the 7 names | 7 ✓ |

## Pre-P verification: the comparator rows already reproduce FINDINGS

Comparators computed from the stored per-run `per_model` (5 seeds, `k`=8,
attention), averaged across seeds, then restricted:

| condition | `worst6-paper8` (10) | `worst16-paper8` (21) | `consensus6` (6) | `naturalgap5` (7) | all-37 `mean_top1` |
|---|---|---|---|---|---|
| paper8 | .720 | .790 | .640 | .664 | .8452 |
| GreedyCover (coverage) | .750 | .798 | .680 | .665 | .8519 |
| JointGreedy (joint energy) | .803 | .825 | .755 | .745 | .8757 |

The `worst6` and `consensus6` columns match FINDINGS' 2026-09-22/23 tables
exactly (.720/.750/.803; .640/.680/.755). `mean(per_model)` equals the stored
`mean_top1` for all three.

**One trap found and handled:** D010's `metrics_by_k.json → runs` holds **10**
`k`=8 runs, 5 `joint_energy` and 5 `joint_mmd`. Filtering on `k` alone silently
averages the two and gives a wrong JointGreedy row (mean 0.8709 instead of
0.8757). The script filters on `condition` and asserts n=5 per comparator.

## Steps

**S0** — Record checkpoint availability (2/10 present, and why), load both
seed-0 checkpoints → `results/D019/checkpoint_availability.json`.

**S1** — Retrain 5 seeds × 2 chains at `k`=8 on D018's code path, keeping
`per_model` and saving all checkpoints. Reload the seed-0 checkpoints and assert
bit-identity. Assert `mean_top1` and range against D018 (Call 2).

**S2** — Four restricted means per chain (sets per Call 3, `worst16`
procedural, asserting n = 10/21/6/7), plus the comparator rows from stored runs
(condition-filtered, n=5 asserted).

**S3** — Full table, 5 conditions × 4 sets + all-37 `mean_top1` + gap, in the
FINDINGS shape. Point estimates only, described as descriptive (no new test, per
the D) → `results/D019/hard_model_recall.json`, rendered in `## R`.

## Cost

10 attention fits × ~7–10 s + data loading ≈ **3–4 min** on one gh node. The
read-only pre-checks above took seconds on the login node.

## Failure handling

- **A retrained seed does not reproduce D018's mean/range, or seed 0 ≠ its
  checkpoint:** stop and report in `R`. Do not use the numbers. That would mean
  the determinism D016 established no longer holds, which is a finding in its
  own right.
- **Any set-size assert fails:** stop and report. Do not substitute.
