## S2 — analysis (one CPU job; S_test read once)

**Bootstrap (fixed now; Call 5).**
- Configs: `M = d008_lib.boot_draws(25, 2000, seed=20261005)`, one draw set
  for every arm, `k`, readout, endpoint and stratum.
- Attention seeds: `S = default_rng(20261005).integers(0, 5, (2000, 24, 5))`;
  arm X at budget `k` uses `S[:, k−1]` — jointly resampled across arms at
  equal `k` (D023 scheme). Contrasts across different `k` (e.g. JG at 16 vs
  PAPER8 at 8, Call 2) use each side's own slot.
- Linear: config bootstrap only (deterministic fit).
- Pair accuracy in a draw: `M·(cnt_a + cnt_b) / (2 ΣM)` per seed, averaged
  over the resampled seeds; E_hard = mean over the stratum's pairs; E_all =
  `M·cnt_total / (85 ΣM)`.
- 95% percentile intervals. Disclosure: resampling 5 seeds with replacement
  understates a 5-seed mean's seed variance by 4/5 (as D023/D025).

**Order of computation (as the D requires):**
1. **Guardrail scan first** (Call 2): for every non-PAPER8 arm, every trained
   `k`, both readouts: Δ_all = E_all(arm, k) − E_all(PAPER8, min(k, 8)), CI.
   Every cell with lo(Δ_all) ≤ −0.02 is a **breach cell**; for each, the
   point Δ_hard and Δ_all are listed and "coincides with a gain" is marked
   when either point estimate is > 0. → `analysis.json["guardrail"]`, and the
   first lines of R if any cell breaches.
2. **Primary label** (attention, `k` = 8, JG vs PAPER8), in the D's order:
   GUARDRAIL BREACH → CONFIRMED → NOT CONFIRMED → INCONCLUSIVE. "linear
   Δ_hard > 0" is read as the linear point estimate at `k` = 8 (Call 6).
   The same table is also evaluated with linear as the label readout and
   reported (not the label unless the Review switches the primary).
3. **P1–P3** (linear, as the D; attention alongside):
   - P1: T1 = 6 tiny-aya pairs; a = acc(JG, 16); b = acc(JG+ML, 16) − a
     (paired draws). If JG+ML selects no ML probe by `k` = 16 (identical
     chains), b ≡ 0 and R says so. Companion: JG8+ML16 vs JG at 8 and 16,
     descriptive.
   - P2: T2 = 3 Ministral-3 pairs, acc(JG, 16).
   - P3: T3 (Call 1), acc(JG, 8).
4. **Secondary (a)–(f)**, all headed "corpus v2":
   - (a) E_hard and Δ by stratum, each with its own n:
     H_N (38) + F_N 85-way recall (64 models);
     H_X (19) + M_X recall (17 models);
     stably hard (26 = 20 H_N + 6 H_X, by the frozen bands);
     H_all without the 5 `mode_mixed` pairs (52);
     fresh-only (both members new: **42** pairs).
   - (b) E_all and Δ_all per block: new 48 / v1 37. The v1 37 include the
     3 regenerated gemma models (new text, but their configs replay
     corpus_v1's, whose S_test was read since D009).
   - (c) curves `k` = 1–8 (+ 12, 16, 24 where trained), E_all and E_hard,
     both readouts, all arms → `curves.png`.
   - (d) GC vs PAPER8 and GC vs JG at `k` = 1–8, both readouts (sign and CI;
     the D asks for sign only).
   - (e) per-pair table for H_all at `k` = 8 and 16: PAPER8 / JG / JG+ML (+GC
     at 8), both readouts, with band, stratum flags and `mode_mixed`.
   - (f) tiny-aya confusion from saved S_test logits: for the 4 tiny-aya
     models' traces, the share of 85-way errors that land within the family
     vs outside, PAPER8 vs JG (and JG+ML) at `k` = 8 and 16, both readouts.
5. → `analysis.json`, `curves.png`, `per_pair_hall.csv`.

## Calls

### Call 1 — T3 has 10 pairs, not 11 (pre-registered set; settle before S2)

The D defines T3 as "every Qwen pair in H_N except Qwen3.5-4B↔9B and
Qwen2.5-7B↔7B-1M", and states that this "leaves 11 pairs … the 9 Qwen3 pairs
in H_N". Counting `hard_sets_v2.json` → `H_N`: 12 Qwen pairs; minus the two
exclusions = **10**:
- Qwen2-1.5B ↔ Qwen2.5-0.5B; Qwen2.5-3B ↔ Qwen2.5-7B;
- 8 Qwen3 pairs: 30B-A3B↔4B, 30B-A3B↔8B, 30B-A3B↔30B-A3B-2507,
  30B-A3B↔4B-2507, 30B-A3B-2507↔4B-2507, 30B-A3B-2507↔8B, 4B↔8B,
  4B↔4B-2507.

The 9th "Qwen3" pair was most likely Qwen3.5-4B↔9B, which the same sentence
excludes. **TACC proposes T3 = these 10 (the rule as written).** The count
is an error in the design-owned `## D`; logged as `TACC_NOTES` Issue 23.
No result exists yet, so fixing it now does not touch pre-registration.

### Call 2 — guardrail scan scope and reading

- At `k` ≤ 8 every arm is compared with PAPER8 at the same `k`.
- At `k` = 12, 16 (JG, JG+ML) and 24 (companion) there is no PAPER8 at that
  `k`. **Proposal:** compare with PAPER8 at `k` = 8 (the paper's full set),
  flagged as an unequal-budget comparison in the scan.
- "Gain coincides with a guardrail failure": **proposal** — every cell with
  lo(Δ_all) ≤ −0.02 is listed in R's first lines regardless; cells where the
  point Δ_hard or Δ_all is > 0 are marked as coinciding with a gain. This
  over-reports rather than under-reports. Expect noise at `k` = 1–2 under
  attention, where intervals are widest; those cells are still listed.

### Call 3 — embed the 16 ML probe texts (new artifact, I5 unchanged)

- The LLMmap trace is [E(query) ; E(response)] per slot. Responses to the ML
  probes are embedded (D028), but the probe texts themselves are not:
  `_queries.npy` holds only the 259 pool texts, and D028 never needed more.
- S0.2 embeds the 16 texts with D028's embedding function in the unchanged
  env, after a parity check on the 259 pool texts against the stored array
  (stop if > 1e-2). 16 vectors, ≈ 1 GPU-min, inside the S0 job.
- Not a corpus or tensor change (I7 unaffected): a 32 KB derived array
  committed under `results/D029/`. JG/JG+ML selection does not use it (the
  joint statistic is over response clouds); only S1's traces do.

### Call 4 — candidate order, ties, and the ML coverage pointer (disclosure)

- `joint_greedy` keeps the first maximum (`o > best`), so the lowest
  candidate index wins an exact tie. ML probes sit at indices 259–274, so a
  pool query wins an exact tie against an ML probe. The objective is
  continuous; exact ties are not expected, and `chains.json` records the
  margin between the winner and the runner-up at each step.
- ML probes are not in the v2 tensor (D028: "never part of the pool tensor"),
  so their I4 coverage cannot be computed without a new tensor. The S0
  pointer (ii) uses the joint statistic instead; no tensor is built.

### Call 5 — bootstrap seeds and slots (disclosure)

- As §S2: seed 20261005 for both config draws and seed slots (the D fixes
  `boot_draws(25, 2000, seed=20261005)` for linear and "one draw set shared
  by all arms"; TACC uses the same seed for the attention seed slots).
- Slot array covers `k` up to 24.

### Call 6 — S_test discipline and the CONFIRMED rule's linear clause (disclosure)

- S1 *computes* S_test logits and counts (as D025 did) but **does not print,
  log or summarise** any S_test metric; the reload assert compares two
  numbers silently. The first S_test summary is made by S2.
- "linear Δ_hard > 0" in CONFIRMED is read as the linear **point estimate** at
  `k` = 8 (the D's "must agree in sign").
- Readout default stays attention, as the D says. One fact for the reviewer,
  from D027 (S_val, already on record): under linear, 17 of the 38 H_N pairs
  are below 0.90 for PAPER8, so linear has less headroom on E_hard. That
  does not change the label mechanics (no ceiling rule here), and TACC has no
  reason to recommend switching.
