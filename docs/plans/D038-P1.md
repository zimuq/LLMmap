## 1. What D038 asks (restated)

On S_build only, for v2 (85 models, 3,570 pairs) and v1 (37 models, 666 pairs, the negative control): which of
**H-strength** (MMR\* keeps individually stronger queries), **H-redundancy** (MMR\*'s set shares less
information) and **H-chase** (JG's later steps chase S_build noise in the hardest pairs) separates
JointGreedy-CVaR's 8-query set from CVaR + MMR's.

| rule | selection call (unchanged code) | reselected on halves |
|---|---|---|
| **JG** | `LLMmap/joint_greedy.joint_greedy(..., gamma=0.1)` via `d037_lib.jg_chain` (adds the exact-tie count) | yes |
| **MMR\*** | `d031_lib.mmr(E, 0.7, "pearson")` (`results/D031/variant_choice.json`, both views) | yes |
| **TOP-K[CVaR]** | `d031_lib.topk(E)` | yes |
| **GC** | `LLMmap/greedy_cover.greedy_cover(E, 8, gamma=0.1, agg="max")` | yes, both views (v1 reproduced in S0, §2) |
| MMR λ = 0.3, 0.5 (Pearson) | `d031_lib.mmr` | full S_build only, descriptive |
| PAPER8 | queries 0–7 | evaluated only |

- **M1:** query strength s_q(C) = CVaR₀.₁ over pairs of the single-query sf energy on config set C
  (`d031_lib.single_cvar`).
- **M2:** redundancy. Within-set Pearson / cosine of pair profiles, the effective number (Σλ)²/Σλ², and each
  pick's maximum correlation with earlier picks.
- **M3:** the two-halves test. Optimism on Y_joint and Y_max, per-step optimism, chain stability, and the
  low-ceiling share of JG's chased pairs.
- **M4:** readout ② raw on halves (references from the selection half, probes from the other) as a sanity
  anchor.

## 3. Two computation paths (Call 1)

The D asks for two things that cannot both hold:
- "Every statistic on a half is computed from the restricted blocks with the frozen float32 operations"
  (Two-halves mechanics);
- "The single-query sf energy on a config subset must use the same operations as the frozen tensor's builder.
  S0's full-set assert [rel 1e-5] is the guard" (Notes, S0).

The frozen tensors were not built from the float32 accumulators. They were built by
`d007_build_tensor.pair_worker` → `d007_lib.energy`, which uses `scipy.spatial.distance.cdist` in float64 and
stores the result as float32. The accumulator path (`d010_select.precompute`) forms squared distances as
‖a‖² + ‖b‖² − 2a·b in float32. On full S_build its `k` = 1 statistic misses the frozen tensor by more than
rel 1e-5 on 79 % of v2 cells (max rel 6.4e-3; §2). The likely cause is the self-distance diagonal, which the Gram form
leaves at float32 round-off instead of 0, so √ inflates the within-cloud means.

**Proposed (Call 1 (a)):** each statistic uses the path of the frozen object it has to reproduce.

| path | operations | used by | full-S_build guard |
|---|---|---|---|
| **1. single-query energies** | `d007_lib.energy`'s: per query, `cdist` (float64) of every model's 75 × 75 within-cloud and every pair's 75 × 75 cross-cloud distances. For a config set C, the V-statistic means are taken over the `[C, C]` sub-block, then raw = 2·xy − xx − yy, sf = raw / ((xx + yy)/2), stored float32. `cdist` entries are computed independently, so the sub-block is exactly `cdist` on the restricted clouds. | M1, M2, MMR\*, TOP-K, GC, Y_max, the pool ceiling | equals the frozen tensor (§2) |
| **2. set statistics** | `d010_select.precompute`'s float32 XY2 / XX2. A config set is the contiguous sub-block `[..., C, C]` (`d038_lib.restrict`), and JG / Y_joint use `joint_greedy`'s operations (`d036_lib.energy_stat(..., "sf")`, shown bit-exact to `_stat_all_pairs` in D036 S0). | JG, Y_joint | JG reproduces D029 / D010 (§2) |

- Path 1 is computed once per view for all 41 config sets (full + 20 × {A, B}), 259 queries, all pairs. It is
  kept locally as `results/D038/energies_<view>.npz` (gitignored; sha256 in `s0.json`).
- **Call 1 (b)** would compute single-query energies from the accumulator sub-blocks too. The S0 rel-1e-5
  assert would then have to be replaced by a measured tolerance, and MMR\* / TOP-K / GC would be reproduced
  only if no near-tie flips. I recommend (a).

## 7. S2 — two halves (`d038_splits.py`, CPU)

Per view, in this order:

**7.1 Load.**
- S_build cubes (`d031_lib.cubes(view, ("build",))`);
- path 1 from `energies_<view>.npz` (sha asserted equal to `s0.json`);
- path 2 (`d038_lib.accumulators`, ≈ 2 min and 20.8 GB on v2).

**7.2 Selection on each half (40 per view).** For half h:
- JG = `jg(restrict(XY2, h), restrict(XX2, h), ia, ib)`;
- MMR\* = `mmr(E[h], 0.7)`, TOP-K[CVaR] = `topk(E[h])`, GC = `gc(E[h])`.
- Nested `k` = 1..8, ties to the lowest id (each rule's own code). Exact-tie counts are stored.
- Runs as a fork pool over halves (12 workers on v2, each with a ≈ 5 GB sub-block), with
  `threadpoolctl.threadpool_limits(1)` in each worker.
- These are chain_A for the directed split that selects on h.

**7.3 Measures per directed split (r, d), sel = s, meas = m,** for each rule's chain c = chain_s (JG, MMR\*,
TOP-K[CVaR], GC) and for PAPER8:

- **M1 held-out:**
  - mean s_q(m) over c[:8] and the mean pool rank on m;
  - per-step s_q(m);
  - the in-sample s_q(s) alongside, as a descriptive row.
  - The non-shared picks (JG \ MMR\*, MMR\* \ JG on this split): counts and mean s_q(m).
- **M2 held-out:** `redundancy(E[m], c)`. The same on s, as a descriptive row.
- **M3:**
  - Y_joint(c[:k], C) for `k` = 1..8 and C ∈ {s, m}: `y_joint` on `restrict(XY2[U], C)`, where U is the union of
    this split's chains. The values are identical to restricting all 259 queries.
    - **Assert:** Y_joint(JG chain_s, s) equals JG's own trace objectives on s exactly.
  - Y_max(c[:k], C) = CVaR₀.₁ of MAX coverage over `E[C]` (float64, as `greedy_cover`).
  - **Optimism**_k = Y(c[:k], s) − Y(c[:k], m), on both yardsticks. Also stored: the held-out level Y(c, m) and
    the in-sample level Y(c, s).
  - **PAPER8** gets the same quantities. Its "optimism" involves no selection, so it is the null difference
    between the two halves (§11 D2).
  - **Per-step optimism** at step j = gain_j(s) − gain_j(m), where gain_j(C) = Y_joint(c[:j], C) −
    Y_joint(c[:j−1], C) and gain_1 = Y_joint(c[:1], C). This is computed for JG, MMR\*, TOP-K and GC. The steps
    sum to the `k` = 8 optimism.
  - **Chased pairs (Call 2 (a)):**
    - n_p = ⌊0.1 · P⌋ pairs (357 on v2, 66 on v1); bottom-n_p sets are taken by stable argsort, so ties go to
      the lower pair index.
    - For JG's chain_s at steps j = 4..8, the chased set is the bottom n_p pairs of the joint statistic of
      c[:j−1] on s (sets of size 3..7). These are the pairs the step's CVaR is computed against before it adds
      its pick.
    - **Reference:** the bottom n_p pairs of the joint statistic of MMR\*'s chain_s[:j−1] on s, at the same size.
    - **Low pool ceiling:** c_p = max over the 259 queries of E[m][q, p], i.e. on the **measurement** half (the
      D's note). "Low" = the bottom n_p pairs of c_p.
    - Shares for JG and the reference, per step and averaged over j = 4..8:
      - |chased ∩ low| / n_p;
      - on v2 also |chased ∩ H_all| / n_p and |chased ∩ N′| / n_p, against base rates of 57 and 161 out of
        3,570 pairs;
      - pair indices from `results/D028/hard_sets_v2.json` `H_all` and `results/D027/n_prime.json`.
- **Chain stability** (per undirected split r, per rule): |chain_A ∩ chain_B| at `k` = 8 and `k` = 4.
- **M4:** `readout2(X, ms, ia, ib, s, m, {JG, MMR*, TOP-K, GC, PAPER8})`.
  - This is D033's frozen point-to-cloud rule: `nc_terms` → `nc_scores(..., "raw")` → `counts`.
  - Reference clouds come from the s configs; probes are every m config of every model.
  - P_all = top-1 over the view's models. P_tail = CVaR₀.₁ over pairs of the both-direction two-model accuracy
    (D033's O_tail form). Both are given for `k` = 1..8.
  - Runs as a fork pool over directed splits (24 workers, `threadpool_limits(1)`).

**7.4 Plot data for I1 (no reading):** `plotdata.npz`, per view:
- the sorted pool ceiling c_p, on full S_build, A_0 and B_0;
- the sorted JG `k` = 8 joint statistic:
  - on full S_build (the frozen chain);
  - of chain_{A_0} on A_0 and on B_0.

**Outputs:**
- `splits.json`: seeds, indices, every half's four chains with tie counts and the JG trace;
- `measures.json`: every per-split quantity above, both views;
- `plotdata.npz`.
- Everything is committed. No summary or reading is computed in S2.
