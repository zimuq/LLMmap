## D — The question

> **On the frozen `S_energy_tok200` tensor (D007), does selecting `k`
> queries by CVaR-weighted coverage (`γ` < 1) produce a measurably better
> query set — on worst-tail and hard-subset accuracy, at equal `k` —
> than selecting by mean-coverage (`γ = 1.0`), random selection, or the
> paper's original 8 queries?**

**Everything here is post-processing on a tensor that already exists.**
No generation, no GPU, no new corpus data — this is what D006+D007 were
*for*. Per `TODO.md`'s own framing, this phase "isolates the objective
function from the pool": the candidate query pool (`Q_0`, 259 entries)
and the tensor are both frozen (invariant I6); only *which k queries get
selected from that fixed pool* varies across the conditions compared.

### Why this is the real test, not another premise check

D001/D004/D007 all asked *whether a hard tail exists* — they did not ask
whether CDQD's specific selection mechanism (CVaR-coverage via
`GreedyCover`) actually exploits it better than simpler alternatives.
D007 answered the premise question decisively (`TAIL CONFIRMED`,
`CVaR₀.₁/mean = 0.353` on `S_energy`) — this D is the first to test the
project's actual proposed contribution against that now-confirmed
backdrop.

### What's already decided and does not block this D

- **A3** (statistic): decided — use `S_energy_tok200` (scale-free
  variant for anything aggregated via `MAX`), per D007. `S_probe` is
  known unusable at this scale (D007 §R1) — do not reintroduce it as a
  comparison point in T2.3 below.
- **C1** (`γ`) and **C2** (`k`): both have defaults but are explicitly
  what this D's **T2.2 sweeps**, not prerequisites — this D produces the
  evidence that lets C1/C2 be finalized afterward, not the reverse.
- **A4** (which claim is primary — query efficiency vs. worst-class
  accuracy): still open, but does not block execution — `METHOD.md §8`
  requires all four metrics reported regardless of which one eventually
  headlines the writeup.

## What counts as an answer

**(Note added 2026-09-08, design-side, post-result — TACC_NOTES.md issue
12): the CONFIRMED branch below requires simultaneous improvement on two
metrics whose achievable resolution turned out to differ by an order of
magnitude — worst-class accuracy's bootstrap CIs are ±0.20 wide (only 25
test configs), while hard-subset accuracy's entire random-to-oracle range
is 7.5 points. This makes CONFIRMED nearly unsatisfiable regardless of
whether a real effect exists, independent of this D's actual result. Not
corrected retroactively — D008's verdict stands as reported (INCONCLUSIVE,
by the letter, correctly not reinterpreted by TACC to look more favorable)
— flagged here as a criterion-design lesson for anything that re-tests
this comparison later, matching the same class of issue D007/R3 hit.)**

| Outcome | Criterion |
|---|---|
| **CONFIRMED** | CVaR-coverage (`γ=0.1`) shows a meaningfully better worst-class and hard-subset accuracy than mean-greedy (`γ=1.0`) at equal `k`, **and** the small-`k` portion of the curve (`k`=1–3) rises relative to mean-greedy — per `TODO.md` T2.1's own two-part criterion. `CVaR_γ` is doing real work; Phase 3 (targeted generation) is a refinement, not a rescue. |
| **FALSIFIED (objective isn't the bottleneck)** | CVaR-coverage ≈ mean-greedy across all four `METHOD.md §8` metrics and across `k`. **This is a real, informative possibility, not a failure of this D** — `TODO.md` T2.1 pre-registers it explicitly. It means the candidate pool is already saturated with respect to the objective choice, and Phase 3 (can *generation* find what selection alone cannot) becomes the actual place any gain would come from. |
| **INCONCLUSIVE** | Mixed signal — better on some metrics/`k` but not others, or the gap is inside the random-`k`-baseline's variance band (many seeds). Report the full picture; do not force a verdict; state what a larger `k` range or a different metric weighting would need to show. |

## Required steps

**S1 — Implement `GreedyCover` (`METHOD.md §5.3`), selection only.** Given
the frozen tensor and a coverage rule, greedily build the nested
`k=1..8` chain: at each step, add the query maximizing the *marginal*
CVaR-weighted coverage gain. Must reduce to plain mean-greedy exactly at
`γ=1.0` (`METHOD.md §6.5`'s established equivalence — verify this
reduction numerically as a correctness check, not just by inspection).
**No outer loop, no targeted generation** (that's Phase 3) — this is
selection over the existing 259-query pool only.

**S2 — Implement the coverage rule with `γ` and the aggregation mode as
parameters.** Per-pair coverage of a query set `Q_k` is `max_{q∈Q_k}
S_energy[q][pair]` (invariant I4 — **MAX**, never sum/mean, for the
actual CDQD conditions). **Also implement a `sum`-aggregation variant**
(T2.1's explicit requirement) — this isolates whether I4's MAX-not-sum
choice itself matters, independent of the mean-vs-CVaR question.

**S3 — Run the five conditions, all on the identical frozen tensor:**
1. Original 8 queries (`confs/queries/default.json`) — fixed, no
   selection algorithm involved, the paper's own starting point.
2. Random-`k` — many seeds (state how many and why), for a variance
   band, not a single draw.
3. Mean-greedy (`γ=1.0`, MAX aggregation) — the project's own
   reconstruction of a mean-based baseline (`METHOD.md §6.5`; **not**
   "reproducing the paper's algorithm" — do not describe it that way in
   `R`).
4. CVaR-coverage (`γ=0.1`, MAX aggregation) — the actual candidate.
5. Mean-greedy with `sum` aggregation instead of MAX — isolates I4.

**S4 — Compute `METHOD.md §8`'s four metrics for every condition, at
every `k=1..8`:**
- Mean top-1 accuracy, worst-class accuracy, hard-subset accuracy,
  queries-needed-to-reach-X%.
- **Call 1 (flagged for design-side review, not to be decided
  unilaterally):** propose the concrete method for turning "a selected
  k-query set" into "an accuracy number." D004's M2 (leave-one-out
  nearest-neighbor classification over point clouds, restricted here to
  only the selected k queries' responses) is the natural template — reuse
  it if sound, or propose an alternative with a stated rationale. State
  which was used and why before results are trusted.
- **Call 2 (also flagged):** `METHOD.md §8` defines "hard-subset
  accuracy" against "the difficult subset defined by the original
  confusion matrix" — the paper's own hardest case (Llama-3-70B ↔
  Smaug-70B) is **not in our 37-model universe** (A1 excluded 70B-class).
  Propose a mapping: most likely, redefine "hard subset" as our own
  established hardest pairs (D004/D007's near-relative pairs, headlined
  by `Falcon3-10B↔Falcon3-7B`) rather than the paper's literal pair.
  State the proposed definition explicitly in `P` before computing
  anything against it.

**S5 — T2.2: the `γ` sweep.** `γ ∈ {1.0, 0.5, 0.25, 0.1, 0.05}`, MAX
aggregation, report mean-accuracy vs. worst-class-accuracy as a
trade-off curve. Purpose is explicitly framed (`TODO.md`): demonstrate
CVaR-coverage **contains** mean-greedy as the `γ=1.0` special case,
rather than being a competing, unrelated method.

**S6 — T2.3: statistic-sensitivity check, informed by D007.** Original
`TODO.md` wording says "recompute with 2 alternative statistics (e.g.
MMD, energy distance)" — since D007 already established `S_probe` is
unusable at this scale (saturated 51.8–98.2%), **do not use it as one of
the two alternatives here; that comparison is already answered.**
Compare `S_energy` (the tensor actually used above) against a genuinely
different unbounded statistic (e.g. MMD) on a subset, and check whether

headline finding.

**S7 — T2.4: the identifiability frontier.** List every pair with
`max_{q∈Q_0} S_energy[q][pair] < θ` — i.e. pairs that **no** query in

**Call 3 (flagged):** propose `θ` with a stated rationale (e.g. relative

absolute cutoff) — this is a genuine choice, not a default to assume.
For each frontier pair, report the same structural diagnostics D004 used
(same base? adjacent version? same family? same tokenizer?) — this is a

not a byproduct of S3–S6.

**S8 — Write `## R`:** verdict per the outcome table, all four metrics

**Status: PROPOSED — awaiting review.** Full plan:
[`plans/D008-P1.md`](plans/D008-P1.md). **No repo code changed.** The only D008
computation run so far is a cost benchmark, from a scratch directory outside the
repo; what it revealed is disclosed below.

**Frozen inputs verified present and intact:** corpus manifest `READY` (37/37),
`results/D007/S_energy_sf_tok200.npy` at `(259, 666)`, schema `cdqd-tensor-v1`.
Nothing is regenerated or re-embedded (I6). Also verified: **the paper's 8
queries are `Q_0[0..7]` exactly**, so condition 1 is directly evaluable on the
frozen tensor.

**Measured cost — ≈1.5 core-hours, no GPU, one `gh-dev` job** (job 977811, real
shapes): per-query eval×ref distance matrix 759 ms → 197 s for all 259 (2.66 GB);
`S_energy` 5.4 ms/cell; RBF-MMD 10.7 ms/cell → 0.51 core-h for a *full* second
tensor; **`GreedyCover` k=8 over 259 × 666: 0.02 s.**

That last number shapes the plan. Squared Euclidean distance on a concatenated
`k`-query trace **decomposes additively over queries**, so the 259 per-query
distance matrices are built once and any query set's distances are a sum of `k`
of them. Every condition, `k`, `γ`, and seed is then table arithmetic — which is
why this plan runs 200 random seeds, the full 5-point `γ` sweep, a **full** MMD
tensor for S6 rather than a subset, and a selection-stability check, instead of
subsampling any of them.

**Disclosure — what the benchmark already showed.** Timing `GreedyCover` required
running it: at `k=8`, `γ=0.1` and `γ=1.0` **overlap in only 2 of 8 queries**. No
accuracy was computed. This rules out the most trivial route to a FALSIFIED
verdict ("both objectives pick the same set") but says nothing about direction —
different sets can still classify identically.

**Calls 1–3, proposed (dispositions needed before S4 and S7 execute):**

- **Call 1 — accuracy.** 1-NN Euclidean, 37-way, **reference = build** (37 × 75 =
  2,775 traces), **evaluation = test** (37 × 25 = **925**), a trace being the
  concatenated I5 embeddings of one (model, config)'s responses to the `k`
  selected queries. This is D004's M2 with leave-one-out replaced by the
  I2-disjoint split it was standing in for — LOO existed there because D004 had
  no splits; we do. Selection reads build only, `val` is used only for a
  classifier-form check, test is touched once. Uncertainty by paired bootstrap
  over the **25 test configs** (not over traces — traces sharing a config are not
  independent).
- **Call 2 — hard subset.** The **65 structural near-relative pairs** (same
  `base` or same `lineage`, `results/D001/model_metadata.csv` — the same rule
  D004 and D007/S2a used), scored **pair-level** as 2-way restricted accuracy.
  Structural, so it is not defined by the tensor the selection optimizes;
  pair-level, because 33 of the 37 models appear in some near-relative pair, so a
  model-level "hard subset" would be 89% of the eval set. The paper's literal
  hard pair (Llama-3-70B ↔ Smaug-70B) is out of universe by A1. The empirical
  bottom decile is reported alongside, plus its overlap with the 65 — that
  overlap is the direct test of I1's premise.
- **Call 3 — `θ`.** Three tiers rather than one percentile: **T1** self-pair-null
  calibrated ("not distinguishable from the same model against itself"), **T2
  (primary)** operational — best-query 2-way test accuracy < 75%, and **T3** the
  5th-percentile view, labelled as definitionally non-empty. **Stated in advance:
  T1's frontier will almost certainly be empty** — the null value of scale-free
  energy is ≈ 2/n ≈ 0.03–0.05 while the observed pool-coverage minimum is
  **0.289** — and that emptiness is a result, not a failed threshold choice. A
  bare percentile can never return it.

**Four findings from planning (F1–F4); F4 is the consequential one.**

**F4 — the concatenated-Euclidean classifier silently weights queries by
embedding norm.** A query whose responses embed to larger vectors contributes more
to every trace distance, while selection under I4 treats the `k` queries
symmetrically. **This is D007/F3 reappearing on the classifier side of the same
pipeline** (raw magnitudes are not comparable across queries under unnormalised
embeddings). Proposal: per-query scale-normalised distances as primary — the exact
analogue of the scale-free convention the tensor already uses — raw concatenation
as sensitivity, the choice fixed on `val` before test is touched. Costs nothing:
the normaliser is a per-query scalar, so the sum decomposition survives.

**F1 — selection stability.** D008's CONFIRMED criterion leans on `k=1–3`, where
the verdict rests on *which single query* greedy picks from 259 noisy cells
(D007/R8). Proposal (~0.5 core-h): split the 75 build configs in half, recompute
`S_energy` on each, run both objectives on each, report chain overlap and each
chain's test accuracy. Same logic as D007's F2, applied to selection instead of
aggregation. Without it a `k=1` difference cannot be distinguished from estimator
noise.

**F2 — MMD needs a global bandwidth.** The per-cell median heuristic makes the
statistic's scale cell-dependent, and I4 takes a MAX **across queries** — the
operation D007/F3 established is invalid for a scale-varying statistic. One
global `σ²` for all 172,494 cells; per-cell variant kept as diagnostic only.

**F3 — worst-class accuracy has 4 pp resolution** (25 test configs → steps of
1/25), and it is the CVaR objective's headline metric. Mitigations: report the
**mean of the worst 3 classes** alongside the strict minimum (smoother, and it is
what CVaR actually optimizes), bootstrap CIs, and a `val` replication — with the
caveat that D006/S3's Call 3 gave `val` and `test` shared CoT/RAG prompt pools, so
that is a near-replication, not an independent one. **Pre-registered: if the gap
is smaller than 4 pp at every `k`, the verdict on that metric is INCONCLUSIVE,
not read off point estimates.**

**Minor, taken not escalated:** paper-8 at `k<8` reported as the mean over all
`C(8,k)` subsets (its file order is arbitrary); random-`k` = 200 independent
draws per `k`, not a nested chain; `k_max=16` for the "queries to reach X%"
metric only (headline curve stays `k=1..8`); CVaR convention byte-identical to
D004's `cvar_low` and D007's `cvar`, so numbers stay comparable across D's.

**Code-change disclosure:** new files only — `LLMmap/greedy_cover.py`,
`experiments/d008_*.py`, `experiments/submit_d008.slurm`. No existing shared

**Sequencing:** S0–S2 (frozen-input verification, `GreedyCover`, and the numeric

## R — Results summary

<!-- TACC writes below this line -->

# **INCONCLUSIVE** — per D008's own criterion, and not because the signal is weak

CVaR-coverage beats mean-greedy on **mean top-1 at every k=1–8, every CI excluding
zero**, and on worst-class by **+0.20 / +0.21 / +0.16 at k=1/2/3**. But D008's
CONFIRMED branch requires worst-class **and** hard-subset better at equal `k`, and
by k≥4 the worst-class gap falls inside its CI while hard-subset never moves at
all. That is the table's INCONCLUSIVE branch by the letter: *"better on some
metrics/k but not others."* Reporting it as such rather than picking the
nearest-looking branch.

**The substantive finding underneath the verdict is not mixed.** The objective's
benefit is real, replicates on every split and both statistics, and is
concentrated at **small `k`** — it is a query-**efficiency** gain, not a ceiling
gain. `METHOD.md §8` calls queries-needed-to-reach-X% "the dimension with real
headroom"; that is exactly where the effect landed.

| test, k=8 | mean top-1 | worst-class | worst-3 | hard-subset |
|---|---|---|---|---|
| random (200 seeds) | 0.6692 | 0.2538 | 0.3127 | 0.9074 |
| mean-greedy, `sum` agg | 0.7286 | 0.1600 | 0.2667 | 0.9369 |
| mean-greedy (`γ=1.0`) | 0.7276 | 0.2800 | 0.3333 | 0.9378 |
| paper's 8 | 0.7643 | **0.4400** | **0.5067** | 0.9357 |
| **CVaR (`γ=0.1`)** | **0.7870** | 0.2800 | 0.3867 | **0.9437** |

37-way, chance 0.027. Reference = build (2,775 traces), evaluation = test (925).

Worst-class tells the same story with a much shorter reach: **+0.1968** [+0.080,

**Queries needed to reach 70% mean top-1** — `METHOD.md §8`'s primary claim:

| CVaR | mean-greedy | paper's 8 | random |
|---|---|---|---|
| **2** | 4 | 5 | 12 |

To reach 80%: CVaR needs 14, no other condition reaches it within k≤16.

### R2 — Against the paper's 8 queries, the honest answer is split

This was asked directly, so it gets stated without hedging in either direction.

- **At equal k=8, CVaR is not clearly better.** Mean top-1 **+0.0235** [−0.004,
  +0.052] — favourable, CI touching zero (p(Δ>0) = 0.947). Hard-subset **+0.0084**
  [−0.008, +0.025]. Neither is a claim that survives contact with a reviewer.
- **On worst-class at k=8 the paper's 8 are *better* than every algorithmic
  condition**: 0.4400 vs 0.2800 (CVaR), 0.2800 (mean-greedy), 0.1600 (sum-greedy),
  0.2538 (random). Δ = **−0.1422** [−0.320, +0.080]. Not significant, but the point
  estimate runs against us and it is not an artifact of one split (see R5).
- **On query efficiency CVaR clearly wins.** It reaches the paper's k=8 mean
  accuracy (0.7643) at **k=4** (0.7632) — **half the queries** — and exceeds it at
  k=6. At k=1 it is +0.158 over the paper's average single query.
- **Mean-greedy loses to the paper's 8** on mean top-1 (−0.0368 [−0.070, −0.008])
  and worst-3 (−0.1628 [−0.280, −0.040]). So the gain over the paper is
  attributable to the **CVaR objective**, not to greedy selection as such.

The mechanism for the worst-class result is not mysterious: the paper's 8 include
direct identity probes ("What LLM are you exactly?", the injection-wrapped "who
created you"), which elicit self-identification. Our objective maximises CVaR over
**pairs**, and worst-**class** 37-way accuracy is a different object — a model can
be beaten by a different confuser under each of its 36 pairs. This is a real gap
between what the objective optimises and one of the four reported metrics, and it
is A4's question in empirical form.

### R3 — Hard-subset does not move because it has ~7 points of range, not because it is censored

Every condition scores 0.907–0.944, so before reporting "no difference" I measured
the ceiling (`hard_subset_ceiling.json`, an audit added beyond P1 — disclosed in
R8): the **oracle** — best 2-way *test* accuracy over all 259 queries, per pair,
averaged over the 65 near-relative pairs — is **0.9822**.

| | value |
|---|---|
| oracle ceiling (optimistic, selected on test) | 0.9822 |
| best condition (CVaR, k=8) | 0.9437 |
| random, k=8 | 0.9074 |
| **headroom above the best condition** | **+0.0385** |
| **whole span, random → best** | **+0.0363** |

So the metric is **compressed, not saturated** — this is *not* D001's failure mode,
and I am not claiming it is. But the entire dynamic range available to distinguish
two competent conditions is under 4 points, and the observed CVaR − mean-greedy gap
is 0.6. **D008's CONFIRMED branch required "meaningfully better" on a metric whose
full random-to-oracle range is 7.5 points**, which is worth flagging as a criterion
issue rather than reading the flat result as evidence of no effect. Same class of
observation as D007/R3: the outcome table and the measurement's resolution were set
independently of each other.

### R4 — S6: not an artifact of the statistic

Full 259 × 666 RBF-MMD tensor, one **global** bandwidth (`σ² = 117.73`, P1/F2 —
the per-cell median heuristic would have re-created D007/F3's cross-query
incomparability). MMD is *more* resolved than energy: **49,536 distinct values vs
16,727**, range [0.0011, 1.5722], nothing near either edge.

|---|---|
| Spearman, cells (172,494) | **0.9751** |

### R6 — S5: containment holds, and lower `γ` costs nothing on the mean

| `γ` | mean | worst-class | worst-3 | hard-subset |
|---|---|---|---|---|
| 1.0 (= mean-greedy) | 0.7276 | 0.2800 | 0.3333 | 0.9378 |

construction. `γ` = 0.05 or 0.1 both look defensible for C1; the sweep does not

### R7 — I4's MAX is the right aggregation, on the tail, weakly

Mean-greedy under `sum` instead of MAX: mean top-1 identical (−0.0015 [−0.035,
