## D — The question

> **On the frozen `S_energy_tok200` tensor (D007), does selecting `k`
> queries by CVaR-weighted coverage (`γ` < 1) produce a measurably better
> query set — on worst-tail and hard-subset accuracy, at equal `k` —
> than selecting by mean-coverage (`γ = 1.0`), random selection, or the
> paper's original 8 queries?**

**Everything here is post-processing on a tensor that already exists.**
No generation, no GPU, no new corpus data — this is what D006+D007 were
*for*. Per `TODO.md`'s own framing, this phase "isolates the objective
function from the pool": the candidate query pool (`Q_0`, 259 entries)
and the tensor are both frozen (invariant I6); only *which k queries get
selected from that fixed pool* varies across the conditions compared.

### Why this is the real test, not another premise check

D001/D004/D007 all asked *whether a hard tail exists* — they did not ask
whether CDQD's specific selection mechanism (CVaR-coverage via
`GreedyCover`) actually exploits it better than simpler alternatives.
D007 answered the premise question decisively (`TAIL CONFIRMED`,
`CVaR₀.₁/mean = 0.353` on `S_energy`) — this D is the first to test the
project's actual proposed contribution against that now-confirmed
backdrop.

### What's already decided and does not block this D

- **A3** (statistic): decided — use `S_energy_tok200` (scale-free
  variant for anything aggregated via `MAX`), per D007. `S_probe` is
  known unusable at this scale (D007 §R1) — do not reintroduce it as a
  comparison point in T2.3 below.
- **C1** (`γ`) and **C2** (`k`): both have defaults but are explicitly
  what this D's **T2.2 sweeps**, not prerequisites — this D produces the
  evidence that lets C1/C2 be finalized afterward, not the reverse.
- **A4** (which claim is primary — query efficiency vs. worst-class
  accuracy): still open, but does not block execution — `METHOD.md §8`
  requires all four metrics reported regardless of which one eventually
  headlines the writeup.

## What counts as an answer

| Outcome | Criterion |
|---|---|
| **CONFIRMED** | CVaR-coverage (`γ=0.1`) shows a meaningfully better worst-class and hard-subset accuracy than mean-greedy (`γ=1.0`) at equal `k`, **and** the small-`k` portion of the curve (`k`=1–3) rises relative to mean-greedy — per `TODO.md` T2.1's own two-part criterion. `CVaR_γ` is doing real work; Phase 3 (targeted generation) is a refinement, not a rescue. |
| **FALSIFIED (objective isn't the bottleneck)** | CVaR-coverage ≈ mean-greedy across all four `METHOD.md §8` metrics and across `k`. **This is a real, informative possibility, not a failure of this D** — `TODO.md` T2.1 pre-registers it explicitly. It means the candidate pool is already saturated with respect to the objective choice, and Phase 3 (can *generation* find what selection alone cannot) becomes the actual place any gain would come from. |
| **INCONCLUSIVE** | Mixed signal — better on some metrics/`k` but not others, or the gap is inside the random-`k`-baseline's variance band (many seeds). Report the full picture; do not force a verdict; state what a larger `k` range or a different metric weighting would need to show. |

## Required steps

**S1 — Implement `GreedyCover` (`METHOD.md §5.3`), selection only.** Given
the frozen tensor and a coverage rule, greedily build the nested
`k=1..8` chain: at each step, add the query maximizing the *marginal*
CVaR-weighted coverage gain. Must reduce to plain mean-greedy exactly at
`γ=1.0` (`METHOD.md §6.5`'s established equivalence — verify this
reduction numerically as a correctness check, not just by inspection).
**No outer loop, no targeted generation** (that's Phase 3) — this is
selection over the existing 259-query pool only.

**S2 — Implement the coverage rule with `γ` and the aggregation mode as
parameters.** Per-pair coverage of a query set `Q_k` is `max_{q∈Q_k}
S_energy[q][pair]` (invariant I4 — **MAX**, never sum/mean, for the
actual CDQD conditions). **Also implement a `sum`-aggregation variant**
(T2.1's explicit requirement) — this isolates whether I4's MAX-not-sum
choice itself matters, independent of the mean-vs-CVaR question.

**S3 — Run the five conditions, all on the identical frozen tensor:**
1. Original 8 queries (`confs/queries/default.json`) — fixed, no
   selection algorithm involved, the paper's own starting point.
2. Random-`k` — many seeds (state how many and why), for a variance
   band, not a single draw.
3. Mean-greedy (`γ=1.0`, MAX aggregation) — the project's own
   reconstruction of a mean-based baseline (`METHOD.md §6.5`; **not**
   "reproducing the paper's algorithm" — do not describe it that way in
   `R`).
4. CVaR-coverage (`γ=0.1`, MAX aggregation) — the actual candidate.
5. Mean-greedy with `sum` aggregation instead of MAX — isolates I4.

**S4 — Compute `METHOD.md §8`'s four metrics for every condition, at
every `k=1..8`:**
- Mean top-1 accuracy, worst-class accuracy, hard-subset accuracy,
  queries-needed-to-reach-X%.
- **Call 1 (flagged for design-side review, not to be decided
  unilaterally):** propose the concrete method for turning "a selected
  k-query set" into "an accuracy number." D004's M2 (leave-one-out
  nearest-neighbor classification over point clouds, restricted here to
  only the selected k queries' responses) is the natural template — reuse
  it if sound, or propose an alternative with a stated rationale. State
  which was used and why before results are trusted.
- **Call 2 (also flagged):** `METHOD.md §8` defines "hard-subset
  accuracy" against "the difficult subset defined by the original
  confusion matrix" — the paper's own hardest case (Llama-3-70B ↔
  Smaug-70B) is **not in our 37-model universe** (A1 excluded 70B-class).
  Propose a mapping: most likely, redefine "hard subset" as our own
  established hardest pairs (D004/D007's near-relative pairs, headlined
  by `Falcon3-10B↔Falcon3-7B`) rather than the paper's literal pair.
  State the proposed definition explicitly in `P` before computing
  anything against it.

**S5 — T2.2: the `γ` sweep.** `γ ∈ {1.0, 0.5, 0.25, 0.1, 0.05}`, MAX
aggregation, report mean-accuracy vs. worst-class-accuracy as a
trade-off curve. Purpose is explicitly framed (`TODO.md`): demonstrate
CVaR-coverage **contains** mean-greedy as the `γ=1.0` special case,
rather than being a competing, unrelated method.

**S6 — T2.3: statistic-sensitivity check, informed by D007.** Original
`TODO.md` wording says "recompute with 2 alternative statistics (e.g.
MMD, energy distance)" — since D007 already established `S_probe` is
unusable at this scale (saturated 51.8–98.2%), **do not use it as one of
the two alternatives here; that comparison is already answered.**
Compare `S_energy` (the tensor actually used above) against a genuinely
different unbounded statistic (e.g. MMD) on a subset, and check whether
`GreedyCover`'s **selected query ranking** — not just the premise verdict
— is stable. **Falsification:** if the selected `k`-query sets or their
relative accuracy ranking change materially under the alternative
statistic, the S3–S5 results are (at least partly) an artifact of the
statistic choice and must be reported as such, not quietly kept as the
headline finding.

**S7 — T2.4: the identifiability frontier.** List every pair with
`max_{q∈Q_0} S_energy[q][pair] < θ` — i.e. pairs that **no** query in
the entire candidate pool, not just the selected `k`, can separate well.
**Call 3 (flagged):** propose `θ` with a stated rationale (e.g. relative
to the tensor's own distribution — a percentile, not an arbitrary
absolute cutoff) — this is a genuine choice, not a default to assume.
For each frontier pair, report the same structural diagnostics D004 used
(same base? adjacent version? same family? same tokenizer?) — this is a
**standalone deliverable** (`METHOD.md §7` lists it explicitly as one),
not a byproduct of S3–S6.

**S8 — Write `## R`:** verdict per the outcome table, all four metrics
at every `k` for all five conditions, the `γ`-sweep curve, S6's
statistic-robustness result, S7's frontier with diagnostics, and an
explicit statement of which Call 1/2/3 choices were made and why.

## Constraints

**Applicable invariants:** I4 (MAX aggregation is the actual CDQD
condition; `sum` is a deliberate isolation variant, not an alternative
default), I6 (reuse `S_energy_tok200` exactly as D007 produced it — no
regeneration, no re-embedding).

**Out of scope:** any targeted-generation / CDQD outer-loop work
(`TODO.md` Phase 3, T3.1+) — this D tests selection over the *existing*
pool only. Do not let "the objective doesn't help much" (a legitimate
possible outcome here) turn into starting Phase 3 work inside this D —
that transition, if warranted, is a new D.

**Framing requirement, not optional (`METHOD.md §6.5`):** the mean-greedy
condition (S3.3) must be described in `R` as *"our reconstruction of
mean-based selection,"* never as *"reproducing LLmap's algorithm"* — the
paper has no such algorithm to reproduce (Eq. 2/3's distance function is
never actually instantiated). This applies to any figure caption or
prose this D's results eventually feed.

**Cost:** no GPU expected — `GreedyCover` and the metric computations
run against the already-embedded tensor and corpus. State a measured
cost in `P` regardless (this project's standing practice since D002/D007
— do not inherit an estimate without checking it applies at this shape).
