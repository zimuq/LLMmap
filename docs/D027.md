## D — The question

> **Among ~49 recent open-weight chat models, chosen in advance for dense
> near-relative structure, which pairs does LLMmap's own query set
> (`paper8`) fail to separate — and does adding them make the universe
> materially harder than the current 37?**

### Why, and what this D is not

- The current universe (37 models, `cdqd-corpus-v1`) is 2024-era and
  ≤14B. D016 showed that difficulty comes from kinship; the 2024-10 →
  2026 ecosystem is full of context-extension twins, version refreshes,
  pruned/size siblings and regional fine-tunes of one base.
- This D only **screens**. It generates the 8 `paper8` queries on S_build
  and S_val configs, trains LLMmap's classifier on them, and fixes the
  hard set by the already-decided D7 rule. It generates **no S_test
  data** and **no pool queries beyond `paper8`**.
- **Selection-bias guard (human-accepted risk (a)).** Candidates are chosen
  below by structure, before any data. `paper8` grades them; it does not
  choose them. The v2 universe for D028 is **all 37 + every candidate
  that passes the technical preflight (S0)**, whatever its screen result.
  The hard set is an endpoint inside that universe, not a filter on it.

### "LLMmap's performance" means

The closed-set protocol this project always uses (human-accepted risk
(b)): LLMmap's attention network, retrained on this universe, with the
`paper8` queries. It does **not** mean the released pretrained checkpoint
applied to unseen models (open-set), which is a different question.

### Candidate inclusion rule — fixed here

A candidate must satisfy all of:

1. **Window.** First public Hugging Face release (`createdAt`) between
   2024-10-01 and 2026-09-30. **Exception:** a pre-window checkpoint is
   admitted only as the documented same-base twin of a window candidate.
   Only `Qwen/Qwen2.5-7B-Instruct` uses it (twin of the 1M version).
2. **Open weights; a general instruct/chat model.** No code, math, medical,
   guard, OCR, tool-only or speech models; no quantised or reformatted
   copies of another checkpoint.
3. **Size ≤ 35B total parameters** (MoE counted by total). This fits the
   95 GB GH200 in bf16.
4. **Thinking can be turned off** (human decision). The model is
   non-reasoning, or its own chat template accepts
   `enable_thinking=False`. Always-reasoning models are excluded. So are
   models whose only switch lives in the system prompt, because that would
   collide with our system-prompt configs (I2).
5. **At least one N-neighbour** (same `base` or same `lineage`, the
   unchanged `near_relative_pairs` rule) in the 37 ∪ candidates.
6. **Loads in one shared environment** with the model's **own** chat
   template. This is checked in S0. Unlike D006's Together exception,
   there are **no fallback templates** for new models.

**Lineage ids for new rows** = the vendor's product line plus major
version, e.g. `qwen3` covers Qwen3 and Qwen3.5. The v1 rows are
unchanged, so N among the 37 is exactly D025's 65 pairs.
- New rows join a v1 lineage id **only if they are the same product line
  and major version**: Qwen2.5 → `qwen2`, Falcon3 → `falcon-3`,
  Granite 3.x → `granite-3`, EuroLLM → `eurollm`, third-party Llama-3.1
  derivatives → `llama-3`.
- v1's `gemma` id spans gemma 1 to 2, and `phi-3` spans 3 to 3.5. Those
  are inherited quirks; Gemma-3/4 and Phi-4 get new ids.
- The `base` column follows v1's convention: a documented derivation names
  the instruct checkpoint of its line.

### Hard set — the D7 rule, applied to the v2 universe

Unchanged from D7 / D025 S0 except for the universe:
- **N′** = `near_relative_pairs` over 37 ∪ surviving candidates.
- **B0′** = `paper8`, `k`=8, D009 attention protocol, seeds 0–4, trained on
  S_build of the whole v2 universe (one 37+C-way classifier per seed).
- **acc_B0′(p)** = two-logit restricted accuracy on **S_val**, 5-seed mean.
- **H′** = {p ∈ N′ : acc_B0′(p) < 0.90}, with D025-style S_val config-bootstrap
  stability bands (2,000 draws, seeds averaged within a draw; *stably
  hard* / *stably easy* / *uncertain*).
- **M_H′**, and **F_H′** (one-step N′ closure), and family groups — as D7.
- **H′_new** = pairs in H′ with at least one candidate model.

## What counts as an answer

**Primary label (pre-registered):**

| label | rule |
|---|---|
| **HARDER** | \|H′_new\| ≥ 3 **and** H′_new spans ≥ 2 lineages |
| **NOT HARDER** | \|H′_new\| = 0 |
| **MARGINAL** | otherwise |

**Instrument control (checked before the label; a failure is a Call).**
- On the 65 v1 N-pairs, the regenerated run must keep both stably-hard D025
  pairs below 0.90: Falcon3-10B↔7B and Phi-3-medium-128k↔4k.
- Report also:
  - the Spearman ρ of acc_B0′ vs D025 S0's acc_B0 over the 65 pairs;
  - D025's other two H pairs.

  This control shows that a new environment plus a larger universe did not
  change what the instrument sees. A failure is ambiguous between "the
  instrument drifted" and "the larger universe changed the training". It is
  reported and stops the label; it does not get explained away.

**Secondary (all descriptive, none decides anything):**
- (a) **LLMmap headline on the v2 universe (S_val):** `paper8` mean top-1
  over all models; mean recall over the 37 v1 models vs over the
  candidates; per-lineage recall.
- (b) **Full pair table:** acc_B0′ and the band for every N′ pair, sorted.
- (c) **Population check (D016 analogue):** every **non-N′** pair with
  acc_B0′ < 0.90. A hit means the structural rule missed a kinship. It is
  listed for design-side; it does **not** change H′ in this D.
- (d) **1-NN readout (human request; classifier-free):**
  - the D008 instrument (`d008_lib.summed` + `nn_predict`, the form D008
    fixed), reference = S_build, two-way restricted to each pair's two
    models, on S_val;
  - H′_1NN = N′ pairs < 0.90 under 1-NN;
  - report |H′ ∩ H′_1NN|, the pairs only one readout flags, and the
    Spearman ρ over N′.

  1-NN numbers are never compared with trained numbers, and never used to
  define H′ (evidence discipline; D016 showed the proxy over-states
  non-structural difficulty).
- (e) **Linear readout** (D017 concat, C=1.0): acc per N′ pair on S_val,
  and the set flagged < 0.90. This is for the open story-freeze readout
  question; it is not used here.
- (f) **Environment drift:** for each v1 model, the byte-identical rate of
  `paper8` answers on greedy (`do_sample`=False) S_build/S_val configs:
  new environment vs `corpus_v1`. There is no stop rule here: the
  environment change is intended. This number tells D028 whether v1's
  259-query shards can be reused or must be regenerated.

**Design-side lean, stated before any run:**
- **HARDER**, with confidence. Most likely new hard pairs:
  - the tiny-aya regional siblings;
  - SmolLM2-1.7B vs its 16k twin;
  - Qwen2.5-7B vs its 1M twin;
  - Tulu-3 vs 3.1;
  - Qwen3-4B vs 4B-2507;
  - the Mistral-Small trio.
- **Least likely:** Granite 4.1 vs 4.2 (4.2 is a reasoning-trained release
  even with thinking off). Falcon3-1B/3B should join v1's Falcon pair as a
  hard family.

## Required steps

**S0 — Environment, preflight, schema. No screening data yet.**
- **One new environment** (e.g. `llmmap-gpu-v2`) for every generation in
  this D, including the regenerated v1 models.
  - It needs a transformers version that loads the candidate
    architectures: qwen3 / qwen3_moe / qwen3_5, gemma3 / gemma4 /
    gemma4_unified, mistral3, olmo2 / olmo3, falcon_h1, cohere2, granite.
  - Record exact versions (torch, transformers, tokenizers, sentencepiece,
    `mistral_common` if used) and the HF revision SHA of every model.
  - **Exception:** a v1 model that already needed a dedicated environment
    in D006 (internlm2.5: sentencepiece 0.1.99) may keep one, recorded.
  - No other per-model environments.
- **Prompting wrapper (new file, not an edit).** A subclass of
  `LLM_huggingface` in `experiments/d027_llm.py`:
  - renders every template with `enable_thinking=False`, which Jinja
    ignores where unused;
  - keeps the system-role sentinel probe;
  - loads with `AutoModelForCausalLM`. Where that fails for a VLM-class
    checkpoint, it loads the model's own `architectures[0]` class with
    **text-only** inputs.
  - No `trust_remote_code` beyond D006's allowlist. A candidate that needs
    it is dropped.
- **Preflight per model** (all 37 + 49):
  - load;
  - render the system-role probe;
  - generate `paper8` on 3 fixed S_build configs, decoding once with
    `skip_special_tokens=False`;
  - **thinking check:** no output may contain `<think`, `</think>`,
    `<|channel|>`, `<reasoning` or a template-specific reasoning marker
    found in that model's template. Quote one raw output per candidate;
  - measured gen/s and peak memory;
  - **drop rules:** cannot load, has no own chat template, thinking cannot
    be switched off, or needs remote code. Then re-apply rule 5.
- **Batch size:** keep D006's `CORPUS_BATCH`=64 where it fits. On OOM, use
  a smaller batch for that model and disclose it (D006/S1c: batch size
  does not shift the response distribution). P may batch several configs
  per call, because 8 queries per config underfills a batch. Disclose it.
- **Configs:** D006's `build_configs()`, unchanged (same seed), so every
  model sees the same 75 S_build + 25 S_val configs as v1. **S_test is not
  generated.**
- **I7:**
  - declare the schema `cdqd-corpus-v2-screen` = the `corpus_v1` record
    plus `gen_env` (environment id) and `template_kwargs`;
  - write the migration note in `results/D027/` before S1 writes anything;
  - store the data in a new directory (`data/corpus_v2_screen/`);
    `corpus_v1` is untouched.
- **Metadata:** materialise the candidate table above verbatim, as
  `results/D027/candidates_metadata.csv` with `model_metadata.csv`'s
  columns. Compute N′, and assert that it restricted to the 37 equals
  D025's 65 pairs.
- **Report:** the survivors, the drops with reasons, the environment
  record, the N′ size and the projected cost. **S1 does not start until
  the Review approves S0's survivor list.** This is the last point at
  which the universe can change.

**S1 — Generate and embed.**
- `paper8` × (75 S_build + 25 S_val) configs × every surviving model:
  800 generations per model.
- Embed with I5 (tok200, unnormalised), exactly as `d006_s6_embed.py`.
- Commit the generation status, the manifest and the embedding hashes
  before any analysis.

**S2 — Train and read out.**
- B0′:
  - D009 attention protocol, seeds 0–4, on S_build;
  - early stopping on S_val loss, the same accepted optimism as D025;
  - the classifier is 37+C-way;
  - save per-trace S_val logits.
- Linear readout (e).
- 1-NN readout (d).

**S3 — Analysis.**
1. The instrument control.
2. H′ / M_H′ / F_H′ / family groups, then freeze them in
   `results/D027/hard_set_v2.json`.
3. The label.
4. Secondary (a)–(f).
5. Freeze the v2 universe list in `results/D027/universe_v2.json`
   (= 37 + S0 survivors).

**S4 — `## R`.** The label first, then the control, H′ with bands, the
LLMmap headline, the population check, 1-NN agreement, environment drift
and cost.

## Constraints

- **I2:**
  - S_build: training of every readout, and the 1-NN reference;
  - S_val: early stopping, H′ and every reported number;
  - S_test: **not generated, not touched.** Its configs stay unused for
    D028.
- **I5:** the same embedding model, tok200, unnormalised.
- **I6:** nothing here selects queries; `paper8` is fixed. The v1 tensor
  and corpus are not modified or regenerated in place.
- **I7:** a new schema id and a migration note before S1 (S0 above).
- **I1:** N′ ⊇ D025's 65 pairs, so it holds trivially. Report |N′|.
- **I3:** every readout uses all S_build configs per model as the
  reference cloud; nothing is collapsed to a centroid.
- **No tuning:** the 0.90 threshold, `paper8`, `k`=8, the seeds, the label
  rule and the candidate list are fixed above.
- **Human actions needed before S1** (TACC's HF account):
  - accept the licences for gemma-3-1b/4b/12b-it (manual approval), the
    four tiny-aya models (auto) and EuroLLM-9B-Instruct (auto);
  - confirm that the v1 gated models (gemma ×5, Llama ×2 and the rest,
    aya-23) are still accessible.

  Several candidates carry non-commercial licences (tiny-aya, UltraLong:
  CC-BY-NC; Falcon: TII licence). That is fine for research use; record
  it in the manifest.
- **Storage:** ~1.4 TB of weights on `$SCRATCH`, including re-staging the
  37 if purged (`ENV.md`'s 10-day purge clock). Generate within the purge
  window after staging.
- **Code:** new files only (`experiments/d027_*.py`, slurm files). Import
  the D006/D009/D025 code; do not edit it.
- **Cost:**
  - about (37 + 49) × 800 ≈ 69k generations, with model load dominating
    for the large candidates;
  - plus 5 attention trainings on ~86 classes, the linear fits and 1-NN;
  - expected ≲ 40 node-h;
  - **stop and raise a Call if the S0 projection exceeds 60 node-h**;
  - state the measured cost in `R`.
- **Out of scope:**
  - any pool query other than `paper8`;
  - S_test;
  - any selection algorithm;
  - D026's probes;
  - any change to D7's definition. The 1-NN and linear readouts are
    reported, never used for H′.
