## D — The question

> **For each hard near-relative pair, does a query chain selected only for
> that pair (a "specialist") separate it materially better than the global
> JointGreedy chain at the same budget `k`? And does the specialist keep
> improving up to `k`=16, or plateau?**

### Why this matters now

Every selection D so far (D008–D011, D018, D023, D024) chose queries for
all 666 pairs at once. The two named pairs never moved much under any of
them (Phi-3-medium-128k↔4k .67–.73, Falcon3-10B↔7B .80–.85, trained,
`k`=8). D023 showed the exact optimum only *redistributes* errors within
sibling pairs. The project has read this as a **pool ceiling** (METHOD §7).

That reading has not been tested directly:
- every chain shared its 8 queries across 666 pairs, so a hard pair only
  ever got a fraction of the budget;
- the single-query oracle values (.80/.84, D007) describe single queries,
  and D021 showed evidence accumulates across queries.

The two explanations call for different next steps:

| if the hard pairs are… | then the fix is… | cost |
|---|---|---|
| **budget-limited** (the pool can separate them, the shared budget can't afford it) | hierarchical / adaptive querying on the frozen corpus | CPU + training only |
| **pool-limited** (no combination of pool queries separates them) | new, mechanism-targeted probes (Phase 3 / Tier-3 H) | new generation, I7 bump |

### The hard set — D7's definition, fixed here and computed in S0

Decided by the human 2026-09-29 (`DECISIONS.md` D7). **Nothing in this
definition uses S_test, and nothing uses our own method's results.**

- **Stratum N:** the 65 structural near-relative pairs,
  `experiments/d008_lib.py:near_relative_pairs` (metadata, fixed since D001).
- **Reference protocol B0:** the paper's 8 queries (`paper8`), `k`=8, D009's
  attention protocol (5 seeds, 0–4), two-logit restricted accuracy per pair
  (`d009_lib.logit_stats`'s `per_hard_pair` quantity), **evaluated on
  S_val**, 5-seed mean.
- **Hard pairs:** `H = {p ∈ N : acc_B0(p) < 0.90}`.
- **Stability bands (descriptive):** config bootstrap on S_val (2,000 draws,
  seeds averaged within a draw):
  - *stably hard* if the upper 95% bound < 0.90;
  - *stably easy* if the lower bound > 0.90;
  - *uncertain* otherwise.

  Membership in H is by the point estimate. The bands are reported and used
  in one sensitivity row.
- **Hard models:** `M_H` = every model in some pair of H.
- **Hard families:** `F_H` = `M_H` plus every model joined to a member of
  `M_H` by an N edge (one-step structural closure). **Family groups** are the
  connected components of `F_H` under N edges.
  - Why the closure: D025's design-side check (FINDINGS 2026-09-29) found
    that gains on hard models can come at the expense of their un-flagged
    siblings (Phi-3-mini-4k −12pp, Mistral-v0.1 −7pp under JointGreedy vs
    paper8). A family-level unit makes that visible.

**Known, accepted optimism.** B0's attention checkpoints are chosen by S_val
loss, so S_val accuracies are slightly optimistic. The bias is uniform
across pairs. B0 is a fixed reference, not a compared arm.

**Expectation, for orientation only.** On S_test, paper8 puts 3 pairs below
0.90 (Phi-3-medium-128k↔4k .712, Falcon3-10B↔7B .804, Mistral-v0.2↔v0.3
.824), then a cluster at .904–.936. S_val may add some of those. Expect
|H| ≈ 3–7.

### The arms

All arms use the frozen `S_energy` build-side accumulators and D010's code
path (`LLMmap/joint_greedy.py`, scale-free joint energy, γ=0.1,
`cvar()` with m = max(1, ⌊γ·|P|⌋), ties to the lowest query id). Only the
pair set P that the CVaR runs over changes.

| arm | P | `k` | role |
|---|---|---|---|
| **GLOBAL** | all 666 pairs | 1..16 | the comparator; prefix 1..8 must equal D010's chain exactly |
| **SPEC(p)** | {p}, one per p ∈ H | 1..16 | **primary**: the pair specialist |
| **FAM(F)** | all pairs within family group F | 1..16 | secondary: the family specialist, the building block of a two-stage design |

If a family group consists of exactly one H pair and nothing else (e.g.
Falcon3), `FAM(F)` = `SPEC(p)`: assert and reuse.

### What is and is not known going in

- GLOBAL `k`=1..8 attention results exist (D010, `per_hard_pair` covers N ⊇
  H). Linear concat results exist (D017) and are deterministic, so a
  recompute must reproduce them exactly.
- Nothing is known about `k`>8 for any chain.
- **Resolution:** a pair's accuracy rests on 50 test traces (2 models × 25
  configs). Paired differences have 95% half-widths around ±0.06–0.10.
  Per-pair labels will often be INCONCLUSIVE unless the effect is large.
  The pooled row over H is the one most likely to resolve. This is stated
  now so an INCONCLUSIVE per-pair label is not read as a failure.

## What counts as an answer

> **Amended 2026-09-29 by `## Review — D025 / P` (Call 1).**
> - A **CEILING** label is added: `1 − acc_GLOBAL(p,8) < 0.05` on a
>   readout means no BUDGET/POOL label on that readout.
> - Each H pair gets a fixed **attribution** (READOUT-LIMITED /
>   NOT HARD ON S_test / tested).
> - Linear stays primary; its tested population is Phi-3-medium only.
> - The downstream mapping in the header is replaced by the Review's.
>
> The Review governs where it and this section differ.

**Primary readout:** D017's linear concat classifier (C=1.0, lbfgs,
max_iter 20000, tol 1e-6, 37-way, trained on S_build, deterministic), read
as two-logit restricted accuracy on each H pair, on S_test.
- *Why linear, not the attention network:* it is deterministic, so the
  interval is config-only and tighter. D017 showed it is at least as strong
  on this corpus. The question is about information in the query set, not
  one particular network.
- **Secondary readout:** D009's attention network (5 seeds), the same
  quantity, with D023's hierarchical config×seed bootstrap. Report the same
  labels. If the two readouts disagree on a label, report both. The label
  follows the primary, and the disagreement is flagged in `## R`.

**Quantities, per p ∈ H**, with `acc_X(p,k)` = two-logit accuracy on p of
arm X at budget `k`:
- `a(p) = acc_SPEC(p)(p, 8) − acc_GLOBAL(p, 8)`: specialisation at equal
  budget.
- `b(p) = acc_SPEC(p)(p, 16) − acc_GLOBAL(p, 8)`: what a dedicated, doubled
  budget buys.
- **Pooled:** the mean of `a` and of `b` over H.

Intervals: 95%, the standing paired config bootstrap (`d008_lib.boot_draws`,
2,000 draws, seed 20260929, one set of draws shared by all arms and pairs).

**Pre-registered labels** (materiality margin M = 0.05):

| label | rule |
|---|---|
| **BUDGET-LIMITED** | `a` ≥ +0.05 **and** lower bound of `a` > 0 |
| **POOL-LIMITED** | upper bound of `b` < +0.05 |
| **CONFLICT** | both of the above hold (possible only if SPEC falls from `k`=8 to 16); report, no downstream action |
| **INCONCLUSIVE** | neither |

- **Why M = 0.05, not the project's δ = 0.02.** δ = 0.02 is defined on mean
  top-1 over 37 models. It cannot be reached at 50 traces per pair. 5pp is
  the decision-relevant size: D024's hard-model effects were 3–6pp, and a
  two-stage architecture is not worth building for less.
- **Downstream uses the pooled label and the family-level labels**; per-pair
  labels are reported but do not trigger anything alone.

**Secondary (descriptive):**
- (a) **Family level.** For each family group F: family-restricted recall
  (argmax over F's logits only, per-model recall, mean over F) under
  `FAM(F)` vs GLOBAL, `k`=1..16. The same `a`/`b` quantities and labels,
  marked descriptive. These scope any two-stage follow-up.
- (b) **Both directions.** For each H pair, the two directional accuracies
  (model a's traces, model b's traces) for every arm. This shows whether a
  gain is real or an error moved from one twin to the other (D023's
  Falcon +13.6 / −16.8 pattern).
- (c) **Cross-specialist placebo.** When |H| ≥ 2: each H pair's accuracy
  under the *other* H pairs' SPEC chains, at `k`=8 and 16. A SPEC gain that
  an off-target specialist also shows is not specialisation.
- (d) **More global budget.** GLOBAL at `k`=9..16: mean top-1, F_H 37-way
  recall, and M_H recall. Also the mandatory hard-tail plot (666-pair
  trained two-logit accuracy, `k`=8 vs `k`=16).
- (e) **S_val replication row** (linear readout only). The same `a`, `b` on
  S_val. **Caveat:** H was selected on S_val with paper8. Report the sign
  and size only.
- (f) **Stably-hard sensitivity.** The pooled `a`, `b` restricted to the
  stably-hard band.
- (g) **By-products:**
  - per H pair, the count of queries with byte-identical greedy-reference
    answers (D024 S0's method);
  - each SPEC chain's objective trace, overlap with GLOBAL, and D022 flag
    count.
