## Why this D

- **D038 (S_build only) located MMR\*'s v2 edge over JG.**
  - It is **query strength**: MMR\*'s queries are individually stronger, +0.017 in held-out s_q, 40 / 40, 4× the v1
    difference.
  - It is **not redundancy**: JG's set is the less redundant one.
  - It is **not noise-chasing**: optimism ≈ 0 for every rule.
  - Set-level tail yardsticks (JG's joint statistic, MAX coverage) rank sets almost opposite to accuracy. JG and GC
    both pick some of the pool's weakest single queries (JG: ranks 149 and 256; GC: 149, 256, 233, 258) because
    those fill specific bottom-decile pairs.
  - Pure strength (TOP-K[CVaR], effective number 3.0) loses to MMR\* on v2. So enough diversity is also needed.
- **MMR\* gets that balance through λ**, which D031 had to choose on S_val (pearson 0.7). The human asked for a rule
  that reaches it without a tuned trade-off parameter.
- **Why SUM is the candidate.** SUM-coverage scores a pair by the sum of its per-query energies, so every query's
  evidence counts.
  - Under MAX, a strong query that separates the same pairs as an earlier one adds zero (D038: GC skips query 0,
    rank 2, correlation 0.835 with 193). Under SUM it still adds. So strength is not discarded.
  - Under CVaR₀.₁ the gain is still scored on the current bottom decile, so a query that only repeats easy pairs
    adds little. That is the diversity pressure.
  - The trained and summed readouts both accumulate evidence across queries. D021 (v1) found accumulation ranks pair
    difficulty better than the joint statistic or MAX.
- **Why it might fail (stated before the data).** SUM + CVaR is still a set-level tail yardstick, the kind D038
  found misaligned with accuracy. It may also reach for weak tail specialists. Stage 1 checks this directly, before
  any training.
- **Prior evidence (v1 only).**
  - D023: an exact ILP maximising CVaR₀.₁ of summed, whitened evidence (`ADD`) tied JG at every `k`. On v1, though,
    JG, MMR\* and TOP-K also tie, so v1 cannot separate these rules.
  - D008 ran SUM only at γ = 1, where it reduces to ranking by mean (= TOP-K[MEAN]).
  - **SUM + CVaR has never been run.**

## D — The question

> **On v2, does SUM-coverage + CVaR₀.₁ select a set that keeps individually strong queries (like MMR\*) while
> staying diverse, and does it then match MMR\*'s accuracy without a λ?**

### Arm

| arm | selection call (unchanged code) |
|---|---|
| **SUM** | `LLMmap/greedy_cover.greedy_cover(E, 8, gamma=0.1, agg="sum")` on the frozen sf tensor (both views, full S_build). On D038's halves, `E` = the half's path-1 energies (`results/D038/energies_<view>.npz`). |

- **`agg="sum"` is the module's documented isolation variant.** No code is edited. Running it as an arm does not
  change I4; any change to I4 would be a METHOD revision.
- **References (reused verbatim, nothing re-selected or re-trained):** JG, MMR\* (`MMR|pearson|0.7`),
  TOP-K[CVaR], GC (MAX) and PAPER8. Stage 1 uses D038's stored per-split chains and measures. Stage 2 uses the
  stored D029 / D031 / D032 / D037 counts.
- **SUM has no tunable parameter.** γ = 0.1 is the method default. S_val is not used for any selection choice.

### Stage 1 — target-free (S_build only; CPU; both views)

**S0 checks (stop for a Call on failure).**
- **γ = 1 reduction.** `greedy_cover(E, 8, 1.0, "sum")` must equal ranking by mean single-query sf energy:
  - D032's TOP-K[MEAN] chain on v2, [109, 117, 123, 114, 1, 132, 136, 121];
  - D008's `mean_greedy_sum` prefix on v1, [123, 114, 117, 109, 1, 113, 140, 132].
- **Inputs.** The frozen tensor sha (D029 / D031) and the energies sha equal D038 `s0.json`.
- **Reproduce one stored D038 M4 value bit for bit** before computing SUM's: PAPER8's P_all at `k` = 8 on directed
  split (0, 0).

**S1 — full-S_build chain, both views.**
- The SUM chain for `k` = 1..8, with ties per step.
- Per pick:
  - pool rank and s_q (D038 M1 definitions);
  - the maximum Pearson correlation with earlier picks (M2).
- Chain-level:
  - mean s_q and mean pool rank;
  - eff_n, and within-set Pearson / cosine;
  - overlap with JG, MMR\*, TOP-K[CVaR] and GC.
- Y_joint and Y_max of the chain, descriptive only.

**S2 — the 40 directed splits** (D038's `splits()` and `directed()`; seeds 20261109 + r).
- Reselect SUM on each half.
- Per directed split (s, m), compute on m for SUM's chain_s:
  - M1: mean s_q(m) and mean pool rank;
  - M2: eff_n(m);
  - M4: readout ② raw, references from s, probes from m (D038's `readout2`); P_all and P_tail, `k` = 1..8;
  - M3 optimism on Y_joint and Y_max, descriptive only.
- Pair each quantity with D038's stored values for MMR\*, JG, TOP-K[CVaR] and GC on the same directed split.

**Stage 1 readings** (D038's rule: median, 2.5–97.5 % band, n(> 0) / n(< 0); "consistent" = ≥ 36 / 40; v2
decides, v1 is reported alongside).

| | d per directed split (`k` = 8) | what it shows |
|---|---|---|
| **S-strength** | mean s_q(m): SUM − JG | SUM keeps strength better than JG |
| **S-diversity** | eff_n(m): SUM − TOP-K[CVaR] | SUM avoids TOP-K's near-copies |
| **S-proxy vs JG** | P_all: SUM − JG | **the gate** (below) |
| S-proxy vs MMR\* | P_all: SUM − MMR\* | descriptive. The proxy is valid only among sets of comparable strength (D038 Review). R states SUM's strength next to it. |

- **Gate for Stage 2:** Stage 2 runs if and only if S-proxy vs JG is consistent > 0 on v2 (n(d > 0) ≥ 36 / 40).
  - Otherwise D039 closes after Stage 1. R reads: "SUM + CVaR does not fix the strength problem on the
    build-internal proxy". No training is done.
- **Identical-chain shortcut.** If SUM's full-S_build v2 chain equals an existing trained chain as a set at every
  `k`, Stage 2 is not run. R reuses that chain's cells and says so.
- **I1 before readings:** a tail plot of SUM's `k` = 8 summed coverage, full S_build and A₀ / B₀, together with
  the pool ceiling (D038's plot form).

### Stage 2 — trained comparison (v2 only; runs only if the gate opens)

- **Protocol:** D037's, verbatim.
  - Attention: 5 seeds, `k` = 1..8, D031 draws, early stopping on S_val.
  - Linear: 32 BLAS threads, as D029 / D037.
  - Endpoints E_all and E_tail on old S_test, read once.
- **Contrasts** (Δ = SUM − X), labelled with `label37` (BETTER / PARITY at TOST δ = 0.02 / symmetric WORSE /
  INCONCLUSIVE):

| | contrast | why |
|---|---|---|
| **C1 (primary)** | SUM − MMR\* | Does the λ-free rule match MMR\*? |
| C2 | SUM − JG | Does it beat the current method rule? |
| C3 | SUM − GC | **The I4 contrast:** same code and γ, SUM vs MAX |

- **Secondaries:**
  - mean-over-`k` labels;
  - the WORSE scan;
  - H_all and stably-hard sets at `k` = 8 (D028 / D037 form);
  - JG − MMR\* and TOP-K − MMR\* reference rows (verbatim);
  - **proxy-vs-trained agreement:** each arm's Stage 1 proxy rank against its trained rank (D021's Goodhart check).
- **Pre-registered interpretation:**

| C1 | reading |
|---|---|
| BETTER or PARITY | SUM is a λ-free rule as good as MMR\*. Design-side drafts the METHOD §5.1 / I4 consequence for the human; confirmation on S_test′ (D034). |
| WORSE or INCONCLUSIVE, with C2 BETTER | SUM improves on JG but does not reach MMR\*. Recorded; no method change proposed from this D. |
| otherwise | No λ-free improvement found. MMR\* vs JG stays the open choice for the human. |

- **Old S_test is development grade** (inspected repeatedly). No number from this D is a paper headline without
  S_test′.

## Constraints

- **I1:** tail plots before readings, in both stages.
- **I2:**
  - Selection on S_build (or its halves) only.
  - S_val: attention early stopping only.
  - S_test: read once, and only in Stage 2.
  - Stage 1 reads no S_val or S_test.
- **I3:** every energy is cloud vs cloud (halves ≥ 37 configs).
- **I4:** SUM is run as an ablation arm with the module's isolation flag. The method default stays MAX until a
  METHOD revision is approved by the human. GC is the MAX reference.
- **I5 / I6:** frozen embeddings and tensors. D038's half energies are reused by sha. Reference counts are verbatim.
- **I7:** no corpus change.

**Out of scope:**
- other γ;
- SUM on the joint (accumulator) statistic;
- whitened / `ADD` evidence (D021 / D023);
- hybrid rules (e.g. a strength floor on JG);
- v1 training;
- open-set;
- S_test′.

**Cost (design-side guess):**
- Stage 1: CPU, < 0.3 node-h (SUM selection is seconds; M4 as D038).
- Stage 2: 1 arm × 8 `k` × 5 seeds = 40 attention runs, plus 8 linear fits, ≈ 0.6 node-h (D037: 1.19 node-h for
  2 arms).
- **Call if > 4 node-h.** State the measured cost in R.
