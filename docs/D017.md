## D — The question

> **Train a simple linear classifier — not the paper's attention network
> — on the exact same frozen traces, splits, and already-selected query
> chains, and ask: does `joint energy`'s advantage over `paper8` (both
> the aggregate mean-top1 gain and its concentration on hard
> near-relative pairs/models) survive, or is it specific to the
> attention network's capacity/inductive bias?**

### Why this is worth the (cheap) cost

`METHOD.md §3–4`'s theoretical framing is about the *information content*
of the selected queries' responses (an MI decomposition over a
point-cloud separability statistic) — a claim that should not depend on
which downstream classifier reads that information out. If a minimal
linear classifier shows the same qualitative story (joint energy >
coverage > paper8 in ordering, and a hard-pair-specific amplification),
that is direct empirical support for "the benefit is in the data," and
strengthens `DECISIONS.md` D5's claim (3) beyond an aggregate-accuracy
argument alone. If it does not survive, that is equally important to know
before any writeup leans on the theoretical framing — and per D009's own
precedent, a "FALSIFIED" branch here is not a failed D, it is the answer.

**Cost is the reason to do this now rather than later.** A linear
classifier is far cheaper to fit than the attention network (no backward
passes through an attention stack, likely sub-second per fit) — this D is
expected to be one of the cheapest in the project, cheaper than D015/D016
even.

### What is and is not known going in

- The attention network's input is already `[E(query); E(response)]`,
  2048-d per trace (`METHOD.md §5.5`) — **no new embeddings are needed**;
  the same frozen per-trace feature vectors this project has used since
  D009 are the linear classifier's input too.
- The attention network takes a *set* of `k` such vectors and
  self-attends across them; D012/R4 confirmed it is **insensitive to
  slot order** (a 40×-smaller-than-seed-noise effect). A linear model
  cannot consume a variable, unordered set directly — **it needs a
  pooling decision**, which does not exist yet and is this D's first
  required design call (S0/Call 1).
- **It is not known whether a linear classifier is stochastic in this
  setting at all.** The attention network's "5 seeds" captures training
  (init + shuffling) stochasticity; a convex linear model fit with a
  deterministic solver (e.g. L-BFGS) may have *no* seed variance to speak
  of. This changes what "resolved" means here and must be checked (S0),
  not assumed either way.
- **Not reopening the hard-pair-definition thread.** D015/D016/this
  session's chat explored several candidate "hard" populations (the 65
  structural pairs; several data-driven sub-clusters within it) — that
  question is explicitly parked. This D uses only two already-settled,
  uncontroversial reference points for its hard-pair check: the full
  65-pair structural set (`hard_subset`, as currently defined in
  `METHOD.md §8`) and the two pairs named since D001 (Falcon3-10B/7B,
  Phi-3-medium-128k/4k). No new cutoff is introduced here.

## What counts as an answer

Report, for `paper8`, `coverage` (γ=0.1), `joint energy` (γ=0.1), at
`k`=1..8 (cheap enough to do the full curve, matching this project's
standing practice since D008):

- **mean top-1, worst-class, `hard_subset`** (the 65-pair set, unchanged
  definition) under the linear classifier — the same three metrics D009
  onward report for the attention network, enabling a direct side-by-side
  table.
- **The two named pairs' own two-logit-restricted accuracy** under the
  linear classifier, compared to their known attention-network values
  (Falcon3-10B/7B: .800/.800/.832; Phi-3-medium-128k/4k: .712/.656/.732
  for paper8/coverage/joint energy at `k`=8).
- **Whether the ordering `joint energy > coverage > paper8`** (on mean
  top-1, and on the two named pairs) **is preserved, reversed, or
  statistically indistinguishable** under the linear classifier — state
  this per `k`, not just at `k`=8, and require a *consistent sign across
  k* before calling an ordering preserved (this project's standing
  convention, e.g. D010/D012).

**Three symmetric, equally informative outcomes — pre-registered before
any run, per standing project discipline:**

| outcome | reading |
|---|---|
| **CLASSIFIER-AGNOSTIC** | Ordering and hard-pair concentration both preserved (consistent sign across `k`, CI excludes zero where the attention-network version was resolved) → strong support for D5 claim (3); the benefit is in the selected data, not the network |
| **CLASSIFIER-DEPENDENT** | Ordering preserved on aggregate mean top-1 but the hard-pair-specific amplification shrinks to statistical indistinguishability (TOST, δ=0.02) or reverses → the aggregate story is robust, the hard-pair story is not; report both halves separately, do not average them into one verdict |
| **FALSIFIED** | Ordering itself reverses or is indistinguishable from noise on mean top-1 → the whole selection-algorithm advantage may be entangled with the attention network's capacity; **not a failed D** — exactly as important as the other two branches, and it would need a design-side/human conversation before any further writeup leaning on classifier-agnosticity |

**Not required:** extending to D012/D013's γ grid, or to more than the
three headline conditions — flag as a cheap follow-up if `k`=8's result
is informative enough to want more. **Not required:** resolving which
"hard" cutoff (the parked question) is correct — use only the two
reference points named above.

## Required steps

**S0 — Design and sanity-check the pooling + determinism, before any
grid.** **Call 1 (state in P1, get it right before training anything):**
how does a linear classifier consume `k` unordered `[E(q);E(r)]`
vectors? Proposal to evaluate: **mean-pool across the `k` slots, then one
multinomial (37-way) logistic regression layer** — preserves the
attention network's confirmed order-insensitivity, simplest defensible
choice. State any alternative considered (e.g. concatenation, which would
reintroduce a slot-order dependency the attention network provably does
not have) and why it was rejected, or why mean-pooling was accepted
without one. **Also determine empirically whether the fit is
deterministic** (e.g., L-BFGS on a convex objective with fixed data
typically is) — fit `paper8` `k`=8 twice, same command, and report whether
the two fits are bit-identical. If deterministic, say what replaces "5
seeds" as this D's source of reported uncertainty (proposal: the same
config-level bootstrap this project already uses for CIs, which does not
depend on training-seed variance and is already the primary uncertainty
source in every prior D's "resolved" calls) — if stochastic, keep 5 seeds
and say why.

**S1 — Fix the regularization/hparams once, not per condition.** Pick
any regularization strength (or lack of one) via the validation split on
one representative condition (`paper8`, `k`=8), then **freeze it and
reuse identically across every condition/`k`** — the same fairness
discipline as the attention network's asserted-identical `hparams` hash
(D009/F4's precedent: an unequal classifier per condition would leak an
incidental advantage into the comparison this D exists to make cleanly).
State the chosen value and the validation-accuracy curve that picked it.

**S2 — Train/fit the linear classifier for `paper8`, `coverage` (γ=0.1),
`joint energy` (γ=0.1), `k`=1..8**, same split, same frozen features,
same fixed hparams (S1). Measure and report wall time before committing
to the full grid, per standing practice (D002/D006/D007/D009/D010/D012's
precedent).

**S3 — Report the four `METHOD.md §8` metrics** (mean top-1, worst-class,
`hard_subset`, and — since selection cost is unaffected by which
classifier reads the result — no new query-efficiency computation needed)
for every condition/`k`, in the same shape as D009/D010's tables, for
direct comparison.

**S4 — The two named pairs' accuracy under the linear classifier**, same
computation D015/D016 already used (`logit_stats`'s two-logit restriction,
here on the linear model's own logits), at `k`=8 (and `k`=1 for the same
contrast D015 reported). Compare directly against the already-known
attention-network values quoted above.

**S5 — State the verdict against the three-way outcome table above**,
per metric, with sign-consistency-across-`k` as the ordering criterion and
TOST (δ=0.02) for any "statistically indistinguishable" call, matching
this project's standing conventions exactly (no new statistical framework
introduced for this D).
