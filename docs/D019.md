## D — The question

> **For `H1-attention` and `H1-linear` (D018's two chains, `k`=8), compute
> each model's true 37-way top-1 recall (`per_model`, the same quantity
> D009/D010 already store for `paper8`/`GreedyCover`/`JointGreedy`), then
> report the mean recall restricted to each of the model sets already
> used earlier this session — do not define a new set.**

### What is and is not known going in

- D018's `metrics_by_k.json` stores `mean_top1`/`worst_class`/
  `worst3_class`/`hard_subset` per chain/readout/`k`, **but no
  `per_model` array** — confirmed by inspection (2026-09-27). The
  restricted-recall analysis needs this and cannot be derived from what
  is already saved.
- D018/R6 discloses that the attention-network checkpoints for both
  chains' final 5-seed evaluations were **saved but not committed**
  (gitignored per D009's convention, left on `$WORK`). **If they still
  exist**, this is a cheap, read-only re-inference — no retraining —
  exactly D016's S0/S1 pattern (load checkpoint, one forward pass on
  `S_test`, extract `per_model`, assert the recovered `mean_top1`
  matches the already-stored value). **If they have been cleaned up**,
  retraining just these two chains at `k`=8, 5 seeds (attention) + 1
  deterministic fit (linear) is itself cheap (on the order of D009's
  original per-run cost, minutes total) — state which branch applies,
  do not silently assume either way.

## What counts as an answer

For each of `H1-attention` and `H1-linear`, at `k`=8: report the mean
`per_model` recall restricted to each of the four sets above, alongside
the already-known values for `paper8`/`GreedyCover`/`JointGreedy` (no
need to recompute those — they are already in `results/D009/runs.json`/
`results/D010/metrics_by_k.json`), and the gap against each chain's own
all-37 `mean_top1` (already stored in D018's `metrics_by_k.json`).

**Not required:** any `k` other than 8. **Not required:** a new
significance test — report point estimates as descriptive, exactly as
the earlier chat analysis did; do not imply resolution these numbers
don't have. **Not required:** deciding which set is "the" hard-model
definition — report all four, unranked.

## Required steps

**S0 — Checkpoint availability check.** For `H1-attention`'s 5 seeds and
`H1-linear`'s deterministic fit, both at `k`=8: confirm the saved
checkpoints from D018/S2 still exist on `$WORK` and load. Report the

checkpoint on `S_test`; for the attention chain, average `per_model`
across the 5 seeds (same convention as D009/D010); for the linear chain,
the single deterministic fit. Assert the recovered `mean_top1` matches
`results/D018/metrics_by_k.json`'s stored value for that chain/`k`=8/
attention-readout (a correctness check, matching D016's S1).

**S2 — Compute the four restricted means** for both chains, reusing the
model sets exactly as specified above (regenerate `worst16-paper8`
procedurally; assert `n`=21).

**S3 — Report the full table**: all five conditions × all four sets,
plus each condition's all-37 `mean_top1` and the gap, in the same shape
as the chat analysis this session (so it can be dropped into `FINDINGS.md`
without reformatting).
