## D — The question

> **Two things, using the SAME underlying data:**
> **(a)** Extend the trained classifier's real two-logit-restricted
> accuracy from the 65 structural near-relative pairs to as much of the
> full 666-pair population as feasible, for `paper8`, `coverage` (γ=0.1),
> `joint energy` (γ=0.1), at `k`=8. Are there pairs *outside* the
> structural set that are as hard, or harder, than the worst structural
> pairs (Phi-3-medium-128k/4k, Falcon3-10B/7B)?
> **(b)** Extend the tensor-level proxy statistic (D008's
> `hard_ceiling`-style `median_query`/`oracle`/`best_build_query`) to the
> same full population, and correlate it against (a)'s real trained
> accuracy — the rigorous version of the 2026-09-22 design-side check that
> was limited to 65 pairs at the time.

### Why this is not a repeat of D008/D011's mistake

D011 showed `results/D008/identifiability_frontier.json`'s T1/T2/T3 tiers
are substantially an estimator artifact: their `best_build_query`
statistic is *one single query*, chosen via build-side data, evaluated on
test — and for a median pair in that tier it generalized so poorly
(0.54, worse than a random pool query at 0.82) that a real trained
classifier using any properly-selected multi-query chain resolved 32/32
of them. **This D does not use that statistic as ground truth for
hardness.** It asks TACC to compute the same thing D009–D015 already
compute and trust for the 65 structural pairs — **a real trained
classifier's argmax-restricted-to-two-classes accuracy, from an actually
trained `k`=8 model** — for the *other* 601 pairs too. That is not a
proxy; it is the same measurement this project has used as ground truth
since D009, just applied to a wider population. Part (b)'s tensor proxy
(`median_query`, an accuracy averaged over the whole 259-query pool, not
a single circularly-chosen query) is retained *only* as something to
correlate against the real number, per the 2026-09-22 check's own
methodology — never as a substitute for it.

### What is and is not known going in

- `results/D009/runs.json` and `results/D010/metrics_by_k.json` each
  record a `best_ckpt` filename per run — a trained model was saved. **It
  is not known whether these checkpoint files still exist on disk** in
  TACC's environment; this repo does not track them (too large, binary).
  This is the first thing to check (S0) and it changes this D's cost by
  an order of magnitude either way.
- If checkpoints exist: extending (a) to all 666 pairs needs **no
  retraining** — one forward pass per already-trained model over the
  already-frozen test set recovers the full 37-way logits per trace, and
  restricting to any pair of columns instead of just the 65 near-relative
  ones is a cheap, purely arithmetic extension of `d009_lib.py:logit_stats`
  (same function, wider `hard_pairs` argument).
- If checkpoints are gone: recovering (a) needs **retraining**, which is
  a materially different cost and a design-side re-scoping decision (see
  Constraints) — not something to do silently under this D's current gate.
- (b)'s tensor-level extension needs no checkpoint at all — it is the
  same computation as `experiments/d008_hard_ceiling.py`, with
  `pair_index(models)` (all 666) in place of `near_relative_pairs(models)`
  (65). Purely reads the already-frozen `S_energy` tensor and
  `build_dq`'s already-frozen distance matrices (I6) — no new embeddings,
  no new generation.

## What counts as an answer

**For (a):** report, for each of `paper8`/`coverage`/`joint energy` at
`k`=8, the full-population distribution of two-logit-restricted accuracy
(not just a mean) — at minimum: the worst 10 pairs overall, whether any
of them are outside the structural 65-set, and how their accuracy compares
to the known worst structural pairs (Phi-3-medium-128k/4k: .656–.732;
Falcon3-10B/7B: .800–.832). State explicitly whether the structural set
already contains the objectively hardest pairs in the universe, or misses
some.

**For (b):** report the Spearman correlation between the tensor proxy and
(a)'s real trained accuracy, across all 666 pairs, with a bootstrap CI —
the 2026-09-22 check's own three caveats (n=65 only; a proxy-accuracy
statistic, not the literal CVaR-tail objective value; no CI on the
correlation) should each be resolved or explicitly re-stated as still
open.

**Not required:** retraining anything if checkpoints are gone (report the
cost/scope question back to design-side instead, per Constraints).
**Not required:** re-deriving `worst_class`/`hard_subset`/`mean_top1` —
those are unchanged; only the pair-restricted view is new. **Not
required:** extending to `k` values other than 8, or to D012/D013's γ
grid — flag as a future cheap follow-up if this D's `k`=8 result is
informative enough to want more.

## Required steps

**S0 — Checkpoint availability check, before anything else.** For each of
the 15 runs behind `paper8`/`coverage`/`joint_energy` at `k`=8 (3
conditions × 5 seeds), check whether `best_ckpt`'s file still exists and
loads. Report the count that do. **If fewer than 5 per condition are
available, stop and report to design-side before proceeding** — this
D's Call 1 (below) needs a design-side decision on how to proceed with a
reduced-seed or retrained set, not a silent substitution.

**S1 — Recover full 37-way logits on the test set from each available
checkpoint.** One forward pass per checkpoint (no training). Assert the
recovered `mean_top1`/`per_model` reproduce the already-stored values for
that run (a correctness check against a known-good number, catching a
mismatched checkpoint/test-set pairing before it propagates).

**S2 — Compute two-logit-restricted accuracy for all `pair_index(models)`
pairs (666, or as many as models permit) from S1's logits**, using
`d009_lib.py:logit_stats`'s existing restriction logic with the wider
pair list — same config-level bootstrap-CI convention as D015 (paired
draws, `n_boot` consistent with prior D's). Report the full distribution,
not just a mean; flag the worst 10 and whether each is inside or outside
the structural 65-set.

**S3 — Extend the tensor-level proxy to the same 666 pairs**, adapting
`experiments/d008_hard_ceiling.py` (`median_query`, `best_build_query`,
`oracle` — retain all three, as before, and continue treating `oracle` as
the least trustworthy per its own docstring) with `pair_index(models)` in
place of `near_relative_pairs(models)`. Frozen tensor and distance
matrices only (I6) — no new embeddings or generation.

**S4 — Correlate S2 against S3**, Spearman with a bootstrap CI, across
all 666 pairs, for each of the three conditions independently (matching
the 2026-09-22 check's structure) — report whether the tail-level
agreement and mid-ranking disagreement pattern found on the 65-pair
sample holds, sharpens, or changes at full scale.

**S5 — Write `## R`:** the worst-10-pairs table (S2), explicitly marking
structural-vs-non-structural membership; the correlation table (S4); and
a direct answer to "does the structural 65-pair set already contain the
objectively hardest pairs, or does real difficulty exist outside it."

## Constraints

**Applicable invariants:** I6 (same frozen `S_energy` tensor, same frozen
test/build splits, same already-trained checkpoints — nothing
regenerated, nothing retrained under this D's current gate).

**Out of scope, explicitly:** retraining any condition/seed to replace a
missing checkpoint — if S0 finds checkpoints missing, **stop and report
it in `## R`**, with the count available and an estimated retraining cost,
and let design-side decide whether a reduced-seed analysis, a resampled
subset of the 601 non-structural pairs, or a full retrain is the right
next step. Do not decide this unilaterally and proceed. Also out of
scope: any change to `k`, γ, or the three conditions already used
throughout D009–D015; editing `METHOD.md`; adopting a new `hard_subset`
definition (that is DECISIONS.md D7, a separate human decision this D's
`## R` will inform, not make).

**Cost:** if checkpoints exist, expect this to be materially cheaper than
any prior training D — inference only, no backward pass, on already-cached
test data. **State the measured cost in `## R`** regardless, per standing
project practice (D002/D006/D007/D009/D010/D012's precedent of measuring
before assuming).
