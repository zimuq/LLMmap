## D — The question

> **Under the linear classifier (both concatenation and mean-pooling,
> D017's frozen hparams), is `JointGreedy`'s point-estimate edge over
> `H1-linear`'s chain (D018/R3: +0.010 to +0.029 at `k`=4..8,
> mean-pool) a statistically resolved difference, or does it disappear
> into noise once both sides get a properly paired bootstrap CI over the
> same test configs?** Extend the same question to `GreedyCover` and to
> `H1-attention`'s chain under the linear readout, so all four
> already-known point estimates (D018/R2, R3) get the same treatment.

### Why this is worth doing, precisely

This is not a new experiment on new data — `GreedyCover`, `JointGreedy`,
`H1-attention` and `H1-linear` are all already-selected, already-frozen
chains (I6). The only thing missing is **per-test-config correctness
counts** for `GreedyCover`/`JointGreedy`'s linear evaluation, which D017
never saved (it kept only the final aggregated accuracy and an
*unpaired* bootstrap CI on that aggregate — confirmed by inspection of
`results/D017/linear_metrics_by_k.json`'s `bootstrap_ci`, which has
`{mean, lo, hi}` per condition but no underlying per-config array). D018
independently computed its own `bootstrap_ci` (`n_boot=2000`) for
`H1-attention`/`H1-linear` under all three readouts, including linear —
so the raw per-config data likely existed *internally* in D018's own
script at compute time, whether or not it was written to disk. **Neither
gap requires new training or new selection — both are refits of already-
fixed chains under already-fixed hparams**, cheap because the classifier
is a deterministic linear fit (D017/D018 established this: seconds per
fit, bit-exact across repeats).

### What is and is not known going in

- The linear classifier is deterministic (D017, reconfirmed D018/D019)
  — there is **no training-seed axis on either side of this comparison**.
  This simplifies the resolution criterion relative to every
  attention-network comparison in this project: a paired bootstrap CI
  excluding zero is sufficient on its own to call a difference resolved
  here — the extra "and |Δ| exceeds the 5-seed range" check (D009/F1
  onward) existed specifically to guard against attention-network
  training stochasticity, which does not exist on either side of this
  specific comparison. State this plainly in `R` rather than importing
  the attention-network rule unnecessarily.
- `GreedyCover`/`JointGreedy`'s linear-readout point estimates are
  already known (D018/R3, reused from D017, I6): `k`=4,6,8 shown; the
  full `k`=1..8 curve is presumably cheap to reproduce as well, but was
  not previously required.
- **Not required:** any new query selection, any new embeddings, any
  change to the four chains being compared. **Not required:** extending
  this to the hard-pair or hard-model views (D015/D016/D019) — this D is
  scoped to the four aggregate `METHOD.md §8` metrics only, under the
  linear readout.

## What counts as an answer

For both `concat` and `mean-pool`, at `k`=1..8: report `GreedyCover`,
`JointGreedy`, `H1-attention`, `H1-linear`'s linear-readout mean top-1
(reproducing D018/R3's known point estimates as a correctness check),
plus a **properly paired** bootstrap CI (shared config-level draws
across all four conditions, same convention as every comparison since
D009) for:

- `JointGreedy − H1-linear` (the comparison D018/R3 flagged as
  point-estimate-only and the primary motivation for this D)
- `JointGreedy − H1-attention`, `GreedyCover − H1-linear`,
  `GreedyCover − H1-attention` (the other three cells of the same 2×2,
  reported for completeness, not as an afterthought)

**Resolved** = paired 95% CI excludes zero (no seed-range condition — see
above). **Not resolved** = CI includes zero, reported as such rather than
implied significant by the point estimate alone. Report all four
`METHOD.md §8` metrics if cheap; `mean_top1` is the primary one this D
exists to settle.

**Not required:** a new "H1 WINS"/"PARITY-OR-BETTER" three-way verdict —
this D answers a narrower, specific question D018 already flagged, not a
restatement of D018's own head-to-head verdict.

**Status: PROPOSED — awaiting review.** Full plan:

**S0(a) is already answered: nothing to reuse.** Neither D017 nor D018 wrote
per-config counts. Both saved only `bootstrap_ci` as `{mean, lo, hi}`, and
D018's `st` lived in memory only. All four chains get refit: 64 deterministic
fits, **≈8–9 min** (D017: 48 such fits in 6.0 min). The fits are bit-deterministic,
so a refit *is* the original fit. Every refit is asserted to reproduce D017 or
D018's stored metrics exactly before its counts are used.

**Call 1 — concat has a small slot-order floor that the D doesn't anticipate.**
At `k`=2, JointGreedy `[193,140]` and H1-linear `[140,193]` are the **same set in
a different order**. At D017's own converged solver (`tol=1e-6`), concat gives
0.844324 vs 0.845405, a **1-trace** gap. Mean-pool gives 0 (it's symmetric in the
slots). D017's order-invariance check was one permutation at `k`=8. In theory the
optimum is order-free, but lbfgs stops at `tol` and a trace can flip. It's
negligible against the motivating 9–27-trace deltas, but it isn't zero, and there
is no seed-range guard to absorb it. **Proposal:** 4 extra reversed-order `k`=8
concat fits (~1 min) to measure the floor. Concat cells at or below it get flagged
as a disclosure, not a new rule. The `k`=2 JointGreedy/H1-linear cell is reported
as order-only, not as a comparison.

**Call 2 — pre-register the primary question.** Up to 256 cells, each judged on
"CI excludes 0" with no seed-range guard. On `mean_top1` alone, ~3 would look
resolved under a global null; across all four metrics, ~13. **Proposal, fixed
before any number exists:** the primary is `JointGreedy − H1-linear`,
`mean_top1`, `k`=4..8, both poolings. It is RESOLVED if the CI excludes 0
**and** the sign is consistent across `k`=4..8 (the D017/D018 ordering
criterion). Everything else is per-cell descriptive, with the total count shown
against the ~5% chance expectation. No Bonferroni: that would be a new framework.

**Excluded as identical inputs (Δ ≡ 0):** `JointGreedy − H1-attention` at
`k`=1, 2; `GreedyCover − H1-attention` at `k`=1.
