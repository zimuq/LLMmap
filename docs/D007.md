## D — The question

> **Using the real, frozen I5 embedding and the full 259-entry query pool
> over all 37 models (D006's corpus), and the statistic(s) decided in A3
> — does a per-query separability tensor `S` of shape `|Q_0| × C(37,2)`
> show a genuine, non-saturated hard tail, the way D004 found on a proxy
> instrument and a stand-in 8-query set?**

**This is not a repeat of D004 — it's the real version of the same
question.** D004 answered "does a hard tail exist at all" using LLmap's
own *trained* stage-2 representation (384-d, optimized to separate these
exact models) and D001's original 8 queries — explicitly flagged there as
a proxy, biased toward *finding* separation, sufficient to answer the
premise question but not a measurement in the project's actual
representation. This D re-asks it on **the representation and query pool
the project actually uses**: I5's raw, untrained 1024-d embedding
(invariant I5) and the full 259-query candidate pool D003/D006 built.

### Why this exists as its own D rather than folding into D006

D006 explicitly stopped at T1.4 (collect the corpus) and deferred T1.5/
T1.6 because both are blocked on **A3** (which statistic) — now decided.
Building the tensor is also a materially different computation from
corpus collection (no GPU, no generation — CPU-only re-analysis of
already-embedded data, closer in shape to D004 than to D006), and
touches invariants (I1, I3, I4, I6) directly enough to warrant its own
review rather than riding along inside D006's already-large scope.

### Hard dependency: D006 must be READY (37/37), not PARTIAL

Per D006's own Call 2 policy (**all-37-or-nothing for anything computing
`Sep(·,·)`**): `CVaR_γ` is a tail statistic over the pair set, so building
this tensor on fewer than 37 models is a *different* experiment, not a
smaller one. **Do not start S1 until D006's manifest reads
`status: READY`.** If picked up while D006 is still `PARTIAL`, stop and
report rather than proceeding on a partial pair set.

## What counts as an answer

| Outcome | Criterion |
|---|---|
| **TAIL CONFIRMED** | Per-pair coverage `max_q S_probe[q][p]` (I4: MAX over queries, never sum/mean) has a CVaR₀.₁/mean ratio meaningfully below 1, **and** the resolution audit (M3 below) shows the distribution is not censored — real spread, not a ceiling artifact. `METHOD.md §2` and invariant I1 stand as written; Phase 2 proceeds. |
| **TAIL STILL ABSENT (genuine falsification)** | Ratio ≈1 under **both** `S_probe` and `S_energy`, **and** the resolution audit shows both have room to show spread (i.e. neither is itself saturating). Per `TODO.md` T1.6's falsification criterion (10th percentile of `max_q S[q][p]` > 0.9), this is a **STOP**: escalate to the human as a `METHOD.md`/I1 revision question — this D reports it, does not resolve it. |
| **STILL INCONCLUSIVE** | The resolution audit shows meaningful censoring in `S_probe` and the pattern doesn't cleanly resolve via `S_energy` either (e.g. `S_energy` shows its own unexplained irregularity). Report the full distribution; do not force a verdict; flag what would need to differ in a follow-up. |

## Required steps

**S1 — Confirm D006 is READY (37/37), not PARTIAL.** Read the corpus
manifest's top-level `status` field. If not `READY`, stop and report —
do not proceed on a partial pair set (see hard dependency above).

**S2 — Build `S_probe`: 5-fold CV AUC of a linear probe, per (query,
pair).** For each of the 259 queries and each of the 666 model pairs:
take model *i*'s I5-embedded responses to that query across all
build-split configs as one point cloud, model *j*'s as the other
(invariant I3: point-cloud vs point-cloud, never single-response or a
collapsed average), fit a 5-fold CV linear probe, record AUC. Shape:
`259 × 666`. Use a fixed regularization `C` (not tuned per cell) —
D004's own reasoning for this (avoiding a p≫n leakage risk) applies
identically here.

**S3 — Build `S_energy`: energy distance, same shape, mandatory (per
A3), not optional.** Same point-cloud pairing as S2, energy distance
instead of probe AUC. Report both raw and scale-free variants, as D004
did.

**S4 — M3-style resolution audit, as a gate, on the FULL tensor.**
Report, for both `S_probe` and `S_energy`: fraction of (query, pair)
cells at/near a ceiling or floor, and — more importantly for T1.6 —
fraction of **pairs** (after I4's MAX-over-queries aggregation) at/near
ceiling. **Do not report a CVaR/mean ratio near 1 as "no tail" if this
audit shows censoring** — this is the exact mistake D001 made and the
exact discipline D004 required going forward.

**S5 — T1.6's mandatory hard-tail check.** Compute `max_q S_probe[q][p]`
per pair (I4: MAX, never sum/mean) and plot the distribution. Per
`TODO.md` T1.6's falsification criterion: **if the 10th percentile is
> 0.9, this is TAIL STILL ABSENT** (pending S4's audit confirming the
statistic itself has room to show spread — see the outcome table). Repeat
using `S_energy`'s per-pair MAX as a cross-check; the two should agree in
direction even if not in exact magnitude (as they did in D004).

**S6 — Carry forward the motivating case for continuity.** Report
`Falcon3-10B ↔ Falcon3-7B`'s percentile rank (the current hardest pair,
per D004, among ≤14B models) under both statistics, alongside any pair
that ranks differently here than it did in D004 (different query pool,
different representation — a change in ranking is expected and worth
noting, not a red flag by itself).

**S7 — Write `## R`:** verdict, the full distributions (not just the
ratio), M3's audit results explicitly for every verdict branch (mirroring
D004's Review requirement — state the representation/instrument caveat
regardless of outcome), and confirmation that the tensor is stored as
`|Q_0| × C(37,2)` with per-cell sample counts (`TODO.md` T1.5's exact
deliverable spec), tagged with a schema version (I7) marking it as the
frozen artifact I6 now refers to.

**S1 is satisfied:** D006's manifest reads `status: READY`, 37/37, 1,197,875 rows,

**Measured cost, as D007 requires rather than inherited from D004.** Benchmarked
at the real cell shape (75 vs 75 point clouds in 1024-d, 5-fold CV): `S_probe`
**22.6 ms/cell**, `S_energy` **5.5 ms/cell** → **1.34 core-hours** for 259 × 666 =
172,494 cells. A few minutes on a 72-core node, **no GPU**. D004's precedent
transfers, but only via parallelism — single-threaded it is 1.3 hours.

**Two findings need resolution before the tensor is built, because I6 freezes it.**

**F1 — D007 does not name the *analysis-time* token budget, and building the
tensor today sets it to 200 by default.** D006 generated at C7's 200-token
ceiling precisely so that generation budget and analysis budget stay separate
knobs (A2 verified 100/100 that truncation is exact). The current embeddings are
of full 200-token responses. But D006/R2's C7 pilot found separability
*significantly best at 100 tokens* — a result now marked **PROVISIONAL** (R10),
because it was computed on normalised embeddings and normalisation was
subsequently shown to discard real signal. **So we do not presently know the right
analysis budget, and the tensor would freeze one silently.** Proposal: re-embed
once at 100-token truncation (~12 min, text is stored) and build `S_probe` at both
budgets over the **full 666 pairs** instead of the pilot's 15, then freeze the
winner. This also discharges R10's provisional flag rather than leaving it hanging
over A3 and query design. The comparison is mine to run; the choice is yours.

**F2 — I4's MAX-over-queries aggregation is upward-biased, and T1.6's
falsification criterion is a threshold on exactly that quantity.** Each cell is
estimated from 75 vs 75 points in 1024 dimensions — `p ≫ n`, and an order of
magnitude fewer points than the pilot's 600. **Taking the MAX over 259 noisy
estimates is a winner's curse: `E[max]` exceeds the true max whenever the
estimates carry variance.** The bias runs in the dangerous direction — it inflates
per-pair coverage, which raises the 10th percentile, which is precisely what
triggers **TAIL STILL ABSENT**, a STOP and a `METHOD.md`/I1 revision escalation.
That would be a falsification caused by estimator noise rather than by the models.
This is D001's censoring failure in a new place — an instrument property
masquerading as a population property — and **S4's audit as written checks
saturation, not selection bias in the aggregation, so it would not catch it.**
Proposal: a split-half winner's-curse correction (select `argmax_q` on half the
build configs, evaluate that query on the other half; the gap *is* the bias),
report corrected and naive side by side, and apply T1.6's criterion to the honest
estimate. ~1.1 extra core-hours. **I am not proposing to change T1.6's threshold —
only that the quantity it is applied to be unbiased.**

**F3** — under unnormalised embeddings (mean ‖v‖ ≈ 19.6) raw energy distance is
not comparable across queries, and I4's MAX runs across queries; the scale-free
variant is the one that may be aggregated, raw is diagnostic. **F4** — per-cell
sample counts are constant at (75, 75); stored anyway, so code doesn't silently
assume constancy a partial corpus would break.

**Added to S6 at no cost:** D006/R11 pre-registered that
`Llama3-ChatQA-1.5-8B`'s canned-refusal mode should make it unusually easy to
separate. Reporting it is a free sanity check on the whole tensor — if that
prediction fails, suspect the instrument.

**S2a (a ~500-cell pilot) can run on approval of itself alone** — it is
diagnostic, changes no frozen artifact, and answers the one question the S6b pilot
cannot: whether `S_probe` saturates at n=75 (it did not at n=600, and 75 is a
different regime; if it does, A3's gate fires and `S_energy` becomes
authoritative). **S2 onward should wait on F1 and F2.**

# **TAIL CONFIRMED** — on `S_energy`, which A3's gate makes authoritative here

`S_probe` saturates so severely that it cannot answer the question, exactly as
A3 anticipated. Under the unbounded statistic the hard tail is unambiguous.

| statistic (tok200) | CVaR₀.₁/mean | pairs at ceiling | distinct values |
|---|---|---|---|
| `S_probe` naive `max_q` | 0.9903 | **98.2%** | 1,081 |
| `S_probe` F2-corrected | 0.9420 | **51.8%** | — |
| **`S_energy` (scale-free)** | **0.3528** | n/a (unbounded) | **16,727** |

Tensor: `259 × 666` = 172,494 cells, 37 models, 75-config point clouds,
I5 1024-d raw embeddings. Schema `cdqd-tensor-v1` (I7). Build 7.3 min,
8.25 core-hours.

### R1 — S4: the audit gate fires, and it is not close

25.6% of *cells* sit at ≥0.99. After I4's MAX over 259 queries that becomes
**98.2% of the 666 pairs** at ceiling under the naive estimator, and still
**51.8%** after F2's correction. A statistic pinned at its ceiling for half to
nearly all of the population measures the ceiling, not the population — D001's
error, which D004 made it mandatory to check for and A3 made a formal gate.

`S_energy` has 16,727 distinct values against `S_probe`'s 1,081 — **15× the
resolution** — over a cell range of 0.007–12.55 with no ceiling to hit.

### R2 — S5/F2: T1.6 fires under *both* estimators. My prediction was wrong.

| | 10th percentile of per-pair coverage | T1.6 fires? |
|---|---|---|
| naive `max_q` | 0.9964 | **yes** |
| F2-corrected | 0.9536 | **yes** |

I predicted in P1 that the naive and corrected estimators would disagree, and
that the correction would prevent a spurious `TAIL STILL ABSENT`. **It does not.
Both fire.** Recording that plainly: the correction was worth doing and its
premise was right — the selection bias is real, **+0.0164 mean, positive on 68.8%
of pairs**, in exactly the predicted direction — but it is an order of magnitude
too small to move a 10th percentile of 0.9964 below 0.9.

**What actually prevents the false verdict is A3's audit gate, not F2.** T1.6's
criterion, applied to `S_probe` by either estimator, would report
`TAIL STILL ABSENT` — and it would be wrong, because the statistic it is
computed on has no resolution left. F2 was the right precaution aimed at the
wrong one of two failure modes.

### R3 — the outcome table has no branch for what happened

D007's three criteria are all phrased on `S_probe`, and none matches:

- **TAIL CONFIRMED** needs `S_probe` uncensored — it is censored (51.8%).
- **TAIL STILL ABSENT** needs ratio ≈1 under **both** — `S_energy` is 0.353.
- **STILL INCONCLUSIVE** needs the pattern *not* to resolve via `S_energy` — it
  resolves cleanly, with 15× the resolution and no irregularity.

**A3's decision does cover it**: *"if the bounded statistic saturates … energy
distance is authoritative for interpretation."* Under the authoritative statistic
the ratio is 0.3528 and demonstrably uncensored, so the verdict is **TAIL
CONFIRMED on `S_energy`**. Flagged rather than resolved by picking the
nearest-looking branch — the table should probably gain this branch explicitly,
since it is the one A3 predicted would be needed.

This replicates D004 at full scale: D004 saw 0.997 censored → **0.616**
uncensored on a proxy instrument and 8 queries; this is 0.99 → **0.353** on the
real representation and 259 queries. The effect is *larger* here, not smaller.

### R4 — S6: three pre-registered checks, all of which land

- **`Falcon3-10B ↔ Falcon3-7B`: 1.5th percentile** under `S_energy` (9.0th under
  the corrected probe). D004's motivating hard pair remains among the very
  hardest across a **different representation and a different query pool** — the
  strongest continuity evidence available.
- **The three hardest pairs are all near-relatives**, unprompted:
  `Phi-3-medium-128k ↔ Phi-3-medium-4k` (0.782 — same model, different context
  length), `Meta-Llama-3-8B ↔ 3.1-8B`, `openchat-3.6 ↔ 3.5`. I1's premise —
  that hardness concentrates in near-relative structure — appears directly in the
  data rather than being assumed.
- **ChatQA's pre-registered prediction holds, and only the unbounded statistic
  can see it.** D006/R11 registered, before this tensor existed, that
  `Llama3-ChatQA-1.5-8B`'s canned-refusal mode should make it unusually *easy*
  to separate. Under `S_energy`: **+0.888, 75.6th percentile** — clearly easier
  than average. Under the saturated probe: **+0.0032**, indistinguishable from
  nothing. A check registered in advance turned out to be *untestable* on the
  bounded statistic, which is independent confirmation that the saturation is
  consequential and not a bookkeeping detail.

### R5 — F1: the 100-token finding does **not** survive. Freeze at 200.

D006/R2's provisional result — separability significantly *best* at 100 tokens —
was measured on 15 pairs with normalised embeddings. Re-measured on **666 pairs,
172,494 cells, raw embeddings, both statistics**:

| | 100 tok | 200 tok | winner |
|---|---|---|---|
| cell probe AUC (mean) | 0.9598 | 0.9581 | 100, by 0.0017 (52.1% of cells — a coin flip) |
| corrected coverage | — | — | 200, on 61.0% of pairs |
| **`S_energy` coverage (authoritative)** | 2.1880 | **2.3586** | **200, on 71.3% of pairs** |

**Under the authoritative statistic 200 tokens is clearly better**, and the probe
comparison is a tie inside its own noise. **R10's provisional flag is discharged:
the finding is refuted, not confirmed.** The reversal is explained by exactly the
two things that made it provisional — normalisation had removed magnitude (which
covaries with length), and 15 pairs could not see what 666 can.

**Consequence: the tensor freezes at the 200-token analysis budget**, and C7's
ceiling is vindicated a second time — first as the recoverable choice, now as the
better one. The verdict is robust to this either way: `S_energy`'s CVaR/mean is
0.3528 at 200 and 0.3682 at 100, both far below 1.

**Worth stating:** had R2's finding been left standing rather than flagged, the
tensor would have been frozen under I6 at the worse budget on 15 pairs' evidence.

### Technical log

**Why F1 is a clean approve.** The provisional flag on D006/R2's "100
tokens separates better" finding is real and self-inflicted by good
practice, not a new problem: TACC found its own normalization bug *after*
that finding shipped, correctly marked the finding provisional rather than
quietly leaving it standing, and now proposes exactly the right fix
(re-measure on the corrected representation, at full scale rather than a
15-pair stand-in, before the choice gets frozen under I6/I7). The
generate-high/analyze-low asymmetry from C7 is precisely what makes this
free to get right now — nothing about the corpus needs to change,
only which stored length gets read for the tensor.

**Why F2 is a clean approve, and why it matters more than its cost.**
The winner's-curse mechanism is correctly diagnosed: 75-vs-75 point
clouds in 1024-d is a noisy per-cell estimate, and `E[max]` over 259 such
estimates exceeds the true max whenever they carry variance — textbook
selection bias, and the bias direction here is the dangerous one (it
inflates the exact quantity T1.6's STOP criterion thresholds). TACC is
explicit that it isn't proposing to relax the threshold, only to correct
what feeds it — the same discipline this project has required of every
other resolution-audit since D004, now applied one step earlier in the
pipeline (the aggregation itself, not just whether the aggregated
statistic saturates). **S4's audit as originally written would not have
caught this** — it checks for censoring, not for selection bias in how
`MAX` is taken — so F2 is a genuine gap in D007's own design, correctly
caught before it could produce a false STOP.

**Cost discipline, consistent with the project's established standard.**
D007 explicitly required a *measured* cost rather than an inherited
estimate (D004's "few minutes" transfers only via parallelism — 1.3 hours
single-threaded), and P1 delivered exactly that (22.6 ms/cell probe,
5.5 ms/cell energy, 1.34 core-hours for the full tensor) before adding
~12 minutes (F1) and ~1.1 core-hours (F2) on top. Both extras are small
relative to the base cost and trivial relative to the SU balance —
correcting the measurement is cheap; a wrong falsification would not
have been.

**On D006's own late finding (R10, the normalization bug):** worth
noting here since it's the direct cause of F1. Catching this by comparing
against the paper's actual embedding code (§6.1, `embedding_model.py`)
